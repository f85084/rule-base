# 02 聊天室與客服

## 一般人員操作

**這頁做什麼**：讓已被分派對話的客服在聊天室找到正確客戶、閱讀歷史訊息並回覆。入口是 `/chat/:uuid`；由其他系統帶入客戶時可能先經 `/RedirectToChatroom/:customerId`。

**開始前**：確認已登入、客戶在自己的處理範圍，並準備要傳送的文字或已核准素材。不要先用猜測的客戶 ID 修改網址。

**照著做**：

1. 在左側客戶清單選取客戶，核對客戶名稱／客代。預期結果：中間對話與右側客戶資訊都對應同一客戶。
2. 閱讀歷史訊息與目前待處理內容；需要時從工具列選文字、貼圖、圖片、商品或模板。預期結果：內容出現在送出前的編排區。
3. 送出前再次核對客戶、文字、連結與素材，再按送出。預期結果：訊息出現在正確對話，且沒有失敗提示。

**完成確認**：正確聊天室已顯示訊息；若需要確認外部送達，依當期系統結果或管理者報表查驗，不以畫面文字保證送達。

**常見問題**：清單、歷史訊息或客戶卡只有一區空白時先重新開啟該對話；整頁無法操作時記錄客戶、時間與非敏感提示，請管理者核對指派、權限或連線。

## 敘述狀態與查核界線

- **current（來源整理）**：一般客服從 `/chat/:uuid` 進入聊天室；外部導入客戶可由 `/RedirectToChatroom/:customerId` 導向對話。
- **historical（歷史）**：需求與舊流程中列出的訊息工具、客服權限或圖庫行為，若目前畫面不同，不能當成現行保證。
- **inference（推論）**：回覆前核對客戶、訊息內容與素材，且送出後在對話內容看得到，是一般客服可採用的最小確認順序。
- **runtime unknown（執行期未確認）**：即時連線、訊息送達、FaceAI／圖庫同步、客戶權限與目前工具列內容，需以當期 UI 與系統回應為準。

## 適用人員與入口

適用於被分派客服對話的一般專員。入口是 `/chat/:uuid`；若由其他業務系統帶入客戶，依授權使用 `/RedirectToChatroom/:customerId`。指派與改派請看 [03-派線與離線訊息](03-派線與離線訊息.md)。

## 正常流程

1. 在左側客戶清單選擇全部、未讀或搜尋結果，確認客戶名稱／客代與目前對話。
2. 查看歷史訊息與客戶資訊，先確認沒有選錯客戶或對話。
3. 從工具列選擇文字、貼圖、圖庫圖片、商品或已核准模板；送出前檢查內容、連結與收件對象。
4. 送出後確認訊息出現在對話內容，並留意畫面是否顯示失敗或權限提示。
5. 需要備註或標籤時，只使用目前帳號被授權的欄位；完整客戶資料維護交給管理者或依 [04-客戶查詢](04-客戶查詢.md) 處理。

## 完成判斷

正確客戶的聊天室可操作，訊息已在對話內容顯示且沒有錯誤提示。畫面顯示文字不等於外部平台或客戶端已送達；若需要送達證據，依管理者提供的當期報表或系統結果確認。

## 權限與前置

需要已登入、聊天室權限與該客戶的處理範圍。導轉頁若檢查到沒有對話權限，請走指派或管理者協助，不要改網址繞過。

## 影響與限制

送出訊息、封鎖客戶、修改客戶資料或使用共用素材都可能影響後續服務。來源中的刪除訊息屬管理者能力，不要把刪除當成一般撤回；不要為了測試刪除或重送共用內容。

## 第一個排錯

先核對客戶、指派狀態、素材／模板是否可用，再重新載入單一對話。若仍異常，記錄頁面、時間、非敏感提示與操作結果，交由管理者判斷權限、連線或資料同步。

## 頁面別子流程與 route-specific 排錯

### `/chat/:uuid`：聊天室

1. **頁面／欄位／分頁判讀**：先核對左側客戶清單的選取對象，再分開看中間歷史訊息、右側客戶資訊與工具列素材；單一區塊空白不要直接判定整頁故障。
2. **資料來源／合併邊界**：對話歷史、客戶卡與可用素材是不同資料區塊；來源未定義單一區塊失敗時一定回傳部分資料，因此要記錄哪一區塊缺失，不自行補合併規則。
3. **寫入／對外副作用**：送出文字、圖片、商品或模板會影響客戶對話；備註、標籤、封鎖等動作可能修改客戶資料或後續聯繫狀態，送出前核對客戶與內容。
4. **空資料／部分失敗判讀**：客戶清單空白、歷史訊息空白、客戶資訊空白與素材工具列空白分開排查；訊息出現在畫面不等於外部平台已送達。
5. **第一個排錯**：記錄 `/chat/:uuid` 的客戶識別、分區、時間與非敏感提示，先重新開啟單一對話，再請管理者核對指派、權限或連線。

### `/RedirectToChatroom/:customerId`：客戶導轉

1. **頁面／欄位判讀**：路徑中的 `customerId` 是導轉目標，不是一般人員可任意替換的查詢欄位；導轉成功後應回到正確客戶聊天室。
2. **資料來源／合併邊界**：導轉頁負責把外部入口與客戶／對話權限銜接，聊天室內容仍由 `/chat/:uuid` 顯示；導轉成功不代表客戶資料所有分頁都載入完成。
3. **寫入／對外副作用**：導轉本身不應被當成已回覆；真正送出訊息、修改備註或封鎖等副作用發生在聊天室操作。
4. **空資料／部分失敗判讀**：導轉到首頁、顯示無權限、客戶不存在或聊天室只有部分資料是不同結果；不要以導轉頁空白推論客戶已刪除。
5. **第一個排錯**：先確認 `customerId` 來源、登入帳號與目前環境，再回到正常聊天室入口；不要分享或修改含個資的完整路徑。
