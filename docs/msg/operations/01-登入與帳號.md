# 01 登入與帳號

## 一般人員操作

**這頁做什麼**：讓一般人員從公司提供的登入入口進入 MSG，確認自己能看到需要的功能。日常使用 `/login`；MI 驗證後的回跳頁依當期流程進入 `/LoginWithMoneyIn`。

**開始前**：準備公司核發的帳號與正確環境；不要使用別人的密碼、Token 或完整登入網址。`/User`、`/Role`、`/PendingUser` 只在管理者交辦且帳號有權限時處理。

**照著做**：

1. 開啟 `/login`，先確認頁面與環境正確。預期結果：看到目前環境提供的登入方式與欄位。
2. 依畫面完成 MSG 或 MI 驗證，不要自行修改回跳網址。預期結果：回到 MSG 後台或看到明確錯誤提示。
3. 進入後查看選單，開啟一個工作頁確認可操作。預期結果：只看到並能使用帳號被授權的功能。

**完成確認**：成功進入 MSG 後台、工作頁可開啟、沒有把需求狀態當成登入成功證明。若只少一個功能，先依權限差異處理，不要重複登入繞過限制。

**常見問題**：登入頁無法驗證時先確認入口、環境與帳號；能登入但沒有功能時請管理者核對帳號啟用、待確認狀態與角色。回報只提供頁面、時間與非敏感提示。

## 敘述狀態與查核界線

- **current（來源整理）**：MSG 登入入口是 `/login`；MI 登入完成後回到 `/LoginWithMoneyIn`，實際可用方式以目前登入頁為準。
- **historical（歷史）**：L2 文件與需求頁記錄的登入欄位、帳號狀態或 MI 回跳細節，不能視為每個環境都已部署。
- **inference（推論）**：能進入 MSG 首頁且只看到被授權選單，可作為一般人員的工作就緒判斷；這不是安全驗證或部署證明。
- **runtime unknown（執行期未確認）**：帳號是否啟用、角色同步、單一登入狀態、session 期限與目前環境的登入按鈕，需由當期畫面與管理者確認。

## 適用人員與入口

一般使用人員從 `/login` 開始。`/User`、`/Role`、`/PendingUser` 是管理者處理帳號、角色或待確認資料的入口；一般人員不要因為看不到頁面而自行切換帳號或角色。

## 正常流程

1. 開啟公司提供的 MSG 登入入口，確認網址與環境正確。
2. 依登入頁顯示的方式完成 MSG 帳號或 MI 帳號驗證。
3. 回到 MSG 後台後，先確認自己的名稱／角色資訊與需要使用的功能是否出現在選單。
4. 開啟一個被授權的工作頁，確認沒有錯誤提示，再開始處理客戶或訊息。

## 完成判斷

畫面已成功進入 MSG 後台，且可看到並開啟自己被授權的工作頁；不能以「收到登入按鈕回應」或需求單狀態判定完成。

## 權限與前置

需要公司核發的有效帳號、相應角色與正確環境。帳號停用、待確認、角色不足或環境不一致時，請交由管理者處理；不要索取他人密碼或 Token。

## 影響與限制

登入會建立本次工作階段。MI 回跳與本機專員資料清理是來源描述的流程邊界，不代表目前每個環境都採相同實作；不要複製完整登入網址、session 或權杖。

## 第一個排錯

先確認登入入口、環境與帳號是否正確，再請管理者檢查帳號啟用、待確認清單與角色。回報時只提供頁面、時間與非敏感錯誤訊息。

## 頁面別子流程與 route-specific 排錯

### `/login`：登入頁

1. **頁面／欄位判讀**：先看目前提供的登入方式、帳號欄位與錯誤提示；不要把瀏覽器網址列的 token、session 或完整 callback 內容當成可填欄位。
2. **資料來源／合併邊界**：頁面表單、帳號驗證與角色可見功能是不同邊界；L2 只描述登入頁，不代表登入頁會替代 `/User`、`/Role` 的管理資料。不要以選單空白推論帳號不存在。
3. **寫入／對外副作用**：送出登入會建立或更新本次工作階段；不會因為登入頁顯示成功就證明其他外部服務已同步。
4. **空資料／部分失敗判讀**：能登入但缺少單一選單，先按角色／權限差異判讀；登入頁載入但驗證失敗，與後台可見頁面不足是兩種問題。
5. **第一個排錯**：確認環境與入口後，用同一帳號重新開啟登入頁；仍失敗時交由管理者核對帳號狀態與角色，不要重複猜測路徑。

### `/LoginWithMoneyIn`：MI 登入回跳

1. **頁面／欄位判讀**：這是 MI 驗證後的回跳入口，不是一般人員手動填寫帳密的第二個登入頁；以畫面導向結果與非敏感提示判讀。
2. **資料來源／合併邊界**：來源描述 MI 回跳與 MSG 工作階段的銜接；本文件不推定 callback、瀏覽器資料或專員資料的清理時序，也不把回跳網址當成可分享資料。
3. **寫入／對外副作用**：成功回跳可能建立 MSG 工作階段或清理來源描述的舊本機狀態；不要手動重放回跳網址。
4. **空資料／部分失敗判讀**：回跳後進入首頁但只有部分選單，先分開判斷登入成功與角色未同步；停在回跳頁或出現錯誤，則先判斷驗證／環境問題。
5. **第一個排錯**：回到公司提供的登入入口重新開始，記錄頁面與時間；不要貼出 callback 內容、token 或完整 URL。

### `/User`：使用者管理

1. **頁面／欄位判讀**：管理者先以使用者清單、帳號狀態與可見角色欄位核對對象；一般人員不因看不到清單而自行要求提高權限。
2. **資料來源／合併邊界**：使用者資料與角色資料由不同管理頁維護；`/User` 顯示的帳號狀態不等於 `/Role` 的完整授權矩陣。
3. **寫入／對外副作用**：新增、停用或修改使用者可能影響後續登入；由管理者依核准流程操作並回列表確認。
4. **空資料／部分失敗判讀**：單一使用者查不到可能是條件、權限或同步差異；清單可開但角色欄位空白，不直接判定帳號不存在。
5. **第一個排錯**：先核對帳號識別與目前環境，再請管理者重查清單；不要貼出完整個資或帳號憑證。

### `/Role`：角色管理

1. **頁面／欄位判讀**：以角色名稱與頁面／功能清單判讀授權範圍；需求列出的功能不是目前帳號的自動授權。
2. **資料來源／合併邊界**：角色定義與使用者帳號是兩個維護邊界；不要由某個選單出現推論所有 API 或資料範圍都可用。
3. **寫入／對外副作用**：修改角色會影響被指派使用者後續可見頁面與操作；儲存後需由管理者依核准結果確認。
4. **空資料／部分失敗判讀**：角色清單空白、單一功能缺失與登入失敗分開處理；可能是查詢條件、權限或同步問題。
5. **第一個排錯**：先核對角色與生效環境，再請管理者確認該帳號的角色指派；不要自行建立相似角色繞過限制。

### `/PendingUser`：待確認使用者

1. **頁面／欄位判讀**：看待確認清單、帳號識別與目前狀態；來源未描述的核准按鈕不要自行推定。
2. **資料來源／合併邊界**：待確認清單是帳號同步／管理流程的一個視角，不等於 `/User` 的完整使用者清單，也不等於已啟用帳號。
3. **寫入／對外副作用**：依目前授權執行來源明確提供的撤銷或處理動作，可能影響後續登入；完成後回清單確認狀態。
4. **空資料／部分失敗判讀**：清單空白可能表示沒有待處理資料、條件未命中或權限不足；單一帳號狀態未更新時不要重複送出。
5. **第一個排錯**：先重新查詢清單並確認帳號識別、時間與畫面提示，再交由管理者判斷同步或權限問題。
