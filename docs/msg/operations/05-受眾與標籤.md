# 05 受眾與標籤

## 一般人員操作

**這頁做什麼**：在 `/Audience` 建立或維護受眾，在 `/Tag` 使用已核准標籤；需要先檢查檔案時回到 `/CustomerCheck`。

**開始前**：確認受眾用途、名稱、收件範圍與公司核准的 CSV／範本；建立、刪除、批次貼標與群發通常需要管理／行銷權限。

**照著做**：

1. 先用 `/CustomerCheck` 檢查名單，閱讀通過／排除原因。預期結果：知道可送入受眾的範圍。
2. 在 `/Audience` 建立新受眾或向既有受眾附加名單，送出前核對名稱與人數。預期結果：列表出現正確受眾狀態。
3. 在 `/Tag` 選擇已核准標籤進行查詢或批次動作。預期結果：列表或客戶資料反映可查的標籤結果。

**完成確認**：受眾／標籤回列表可查，名稱、用途與範圍正確；不把列表人數當成外部群發送達人數。

**常見問題**：受眾空白先確認檔案檢核、權限與條件；部分名單被排除時保留筆數與原因，不要重送正式名單。

## 敘述狀態與查核界線

- **current（來源整理）**：`/Audience` 用於建立或維護行銷受眾，`/Tag` 用於標籤管理；`/CustomerCheck` 的批次檢查見 [04-客戶查詢](04-客戶查詢.md)。
- **historical（歷史）**：需求頁的受眾欄位、匯入格式、標籤批次動作或外部同步描述，僅反映需求／來源版本，不能當成目前一定存在的按鈕。
- **inference（推論）**：先確認受眾用途與檔案，再建立或附加名單，最後回列表確認名稱與範圍，是一般人員可採用的安全順序。
- **runtime unknown（執行期未確認）**：受眾人數、去重、封鎖排除、標籤同步、外部平台可用性與目前角色權限，需依當期 UI、回應與管理者確認。

## 適用人員與入口

入口為 `/Audience`、`/Tag`；需要先檢查名單時會交叉使用 `/CustomerCheck`。一般客服以使用既有、已核准標籤為主；建立、刪除、批次貼標與受眾發送通常由管理者、行銷或指定資料人員執行。

## 正常流程

1. 先確認工作目的、受眾名稱、資料範圍與收件用途；不以個人本機名單直接上傳。
2. 在 `/Audience` 使用頁面範本或公司核准的 CSV，建立新受眾或向既有受眾附加名單。
3. 送出前檢查檔案欄位、重複資料、封鎖／排除條件與受眾名稱，再執行畫面提供的儲存或匯入動作。
4. 回到受眾列表確認名稱、狀態與可見人數；若要用標籤篩選或貼標，在 `/Tag` 使用已核准的標籤名稱。
5. 需要修改或刪除共用標籤／受眾時，先取得負責人覆核並記錄變更目的。

## 完成判斷

受眾或標籤變更在列表中出現，檢核結果可讀，且名稱與用途正確。列表出現不等於外部平台已同步或群發已送達，需另依 [06-訊息素材與群發](06-訊息素材與群發.md) 查驗。

## 權限與前置

需要合規的客戶資料、頁面範本／檔案格式與相應管理權限。看不到新增、刪除或批次功能時，請找管理者，不要用其他入口繞過權限。

## 影響與限制

建立、附加、批次貼標、刪除受眾或修改標籤會影響後續客服、分眾與群發；刪除或錯誤貼標可能難以從使用者端復原。不要在文件中保存完整客戶名單。

## 第一個排錯

先核對受眾名稱、檔案格式、筆數、重複／封鎖檢核與目前帳號，再回列表重新查詢。若結果為空，不要直接判定服務故障；先區分條件未命中、權限範圍與同步未完成。

## 頁面別子流程與 route-specific 排錯

### `/Audience`：受眾管理

1. **頁面／欄位判讀**：先核對受眾名稱、用途、目前狀態與可見人數，再分開看建立、附加名單或列表動作；不要把人數直接當成外部送達人數。
2. **資料來源／合併邊界**：受眾列表由受控名單與頁面規則組成；上傳檔案的通過／排除結果、既有受眾與外部群發收件結果是不同邊界，不自行補去重或同步時序。
3. **寫入／對外副作用**：建立、附加、刪除受眾或送出名單可能影響後續群發；送出前確認名稱、檔案與排除條件，完成後回列表確認。
4. **空資料／部分失敗判讀**：受眾空白、部分列被排除、列表有但群發不可選與外部未同步分開記錄；部分成功不代表全部名單可用。
5. **第一個排錯**：先以受眾名稱與最小範圍重查，核對檔案檢核結果與權限，再交由管理者判斷同步或資料問題。

### `/Tag`：標籤管理

1. **頁面／欄位判讀**：查看標籤名稱、狀態、適用範圍與目前可用的批次動作；一般人員優先使用已核准標籤，不建立相似名稱。
2. **資料來源／合併邊界**：標籤定義、客戶標籤關聯與受眾條件是不同資料；畫面顯示標籤不代表所有客戶或外部受眾已同步。
3. **寫入／對外副作用**：新增、修改、刪除或批次貼標會影響查詢、分眾與後續群發；共用標籤變更須先取得負責人覆核。
4. **空資料／部分失敗判讀**：標籤列表空白、單一客戶未顯示、批次部分成功與受眾人數未變分開排查；不要重複貼標造成難以回復的結果。
5. **第一個排錯**：先核對標籤名稱、客戶範圍與批次結果，回列表或客戶頁重查，再請管理者確認權限與同步。

### `/CustomerCheck`：跨入口名單前置

1. **頁面／欄位判讀**：先在 [04-客戶查詢](04-客戶查詢.md) 的 `/CustomerCheck` 查看範本、通過／未通過筆數與原因，再回 `/Audience` 建立或附加受眾。
2. **資料來源／合併邊界**：檢核結果只表示上傳檔案通過頁面規則，不代表客戶資料、標籤、受眾或外部收件結果已寫入；四者分開確認。
3. **寫入／對外副作用**：上傳可能產生檢核報表；將檔案送入 `/Audience` 才進入受眾寫入邊界，不要把檢核完成當成受眾完成。
4. **空資料／部分失敗判讀**：檢核無結果、部分列通過或受眾只收到部分清單，都要保留筆數與原因，不直接重送正式名單。
5. **第一個排錯**：先核對範本、檔案欄位與檢核原因，必要時回 [04-客戶查詢](04-客戶查詢.md) 依 route-specific 順序處理。
