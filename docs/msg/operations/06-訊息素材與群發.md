# 06 訊息素材與群發

## 一般人員操作

**這頁做什麼**：在圖庫、商品、模板與圖文選單頁準備已核准內容，並在 `/multicast` 使用 `/Audience` 收件範圍進行群發。一般客服優先使用既有素材，不要自行刪改共用內容。

**開始前**：確認素材檔案、商品連結、模板版本、受眾名稱與群發覆核人；發布、停用、刪除與群發都可能影響外部使用者。

**照著做**：

1. 在 `/Gallery`／`/GalleryManage` 確認圖片與分類，在 `/Product` 確認商品與連結。預期結果：素材在列表顯示可用狀態。
2. 在 `/Combo` 檢查模板文字與引用素材；需要調整 `/Richmenu` 時先確認主檔，再進子頁設定熱區。預期結果：預覽與狀態符合覆核內容。
3. 在 `/Audience` 確認受眾名稱／人數，再到 `/multicast` 選收件對象、編排內容與預覽。預期結果：送出前能看見正確受眾與內容。
4. 完成最後覆核後才送出；送出後依畫面結果或後續報表查驗。預期結果：有可追溯的群發結果，不把按鈕回應當成每位收件者已收到。

**完成確認**：素材／模板狀態正確，群發對象與內容可回查；LINE 使用者端呈現與實際送達仍需 runtime 證據。

**常見問題**：聊天室找不到素材先查分類、啟用狀態與權限；群發不能送出先查受眾、功能開關與畫面錯誤，不要重複送出。

## 敘述狀態與查核界線

- **current（來源整理）**：`/Gallery`、`/GalleryManage`、`/Product`、`/Combo`、`/Richmenu`／`RichmenuSlave` 用於準備共用素材與內容；`/multicast` 用於群發流程，並以 `/Audience` 提供收件名單。
- **historical（歷史）**：需求頁中的素材欄位、快取刷新、模板狀態與群發功能開關，屬需求／來源描述，不保證目前每個環境一致。
- **inference（推論）**：先準備並核對素材，再以受眾與內容預覽做最後覆核，適合降低錯誤群發風險；不代表系統提供撤回。
- **runtime unknown（執行期未確認）**：素材同步、LINE 使用者端呈現、外部送達率、群發可用性、模板版本與目前權限，必須以當期畫面與後續結果確認。

## 適用人員與入口

一般客服主要在聊天室使用已核准素材；圖庫、商品、模板、圖文選單與群發多由行銷或管理者操作。入口為 `/Gallery`、`/GalleryManage`、`/Product`、`/Combo`、`/Richmenu`、`/RichmenuSlave/:masterId/:bindingType`、`/Audience`、`/multicast`。

## 正常流程

1. 在圖庫與圖庫頁籤整理核准的圖片／影片分類；在商品維護確認商品資訊、宣傳圖與連結。
2. 在模板訊息選擇結構，填入內容與素材，先檢查文字、圖片、影片、商品連結與狀態。
3. 若調整圖文選單，確認底圖、版面、熱區與目標內容，再依授權儲存、發布或停用。
4. 群發前先在 `/Audience` 確認受眾名稱與範圍，再在 `/multicast` 編排內容並檢查收件對象、預覽與送出時機。
5. 送出後依畫面結果、可用報表或管理者提供的系統結果確認；不要以按下送出直接當成所有客戶已收到。

## 完成判斷

素材／模板在列表顯示正確狀態，聊天室可選取已核准內容；群發流程有明確成功或失敗結果且受眾與內容可追溯。LINE 使用者端是否呈現屬 runtime unknown，不能由後台儲存推定。

## 權限與前置

需要受控素材、正確商品連結、核准模板、目標受眾與群發權限。群發會影響多人，應依公司流程覆核；一般人員沒有授權時只查詢或使用既有內容。

## 影響與限制

刪除共用素材、商品或模板可能影響既有對話；發布／停用圖文選單與群發會改變對外行為，通常不能假設可撤回。來源提到的快取刷新不等於所有環境即時同步。

## 第一個排錯

若聊天室找不到素材，先核對分類、啟用狀態、模板／商品是否存在與帳號權限，再重新開啟頁面。若群發不能送出，先查受眾、素材、功能開關與畫面錯誤，不要重複送出或擴大受眾。

## 頁面別子流程與 route-specific 排錯

### `/Gallery`：圖庫

1. **頁面／欄位判讀**：分開確認圖片／影片清單、分類、啟用狀態與預覽；聊天室工具列可用不等於所有圖庫項目都可用。
2. **資料來源／合併邊界**：圖庫項目與圖庫頁籤分類是不同管理邊界；來源未定義所有分類、快取與聊天室載入的即時同步時間。
3. **寫入／對外副作用**：新增、修改或刪除共用素材會影響後續模板與聊天室使用；送出前核對檔案、分類與用途。
4. **空資料／部分失敗判讀**：整個圖庫空白、單一分類空白、預覽失敗與聊天室找不到素材分開處理；部分項目可見不代表查詢完整。
5. **第一個排錯**：先選正確分類並重新載入 `/Gallery`，確認素材狀態與帳號權限，再請管理者判斷同步。

### `/GalleryManage`：圖庫頁籤管理

1. **頁面／欄位判讀**：看頁籤名稱、排序、啟用／停用狀態與所屬素材，不只看列表是否有資料。
2. **資料來源／合併邊界**：頁籤設定影響圖庫分類呈現，但不等於每個素材內容或聊天室快取都已更新。
3. **寫入／對外副作用**：新增、修改、排序或刪除頁籤會改變共用素材的選擇入口；完成後回圖庫與聊天室核對。
4. **空資料／部分失敗判讀**：頁籤列表空白、頁籤有但素材空白、排序未反映與聊天室仍看不到分開記錄。
5. **第一個排錯**：先核對頁籤狀態與所屬素材，再回 `/Gallery` 重新查詢；不要為測試刪除共用頁籤。

### `/Product`：商品素材

1. **頁面／欄位判讀**：確認商品名稱、商品／銷售連結、宣傳圖與啟用狀態；空連結與預覽錯誤要分開記錄。
2. **資料來源／合併邊界**：商品資料、商品圖片與聊天室選取工具是不同區塊；商品列表存在不等於外部銷售頁或 LINE 端可用。
3. **寫入／對外副作用**：新增、修改、停用或刪除商品會影響模板與對客內容；送出前核對連結與版本。
4. **空資料／部分失敗判讀**：商品列表空白、單一商品缺圖、連結不可用與聊天室搜尋不到分開排查；不要把一個商品失敗當成全圖庫故障。
5. **第一個排錯**：先以商品名稱與狀態重查，確認圖片與連結，再請管理者核對權限或同步。

### `/Combo`：模板訊息

1. **頁面／欄位判讀**：分開確認模板結構、文字、圖片／影片、商品內容與啟用狀態；不要只看模板名稱。
2. **資料來源／合併邊界**：模板引用的素材、商品與聊天室工具列是不同來源；模板儲存不代表每個引用項目仍可用。
3. **寫入／對外副作用**：修改或啟用共用模板會改變後續客服與群發可選內容；先以預覽或受控對話核對。
4. **空資料／部分失敗判讀**：模板列表空白、模板存在但引用素材缺失、預覽失敗與送出失敗分開處理。
5. **第一個排錯**：先核對模板狀態與每個引用項目，再回 `/Gallery`／`/Product` 查驗，不重複啟用同一模板。

### `/Richmenu`：圖文選單主頁

1. **頁面／欄位判讀**：查看圖文選單清單、名稱、尺寸／底圖、狀態與可進入的子頁；主頁狀態不等於每個熱區已正確設定。
2. **資料來源／合併邊界**：主頁保存選單主檔，版面與熱區由 `RichmenuSlave` 子頁維護；後台狀態與 LINE 使用者端呈現分開確認。
3. **寫入／對外副作用**：發布、停用、修改或刪除圖文選單可能改變對外入口；送出前核對目標環境與覆核人。
4. **空資料／部分失敗判讀**：主清單空白、主檔有但子頁缺資料、發布後使用者端未變更分開記錄；不能只看後台成功訊息。
5. **第一個排錯**：先確認主檔狀態與是否能進入正確 `RichmenuSlave`，再記錄發布時間與環境請管理者查核。

### `/RichmenuSlave/:masterId/:bindingType`：圖文選單子頁

1. **頁面／欄位判讀**：以 `masterId` 與 `bindingType` 確認主選單及綁定視角，再核對底圖、版面、熱區、文字／連結或 action 欄位。
2. **資料來源／合併邊界**：子頁版面／熱區依附主頁選單；子頁保存成功不代表主頁已發布，也不代表外部使用者端已同步。
3. **寫入／對外副作用**：修改熱區、連結或綁定內容可能改變使用者點擊後的外部行為；先核對每個區塊再發布。
4. **空資料／部分失敗判讀**：主檔不存在、子頁載入空白、單一熱區缺失與發布後外部未更新分開排查。
5. **第一個排錯**：先確認 `masterId`／`bindingType` 與主頁狀態，再重新開啟子頁；不要用猜測 ID 修改其他選單。

### `/Audience`：群發前置受眾

1. **頁面／欄位判讀**：先確認受眾名稱、用途、狀態與可見人數，再回 `/multicast` 選擇收件對象；這不是群發送達報表。
2. **資料來源／合併邊界**：受眾清單與素材／模板內容在群發頁才合併；受眾檢核結果、群發請求與外部送達是不同階段。
3. **寫入／對外副作用**：建立／附加受眾會影響後續收件範圍；未經覆核不要在群發頁直接使用新建受眾。
4. **空資料／部分失敗判讀**：受眾列表空白、受眾存在但 `/multicast` 不可選、部分名單排除與外部送達未知分開記錄。
5. **第一個排錯**：先回 [05-受眾與標籤](05-受眾與標籤.md) 依 `/Audience` 與名單檢核流程確認，再回群發頁重查。

### `/multicast`：群發

1. **頁面／欄位判讀**：分開確認受眾／收件對象、文字／貼圖、圖片／商品／模板內容、預覽與送出狀態。
2. **資料來源／合併邊界**：群發頁把 `/Audience` 收件範圍與圖庫／商品／模板內容組合成一次請求；預覽或送出成功不等於每位收件者已收到。
3. **寫入／對外副作用**：送出會對多位客戶產生外部訊息副作用，通常不可假設可撤回；送出前必須覆核受眾、人數與內容。
4. **空資料／部分失敗判讀**：受眾為空、素材無法選、群發功能停用、請求失敗與部分送達分開判讀；不可直接重送造成重複訊息。
5. **第一個排錯**：先記錄受眾名稱／人數、內容預覽、時間與畫面提示，確認功能開關與權限後交由管理者查核。
