# 03 派線與離線訊息

## 一般人員操作

**這頁做什麼**：提供主管／管理者處理客戶指派、非工作時間留言與待確認帳號的入口；一般客服主要在聊天室接收已派來的對話。

**開始前**：準備正確的客戶、專員、月份／日期與受控匯入檔；確認自己有管理頁權限。看不到按鈕時不要用別人帳號代操作。

**照著做**：

1. 在 `/Assign` 選客戶與專員，按畫面提供的確認動作。預期結果：指派關係在列表反映。
2. 回聊天室查驗目標專員是否看到可處理對話。預期結果：不會把改派成功只判斷成按鈕關閉。
3. 在 `/LeaveMessages` 選月份／日期，設定或修改離線規則；匯入只使用目前頁面要求的檔案格式。預期結果：回日曆可看到指定日期規則。
4. 在 `/PendingUser` 查看帳號狀態，只執行當期畫面與權限明確提供的動作。預期結果：清單狀態更新，且不自行補造核准流程。

**完成確認**：指派、離線規則或帳號狀態回到原清單可查；若沒有更新，先保留客戶／專員／日期與錯誤提示，不要重複送出。

**常見問題**：查不到資料先清除條件並以單一客戶或日期重查；仍失敗時請管理者核對權限、匯入格式與同步狀態。

## 敘述狀態與查核界線

- **current（來源整理）**：`/Assign` 處理客戶與專員的指派關係，`/LeaveMessages` 處理非工作時間留言規則，`/PendingUser` 顯示待確認使用者。
- **historical（歷史）**：需求快照中的指派欄位、離線日曆或帳號動作，僅是該快照記錄，不代表所有角色目前都能操作。
- **inference（推論）**：改派後回聊天室確認客戶清單、離線規則回日曆確認、待確認動作回列表確認，是降低誤派與漏設的合理檢查順序。
- **runtime unknown（執行期未確認）**：實際角色、批次匯入格式、規則生效時間、帳號同步與對話重新分派結果，需以當期畫面與管理者確認。

## 適用人員與入口

一般客服主要接收已派來的對話；`/Assign`、`/LeaveMessages`、`/PendingUser` 多由主管或管理者使用。沒有相應頁面或按鈕時，不要以其他帳號代操作。

## 正常流程

1. 派線／改派：在 `/Assign` 先確認客戶與專員，再選取關係並按畫面提供的確認動作。
2. 回到聊天室或清單，查驗客戶是否出現在正確專員的處理範圍；若未更新，先不要重複送出。
3. 離線訊息：在 `/LeaveMessages` 選對月份與日期，設定或修改非工作時間規則；大量更新只使用頁面明確提供的檔案格式。
4. 回日曆確認指定日期有正確規則，並記錄變更日期與操作者給交接人員。
5. 待確認使用者：在 `/PendingUser` 檢查清單與帳號，只有依當期授權執行來源明確提供的動作；來源未描述的核准流程不要自行補造。

## 完成判斷

- 派線：客戶與專員關係在畫面清單反映，且目標專員可看到可處理對話。
- 離線訊息：指定日期的規則回到日曆可查，畫面沒有錯誤。
- 待確認使用者：管理者動作完成後，清單狀態以目前畫面為準。

## 權限與前置

需要管理者或指定主管權限、正確客戶／專員、日期與受控檔案。一般客服只處理自己被授權的對話；看不到管理頁面屬權限差異，不是要繞過的錯誤。

## 影響與限制

改派會改變後續對話負責人；離線規則會影響非工作時間回覆；批次匯入可能一次改動多日；帳號撤銷可能影響後續登入。送出前核對範圍，不要用測試資料改動正式關係。

## 第一個排錯

先核對月份／日期、客戶、專員與目前清單，再確認是否收到儲存或匯入錯誤。若是帳號或權限問題，提供頁面、時間與非敏感訊息給管理者；不要直接判定資料未存在。

## 頁面別子流程與 route-specific 排錯

### `/Assign`：指派

1. **頁面／欄位判讀**：分開確認客戶、專員／被指派人與目前關係清單；不要只看勾選框，還要核對送出後的列表狀態。
2. **資料來源／合併邊界**：客戶清單、專員清單與既有指派關係是不同查詢視角；清單顯示不代表聊天室歷史或所有客戶資料都已重新載入。
3. **寫入／對外副作用**：確認／改派會改變後續對話負責人；完成後回聊天室確認處理範圍，不要在未核對客戶與專員時重複送出。
4. **空資料／部分失敗判讀**：客戶查不到、專員查不到、關係清單未更新與聊天室未出現分開判讀；單一關係失敗不等於整個指派頁不可用。
5. **第一個排錯**：清除不必要條件，以單一客戶與專員重查，記錄時間與非敏感提示，再交由管理者確認權限或同步。

### `/LeaveMessages`：離線訊息管理

1. **頁面／欄位判讀**：先選月份，再看日期／行事曆上的工作日與離線規則；大量匯入欄位以頁面目前提供的格式為準。
2. **資料來源／合併邊界**：行事曆規則、匯入檔案與實際聊天室回覆是不同邊界；日曆顯示保存不等於已在所有非工作時間環境生效。
3. **寫入／對外副作用**：新增、修改或批次匯入會影響非工作時間回覆；送出前確認月份、日期區間與檔案，完成後回日曆查驗。
4. **空資料／部分失敗判讀**：整月空白、單日沒有規則、匯入部分日期成功與聊天室未出現預期回覆分開排查；不把空日曆當成服務故障。
5. **第一個排錯**：重新選定月份與單一日期，確認檔案格式與畫面訊息，再請管理者判斷規則同步或環境差異。

### `/PendingUser`：待確認使用者

1. **頁面／欄位判讀**：以待確認清單、帳號識別與目前狀態判斷；來源只支持的動作才可執行，不自行補造核准流程。
2. **資料來源／合併邊界**：待確認清單與 [01-登入與帳號](01-登入與帳號.md) 所述使用者管理清單是不同管理視角；清單移除不等於所有登入快取或角色資料已同步。
3. **寫入／對外副作用**：撤銷或其他當期授權動作可能影響後續登入；完成後回清單確認狀態，不以按鈕關閉視窗當成成功。
4. **空資料／部分失敗判讀**：沒有待確認資料、查詢條件未命中、單一狀態未更新與登入仍可用分開記錄；不要重複執行未知動作。
5. **第一個排錯**：重查清單並核對帳號識別、時間與畫面提示，再交由管理者確認同步與權限。
