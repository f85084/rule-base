# RuleBase 與 project-docs 的專案邊界

## 定位

`rule-base` 是 `project-docs` 的延伸層，不是另一份相同的業務流程文件庫。

主要目標是將既有文件中的資訊，整理成方便查詢與操作的：

- 操作摘要
- 規則快查
- 排錯手冊
- 測試資料索引
- 需求單與文件對照

## 文件來源

CSP 的完整業務流程來源位於：

```text
/home/art/openab-repos/project-docs/projects/CSP/data/business-flows/
```

該專案是完整業務與技術文件的主要來源，包含：

- L1：Controller 技術解析與技術鏈路
- L2：前端頁面全貌與操作範圍
- L3：跨頁面的業務解決方案
- `log-map/`：API、日誌與 Endpoint 對照
- `special/`：特殊機制與跨模組實作說明

## RuleBase 的責任

RuleBase 只保留對日常查詢與操作有幫助的延伸內容，並連回原始文件：

```text
project-docs
    ↓
完整業務流程、頁面與技術文件
    ↓
rule-base
    ↓
操作摘要、規則快查、排錯、測試資料與需求單索引
```

不應在 RuleBase 重新複製完整的 L1、L2 或 L3 內容。若需要完整流程或技術細節，應連結回 `project-docs`。

## 功能索引欄位

未來建立 CSP 或 MSG 功能索引時，至少記錄：

| 欄位 | 說明 |
|---|---|
| 功能名稱 | 對人員可理解的功能名稱 |
| 用途 | 這項功能解決的工作或問題 |
| 原始文件 | 對應的 `project-docs` 文件連結 |
| 操作文件 | RuleBase 中的操作摘要或手冊 |
| 需求單 | 相關需求單編號與連結 |
| 狀態 | 待整理、整理中、待確認或已完成 |
| 待補充事項 | 尚未確認或需要補文件的內容 |

## 判斷原則

- 完整業務流程與技術解析放在 `project-docs`。
- 日常操作、規則快查與排錯內容放在 RuleBase。
- RuleBase 整理來源時，必須保留來源中的操作步驟、條件、例外、錯誤訊息、處理方式與聯絡資料；內容過長應拆分並建立索引，不得自行省略。
- 不確定內容的真實來源時，先連回 `project-docs`，不要自行重寫成另一套流程。
- 新增文件前先確認是否已存在對應的 `project-docs` 文件，避免重複建立。
