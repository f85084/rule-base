# CSP 錯誤訊息快速排查

來源：`data/sources/csp/錯誤訊息排除總表_含提示與駐點資訊20260319.docx`

本文件將來源表整理成快速分流入口。來源表的完整錯誤清單與駐點聯絡資料仍保留在 DOCX；本文件只保留可先自行確認的判斷順序，避免把不同層級的問題混在一起。

## 先判斷影響範圍

| 症狀 | 優先判斷／處理 |
|---|---|
| 只有少數人轉圈或操作異常 | 先詢問操作情境、時間、頁面、客代與截圖，再交由當地駐點資訊排查 |
| 全職場同時轉圈、無法使用 | 直接通知中和 3535 資訊總窗口，並記錄開始時間與影響範圍 |
| 重新登入後恢復 | 優先檢查非正常登出、測試區／正式區、Cookie 或舊工作階段 |
| 同一錯誤持續或多人同時發生 | 不只要求重試；保留錯誤文字、時間、帳號／ACDID、主機與截圖，轉交資訊窗口 |

## 常見錯誤分流

| 關鍵字／錯誤 | 來源表提供的第一步 |
|---|---|
| 防偽令牌過期 | 關閉視窗後重新登入 MI |
| CTI 帳號密碼錯誤 | 確認是否誤開測試區，重新開啟正式區 |
| CTI-58、CTI-56、CTI-1143、CTI-237 | 先拔插 SIP／黑頭話機線路；仍失敗再找資訊人員 |
| CTI-527 | 確認帳號是否仍在其他分機登入，必要時從原分機登出 |
| CTI-565 | 確認是否在通話中再次外撥，交由資訊人員解除通話 |
| CTI-570、CTI-61 | 先登出登入；CTI-61 另可先 Ctrl+F5，再重新登入 |
| CTI Server 未登入／ACDID 錯誤 | 核對 ACDID 與分機設定，請資訊人員確認或重設 |
| SignalR Server 連線失敗 | 先更新電腦並清除 Cookie；仍失敗再聯繫當地駐點資訊 |
| 音檔播放器無法辨認 TimeSpan | 檢查播放清單是否有負數花費時間的音檔，移除後改用 ConnectionId 搜尋 |
| 找不到原始音檔 | 區分電腦網路、音檔主機下架與特定區域檔案問題，再通知對應窗口 |
| 播放器無資料可播放 | 先移出全部音檔、重開播放器後重新加入；仍失敗再重開電腦 |
| 小結更新資料錯誤 `status is null` | 確認 SIP 是否登入正確分機，必要時請 MI 窗口清除小結 |
| 505／500／400／404 | 先重新整理；若為 BI，考量流量過高並避開尖峰重試 |
| 信用卡刷卡異常 | 區分單一客戶／大量客戶：前者確認發卡行，後者稍後重試並通知金流窗口 |
| 商品無法同倉庫出貨 | 確認 KIT 子商品是否位於不同倉庫，請商品處重新設定 |

## 音檔問題的特別分流

音檔問題至少要區分三種情況：

1. 播放清單資料本身錯誤，例如花費時間為負數。
2. 找不到原始音檔，可能是網路、音檔主機或下架狀態。
3. 索引已建立但 NAS 實體檔案稍後才產生，請看 [音檔：索引與檔案建立時間落差](audio-index-delay.md)。

若是同一 `ConnectionId` 出現多段錄音，則應查 `project-docs` 的 [2026-07-17-003 Incident](../../../../project-docs/projects/CSP/data/gotchas/incidents/2026-07-17-003_recording-same-connectionid-multiple-segments.md)，這是 `RecordId`／播放清單去重問題，不是檔案尚未產生。

## 回報時至少提供

- 完整錯誤文字或截圖
- 發生時間、環境／主機、帳號或 ACDID
- 操作頁面、操作步驟、客代／ConnectionId（若適用）
- 影響人數：單一人員、局部人員或全職場
- 是否重新登入、清 Cookie、重插話機或重開播放器後恢復

若本表無法解決，請補齊上述資訊，再依來源 DOCX 的駐點資訊轉交對應窗口；不要只回報「系統壞掉」。
