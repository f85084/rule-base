# CSP #50285／#50152 功能驗收測試案例

這份文件只做功能驗收，技術驗收由開發／維運另行確認。

目前狀態：待 QA 執行

本文件提供一般人員與 PO 直接依畫面驗收。測試者只操作已提供的測試帳號與畫面；維運協助只負責準備合成資料、安排必要的背景動作及清除測試資料，不要求測試者操作背景工作、查看技術紀錄或接觸內部設定。不得在測試紀錄放入帳密、敏感憑證、個資或內部連線資訊。

## 共通說明

- 測試資料一律使用已核准的合成帳號、合成客戶與合成訊息。
- 畫面顯示的測試帳號、客代或訊息內容只記錄遮罩後識別碼。
- 若開始前準備未完成，案例標為待測或阻塞，不以猜測代替。
- 每案的結果記錄請填寫：待 QA 執行／通過／失敗／阻塞、日期、環境、測試角色、畫面證據位置與異常描述。

## #50285

### TC-50285-01 名單同步後出現新資料

- **測試目的**：確認背景同步完成後，新安排的推薦名單會出現在正確的一般人員畫面。
- **測試角色**：一般人員操作；PO 觀察結果；維運協助準備一筆合成的新名單資料。
- **開始前準備**：登入測試環境，確認目前人員與查詢視角正確；維運協助安排資料更新並通知可開始查看。
- **操作步驟**：1. 開啟 TM 名單。 2. 以平常使用的查詢條件查詢。 3. 重新整理畫面一次。 4. 以畫面上的客代或任務識別確認新資料。
- **預期結果**：新資料出現在預期人員的名單中，資料內容與維運協助提供的合成資料相符；原有名單仍可正常查詢。
- **通過判定**：新資料可在正確人員的 TM 名單查到，且沒有出現在不相關人員畫面；目前 runtime 尚未執行前維持待 QA 執行。
- **結果記錄**：填寫結果狀態、執行時間、測試人員、遮罩後資料識別碼、畫面前後截圖位置與異常說明。

### TC-50285-02 有資料與無新資料的畫面判讀

- **測試目的**：確認有新資料時可看到變更，沒有新資料時不會誤增資料或重複通知。
- **測試角色**：一般人員操作；PO 判讀畫面；維運協助準備一個有變更時段與一個無變更時段。
- **開始前準備**：確認測試帳號可查看 TM 名單與通知；記下查詢前的名單筆數與通知狀態，但不記錄個資。
- **操作步驟**：1. 在有變更時段查詢並記錄畫面。 2. 在無變更時段重新整理並記錄畫面。 3. 比較兩次結果與通知數。 4. 重新開啟名單確認沒有重複列。
- **預期結果**：有變更時顯示對應新資料；無變更時畫面維持原狀，不新增空白或重複名單，也不產生不明通知。
- **通過判定**：測試者能清楚區分「有新資料」與「本次沒有新資料」，兩種情況都沒有誤導性畫面或重複項目。
- **結果記錄**：填寫兩個測試時段、畫面證據、名單與通知的前後狀態、結果狀態及異常說明。

### TC-50285-03 指定回電與客訴未結通知

- **測試目的**：確認指定回電與客訴未結的提醒會送到正確人員，且不會重複或誤當成案件已結束。
- **測試角色**：一般人員操作 TM 名單與通知；PO 確認業務結果；維運協助準備兩筆合成情境。
- **開始前準備**：準備一筆指定回電與一筆客訴未結的合成資料；分別準備尚未有提醒及已有相同提醒的畫面狀態。
- **操作步驟**：1. 登入並開啟通知入口。 2. 查看兩種提醒是否出現。 3. 點擊提醒回到對應名單或案件。 4. 回到原功能確認案件狀態。 5. 重新整理後再次確認提醒數量。
- **預期結果**：提醒出現在正確人員畫面，能回到正確的名單或案件；已有提醒不重複增加；提醒消失或刷新不代表案件已結束，原案件仍可查回。
- **通過判定**：兩種提醒均能正確辨識、回查與繼續處理，且沒有串到其他人員或重複建立。
- **結果記錄**：填寫提醒類型、遮罩後案件識別碼、畫面路徑、前後通知狀態、結果狀態與異常說明。

### TC-50285-04 暫時離線再登入後資料正確

- **測試目的**：確認一般人員暫時離開畫面或網路恢復後，重新登入仍能看到正確名單與提醒。
- **測試角色**：一般人員操作畫面；PO 觀察前後一致性；維運協助準備可查回的合成資料。
- **開始前準備**：先開啟 TM 名單並記錄遮罩後的名單與通知狀態；確認測試資料已準備完成。
- **操作步驟**：1. 暫時關閉頁面或依 QA 指示短暫中斷網路。 2. 恢復後重新開啟網站並登入。 3. 回到 TM 名單查詢原條件。 4. 開啟通知並回查一筆原案件。
- **預期結果**：重新登入後可看到目前應有的名單與提醒；資料沒有消失、重複、串到其他人員或回到過期畫面。
- **通過判定**：離開與重新登入前後，名單、提醒及原案件狀態一致且可繼續操作。
- **結果記錄**：填寫離開與重新登入時間、畫面前後證據、遮罩後資料識別碼、結果狀態與異常說明。

## #50152

### TC-50152-01 新訊息提醒

- **測試目的**：確認新訊息會提醒正確的人員，並可從提醒進入訊息內容。
- **測試角色**：一般人員操作訊息畫面；PO 確認提醒與內容；維運協助準備一筆合成未讀訊息。
- **開始前準備**：登入測試帳號並開啟訊息中心；維運協助安排一筆只屬於此帳號的新訊息。
- **操作步驟**：1. 先記錄目前提醒數量。 2. 依通知提示開啟訊息中心。 3. 點開最新訊息。 4. 回到列表再重新整理一次。
- **預期結果**：新訊息提醒出現，點擊後可看到正確的合成訊息；列表與提醒數量前後一致，不會顯示其他帳號內容。
- **通過判定**：測試者可從提醒找到新訊息並完成閱讀或回查，內容與準備資料相符。
- **結果記錄**：填寫提醒前後畫面、遮罩後訊息識別碼、執行時間、結果狀態與異常說明。

### TC-50152-02 兩位測試使用者資料不混淆

- **測試目的**：確認兩位測試使用者只能看到各自的訊息提醒、筆數與內容。
- **測試角色**：兩位一般人員分別操作；PO 比對兩邊結果；維運協助準備兩組不同的合成訊息。
- **開始前準備**：準備兩個已核准的測試帳號，各有一組可辨識但不含個資的合成訊息；兩組資料不得共用識別內容。
- **操作步驟**：1. 第一位使用者登入並查看提醒與訊息列表。 2. 登出。 3. 第二位使用者登入並查看相同位置。 4. 分別重新整理並比對畫面。
- **預期結果**：第一位只看到第一組資料，第二位只看到第二組資料；提醒數量、列表與內容均不串人，也不因上一位登出後殘留畫面。
- **通過判定**：兩位使用者的畫面和資料完全依帳號區分，沒有任何跨帳號顯示。
- **結果記錄**：填寫兩組遮罩後識別碼、各自畫面證據、登入順序、結果狀態與異常說明。

### TC-50152-03 短暫斷線後訊息恢復

- **測試目的**：確認使用者短暫斷線或重新整理後，新訊息仍能在恢復後出現一次並可繼續查看。
- **測試角色**：一般人員操作畫面；PO 觀察恢復前後結果；維運協助安排斷線前後的合成訊息。
- **開始前準備**：開啟訊息中心並確認已有一筆合成訊息；維運協助安排恢復後會出現的另一筆合成訊息。
- **操作步驟**：1. 在訊息中心停留。 2. 依 QA 指示短暫中斷網路或關閉頁面。 3. 恢復後重新開啟並登入。 4. 查看提醒與列表，重新整理一次。
- **預期結果**：原有資料仍可查詢；恢復後的新訊息會出現一次，提醒與內容一致；畫面可繼續使用，不需要測試者處理內部錯誤。
- **通過判定**：恢復後能找到預期新訊息，沒有重複、遺失或跨帳號資料，且可繼續查看其他訊息。
- **結果記錄**：填寫斷線與恢復時間、畫面前後證據、遮罩後訊息識別碼、結果狀態與異常說明。

### TC-50152-04 異常資料後下一筆訊息仍可處理

- **測試目的**：確認一筆由維運協助安排的可恢復異常，不會阻止下一筆正常訊息顯示。
- **測試角色**：一般人員只操作畫面；PO 判讀是否可繼續；維運協助事先安排並清除異常情境。
- **開始前準備**：維運協助準備一筆可還原的合成異常情境，以及一筆後續正常訊息；若環境沒有已核准的可還原情境，本案例標為 automation-only／待建立，不直接執行。
- **操作步驟**：1. 開啟訊息中心查看異常情境的畫面結果。 2. 不自行重試內部操作，記錄畫面提示。 3. 由維運協助恢復環境並安排下一筆正常訊息。 4. 重新整理或重新登入查看下一筆訊息。
- **預期結果**：異常情境有可理解的畫面結果；恢復後下一筆正常訊息可以出現並可開啟，先前異常不會讓整個訊息中心停止或顯示他人資料。
- **通過判定**：下一筆正常訊息能在正確帳號畫面處理；若沒有核准的可還原異常情境，結果只能記為待建立，不得宣稱通過。
- **結果記錄**：填寫異常情境是否可用、維運協助恢復時間、下一筆訊息的畫面證據、結果狀態與異常說明。

## 共同回歸

### TC-COM-01 正常使用後可繼續操作且不重複或串人

- **測試目的**：確認完成名單與訊息的日常操作後，兩個功能仍可互相切換並維持正確資料。
- **測試角色**：一般人員依日常流程操作；PO 做整體驗收；維運協助準備各一組合成名單與訊息。
- **開始前準備**：確認測試帳號可使用 TM 名單與訊息中心；準備一筆名單資料、一筆提醒及一筆訊息，均使用合成識別碼。
- **操作步驟**：1. 登入後查看 TM 名單。 2. 開啟提醒並回查指定回電或客訴未結案件。 3. 切換到訊息中心查看新訊息。 4. 重新整理並登出再登入。 5. 再次查看兩個功能。
- **預期結果**：兩個功能均可繼續使用；名單、提醒、案件與訊息沒有重複、消失或串到其他使用者；重新登入後仍能回查原本應有資料。
- **通過判定**：一般人員可完成整段日常流程，且所有畫面結果與合成資料一致；目前 runtime 未執行前維持待 QA 執行。
- **結果記錄**：填寫流程完成時間、兩個功能的畫面證據、遮罩後資料識別碼、結果狀態與異常說明。
