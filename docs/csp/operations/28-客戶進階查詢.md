# 客戶進階查詢

本篇是 CSP `/SuperiorQuery` 客戶進階資料查詢入口。此頁以客戶編號查詢姓名、身分證字號與聯絡資訊；有效查詢成功後會寫入 MariaDB 稽核紀錄，不能把它當成無副作用的單純讀取頁。

## 1. 權限與資料邊界

- 登入後可查詢，實際頁面權限依目前帳號與環境設定為準；後端會從目前登入身分取得員工編號。
- 查詢資料來自 Fugo Oracle `SPX_OB_GetCustomerInfo`，稽核紀錄寫入 MariaDB `usp_customer_queryLog_add`；本頁不修改客戶主檔。
- 回傳只包含必要識別／聯絡欄位：姓名、身分證字號、住家電話、公司電話、傳真、手機 1、手機 2。
- 查詢日誌在成功取得客戶資料後才寫入；查無客戶不應留下有效查詢紀錄。

## 2. 查詢流程

1. 開啟 `/SuperiorQuery`。
2. 輸入客戶編號；前端要求 8 碼數字且不可 0 開頭。
3. 按【查詢】或在欄位按 Enter，呼叫 `POST api/SuperiorQuery/QuerySuperiors`。
4. 後端取得目前登入員工編號，查詢 Oracle 客戶資料；查到後才寫入查詢稽核 log。
5. 查詢成功後核對姓名、身分證字號與聯絡資訊；電話欄位由後端以區碼與號碼組成 `area - number` 格式。
6. 若查詢失敗，先以錯誤視窗為準；頁面不保留前一次結果，避免誤把舊客戶資料當成目前查詢結果。

## 3. API、欄位與狀態

| 項目 | 規則／技術重點 |
|---|---|
| 路由 | `/SuperiorQuery`。 |
| 客戶編號 | 前端 8 碼數字、不可 0 開頭；後端以 `customerId` 查詢。 |
| API | `POST api/SuperiorQuery/QuerySuperiors`。 |
| 登入員工 | 後端從 `AuthorizeManagement.CurrentUser.UserId` 取得 `EmployeeNo`，不是由畫面任意指定。 |
| 客戶資料來源 | Oracle `SPX_OB_GetCustomerInfo`。 |
| 稽核資料 | 查詢成功後寫 MariaDB `usp_customer_queryLog_add`，記錄 CustomerId 與 EmployeeNo。 |
| 電話格式 | `FormatPhone(area, number)` 組成 `area - number`；空值可能顯示為 ` - `。 |
| 成功／失敗 | 有資料才寫 log；查無資料回 `NotFound`，查詢 log 寫入失敗也會影響整體流程。 |

## 4. 異常處理與排錯

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 前端無法送出 | 客戶編號是否為 8 碼數字且非 0 開頭 | 修正欄位後重試，不以姓名、手機或其他識別值代替。 |
| `查無客戶資料`／`NotFound` | CustomerId、環境與客戶是否存在 | 確認輸入與資料來源；查無資料不會寫有效 query log。 |
| 結果顯示舊資料 | 目前查詢回應與錯誤狀態 | 重新送出有效查詢；失敗時頁面應清除前一次結果，不要手動沿用舊畫面。 |
| 電話顯示 ` - ` 或不完整 | Oracle 回傳的區碼／號碼欄位 | 保留 CustomerId、回應時間與欄位狀態；這是目前 FormatPhone 的輸出邊界，不自行拼接資料。 |
| Oracle `ORA-04045`／`ORA-01775` | Fugo Oracle `SPX_OB_GETCUSTOMERINFO`、時間、TID／主機 | 先確認是否多台 CSP 主機同時發生，再交 Fugo／Oracle DBA 檢查 synonym chain；不要把 Oracle synonym 問題判定為單一瀏覽器或 CSP 前端故障。 |
| 查詢資料已回來但流程仍失敗 | MariaDB query log 寫入結果與回應 | 查詢 log 寫入是 await 流程的一部分，保留 CustomerId、EmployeeNo、時間與錯誤，交維運比對。 |

## 5. 維運稽核注意事項

- 每次有效查詢會留下 CustomerId 與 EmployeeNo 的查詢 log；排錯時以查詢時間、登入員工與客戶編號交叉比對。
- 不要用查詢結果回填或修改客戶主檔；需要資料異動時轉至具備相應權限的客戶／會員操作入口。
- 若同一 Oracle SP 的錯誤同時影響客戶 dashboard 或其他客戶資訊流程，優先升級 Fugo／Oracle DBA，並保留跨主機與 TID 證據。
