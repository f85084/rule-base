# 客戶進階查詢

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP `/SuperiorQuery` 客戶進階資料查詢入口。此頁以客戶編號查詢姓名、身分證字號與聯絡資訊；有效查詢成功後會寫入 MariaDB 稽核紀錄，不能把它當成無副作用的單純讀取頁。

## 1. 權限與資料邊界

- 登入後可查詢，實際頁面權限依目前帳號與環境設定為準；查詢會以目前登入身分留下稽核紀錄。
- 本頁只回傳必要的客戶識別／聯絡資訊，不修改客戶主檔；稽核紀錄的技術來源見下方維運查核補充。
- 回傳只包含必要識別／聯絡欄位：姓名、身分證字號、住家電話、公司電話、傳真、手機 1、手機 2。
- 查詢日誌在成功取得客戶資料後才寫入；查無客戶不應留下有效查詢紀錄。

## 2. 查詢流程

1. 開啟 `/SuperiorQuery`。
2. 輸入 8 碼、非 0 開頭的客戶編號。
3. 按【查詢】或在欄位按 Enter。
4. 查詢成功後核對姓名、身分證字號與聯絡資訊；電話若不完整，保留畫面結果，不自行拼接。
5. 若查詢失敗，先以錯誤視窗為準；頁面不保留前一次結果，避免誤把舊客戶資料當成目前查詢結果。

## 3. 異常處理與排錯

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 前端無法送出 | 客戶編號是否為 8 碼數字且非 0 開頭 | 修正欄位後重試，不以姓名、手機或其他識別值代替。 |
| `查無客戶資料`／`NotFound` | CustomerId、環境與客戶是否存在 | 確認輸入與資料來源；查無資料不會寫有效 query log。 |
| 結果顯示舊資料 | 目前查詢回應與錯誤狀態 | 重新送出有效查詢；失敗時頁面應清除前一次結果，不要手動沿用舊畫面。 |
| 電話顯示不完整 | 查詢結果與發生時間 | 保留客戶編號、回應時間與欄位狀態，不自行拼接資料。 |
| 查詢資料已回來但流程仍失敗 | 畫面錯誤、查詢時間與帳號 | 保留查詢識別與錯誤，交維運比對資料查詢與稽核結果。 |

## 4. 維運查核補充

以下技術來源、欄位映射與稽核寫入規則只供維運查核；一般讀者先依前文完成查詢。Oracle／MariaDB 回應、錯誤與跨主機影響若未 runtime 驗證，不是現行保證。

### 查詢與稽核來源

| 項目 | 規則／技術重點 |
|---|---|
| API | `POST api/SuperiorQuery/QuerySuperiors`；以 `customerId` 查詢。 |
| 登入員工 | 由 `AuthorizeManagement.CurrentUser.UserId` 取得 `EmployeeNo`，不是由畫面任意指定。 |
| 客戶資料 | Oracle `SPX_OB_GetCustomerInfo`。 |
| 稽核資料 | 成功查詢後寫 MariaDB `usp_customer_queryLog_add`，記錄 CustomerId 與 EmployeeNo。 |
| 電話格式 | `FormatPhone(area, number)` 組成 `area - number`；空值可能顯示為 ` - `。 |
| 失敗邊界 | 查無資料回 `NotFound`；稽核寫入失敗也可能影響整體流程。 |

每次有效查詢會留下 CustomerId 與 EmployeeNo 的查詢 log；需要資料異動時轉至具備相應權限的客戶／會員操作入口。若同一 Oracle SP 的錯誤同時影響其他客戶資訊流程，保留跨主機、TID 與時間證據交 Fugo／Oracle DBA 查核。
