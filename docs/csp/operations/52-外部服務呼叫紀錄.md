# 外部服務呼叫紀錄

本篇是 CSP `/ApiLog` 外部服務呼叫紀錄查詢入口。此頁只讀取 `apilog` 的請求與回應資料，供維運依時間、分頁及內容追查串接問題；不提供刪除、重送或修改外部呼叫的操作。

## 1. 權限與查詢範圍

- 登入後可查詢；實際頁面可見範圍仍以目前帳號與環境為準。
- 查詢條件是請求時間區間與分頁，不要把此頁當成外部服務的即時健康檢查或重送入口。
- request／response 內容可能包含串接資料。複製或回報時只保留必要識別資訊，依既有維運資料處理規範保護敏感內容。

## 2. 查詢與翻頁

1. 開啟 `/ApiLog`，先確認目前環境與查詢目的。
2. 設定 `startTime`、`endTime`；只需要單側範圍時可保留另一側為空。
3. 執行查詢，依清單查看 API 名稱、RequestId、RequestUrl、請求／回應內容與時間。
4. 以頁碼與每頁筆數翻頁；翻頁時保留原本的時間條件，避免把不同範圍的結果混在一起。
5. 追查串接問題時，以 RequestId、ApiName、RequestTime 對照上下游紀錄，再判斷是否需要轉交服務負責人。

查詢使用 `GET api/ApiLog/QueryApiLog`，參數為 `startTime`、`endTime`、`page`、`pageSize`。後端會分別查詢總筆數與當頁清單，結果依 `Id` 遞減排列。

## 3. 欄位與規則

| 欄位／資料 | 維運用途 |
|---|---|
| `startTime`／`endTime` | 以請求時間篩選；任一為空時忽略該側邊界。 |
| `page` | 分頁頁碼；小於或等於 0 時偏移量按 0 處理。 |
| `pageSize` | 每頁筆數；需為有效整數。 |
| `ApiName` | 辨識呼叫的 API。 |
| `RequestId` | 串接上下游紀錄的交叉比對鍵。 |
| `RequestUrl`、`RequestData` | 確認實際請求目標與內容。 |
| `RequestTime`、`ResponseTime` | 對照請求與回應時間。 |
| `ResponseData` | 確認外部回應內容；回報時避免暴露不必要資料。 |

查詢條件完全為空時，會依分頁查詢全量資料；資料量較大時先縮小時間範圍再追查。

## 4. 異常處理

| 情況 | 處理方式 |
|---|---|
| 查無資料 | 確認時間區間、環境、頁碼與每頁筆數；空集合不代表可以自行補造紀錄。 |
| 翻頁結果不符預期 | 檢查是否保留原時間條件，以及是否將 page 設為有效值；重新查詢後再判斷。 |
| 查詢失敗或底層例外 | 記錄時間區間、帳號、環境與錯誤訊息；此 Controller 沒有額外錯誤包裝，交由系統／資料庫維運追查。 |
| 找不到預期外部呼叫 | 先確認呼叫時間是否落在 `RequestTime` 範圍、查詢環境及實際 API；不要以此頁沒有資料推論外部服務未被呼叫。 |
