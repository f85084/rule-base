# 撥號日期管理

本篇是 CSP `/DialScheduler` 撥號日期維護入口。此頁維護外撥前置碼判斷所使用的日期清單；實際前置碼是在取得 TM 名單時由後端決策，再傳給軟體電話／CTI，不能把本頁儲存成功直接視為通話路由已驗證。

## 1. 權限與操作前確認

- 先確認帳號已登入且目前環境、日期與需求單一致；查詢與異動按鈕是否可用，以目前帳號權限為準。
- 本頁異動的是撥號日期清單，不是直接編輯專員、名單或 CTI 的電話號碼。
- 同一時間可能有其他維運人員修改清單。保留頁面載入時取得的版本資訊，不要用舊分頁直接覆蓋新資料。

## 2. 查詢目前撥號日期

1. 開啟 `/DialScheduler`，先載入目前日期清單與版本資訊。
2. 確認要新增或移除的日期，再檢查清單中是否已存在，避免送出無效的重複異動。
3. 若查無資料，先把它視為空清單；不要自行補入日期。

頁面查詢使用 `GET api/DialScheduler/QueryDialScheduler`，回傳日期清單與後續更新所需的版本值。

## 3. 新增／移除日期

1. 在畫面中準備新增日期與移除日期的集合；只做本次需求明確要求的變更。
2. 確認至少有一筆新增或移除，再執行儲存。新增、移除可依頁面送出的兩個集合一併處理。
3. 儲存成功後重新查詢頁面，確認清單與日期版本已更新；必要時再用受控的 TM 名單流程驗證實際取得的 `dialCode`。

更新使用 `POST api/DialScheduler/UpdateDialScheduler`。後端會先比對送回的版本；版本一致才寫入新增／移除日期，成功後清除日期快取並產生新版本。

### 日期切換與前置碼邊界

- 今天是否落在撥號日期清單，會形成 `isDialCodeDate` 判斷。命中日期時，TM 名單的前置碼決策可使用系統設定 `SYS_SoftwareDialCode`；未命中時，該值不會因本頁而強制帶入。
- `LevelName` 為空、字串 `null` 或 `Z` 時，同樣是後端前置碼決策的特殊條件；不要只以日期清單推斷單一名單的最終電話字串。
- `dialCode` 由後端取得 TM 名單時決定，前端再原樣傳給 SignalR／CTI；`dialCode` 為空時由 CTI 使用其預設行為。因此本頁完成後應依實際流程驗證，不要在本頁自行修改 CTI 預設值。

## 4. 欄位、規則與 API

| 項目 | 規則／操作重點 |
|---|---|
| 查詢 | `GET api/DialScheduler/QueryDialScheduler`；取得日期清單與版本。 |
| 新增日期 | 送入更新請求的新增集合；日期需能被後端解析。 |
| 移除日期 | 送入更新請求的移除集合；只移除目前要撤下的日期。 |
| 版本 | 更新前由後端與目前版本比對，屬樂觀鎖；不可沿用過期頁面的版本強制覆蓋。 |
| 更新 | `POST api/DialScheduler/UpdateDialScheduler`；新增／移除集合不可同時為空。 |

## 5. 異常處理

| 畫面／回應 | 判斷與處理 |
|---|---|
| `資料已被其他使用者修改，請重新整理頁面。` | 版本衝突。停止重送，重新整理取得最新清單，重新確認本次新增／移除後再儲存。 |
| `請至少新增或移除一個撥號日期` | 本次沒有任何異動；回到清單確認後再送出有效變更。 |
| 日期格式解析失敗 | 保留錯誤內容，檢查日期欄位格式與清單資料，不要以猜測格式重送。 |
| `更新失敗，請聯絡系統管理員。` | 先重新查詢確認是否已寫入；若仍失敗，記錄時間、帳號、日期集合與版本，交由系統管理員處理。 |
| 外撥顯示非預期前置碼或失敗 | 先記錄實際 `dialCode`、名單／客戶識別與時間，再分別核對日期命中、`LevelName` 特殊值及 CTI／交換機紀錄；不要直接判定為 CSP 全站故障。 |
