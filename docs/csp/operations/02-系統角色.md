# 系統角色

本篇是 CSP `/Role` 系統角色維護入口。頁面分成角色群組、角色基本資料、角色功能／區塊權限，以及角色成員四個範圍；不要把角色設定與[系統功能](01-系統功能.md)的功能樹維護或[使用者設定](31-使用者設定.md)的代理人設定混為同一個操作。

## 1. 權限與操作邊界

- 登入後可查詢角色資料、功能矩陣與成員清單；新增、修改、刪除及儲存權限／成員需要角色維護權限，實際按鈕以目前帳號為準。
- 角色掛在角色群組下；新增角色前必須先確認目標群組存在。
- 角色功能設定改的是角色可用功能與區塊，不是建立或修改功能樹本身；功能樹與網址請到[系統功能](01-系統功能.md)處理。
- 角色成員設定改的是使用者與角色的關聯，不等於代理人設定；代理人請到[使用者設定](31-使用者設定.md)處理。

## 2. 查詢與選擇範圍

1. 開啟 `/Role`，先載入角色群組與其下角色。
2. 選取目標群組或角色，確認名稱與層級後再開啟編輯。
3. 角色功能視窗會載入功能群組、功能、啟用中的區塊與目前角色設定；未授權項目會保持未勾選。
4. 人員設定視窗分開顯示已套用此角色的使用者與可加入使用者；可加入清單會排除已選使用者。

## 3. 群組與角色基本資料

### 3.1 群組

1. 新增或選取角色群組，填寫名稱與描述後儲存；欄位必須通過頁面驗證。
2. 修改群組只處理群組基本資料，不在此步驟搬移角色。
3. 刪除前先確認群組底下沒有角色；仍有角色時系統會阻擋刪除。

### 3.2 角色

1. 新增角色時選定既有群組，填寫角色基本資料與頁面要求欄位後儲存。
2. 修改角色基本資料時，確認目前角色與群組，不要以編輯角色取代群組操作。
3. 刪除角色前先確認其權限與成員影響；刪除結果仍受資料庫／關聯約束影響。

## 4. 設定功能／區塊權限

1. 在目標角色開啟功能設定，先查詢完整功能矩陣與目前勾選狀態。
2. 依核准範圍調整功能與區塊勾選，逐項確認角色、功能及區塊識別。
3. 儲存時系統會在交易中先清除該角色既有功能／區塊設定，再依本次完整選擇重建；這不是只更新畫面上改動的一筆。
4. 儲存成功後會清理角色、區塊及受影響使用者的 menu cache；重新載入或重新登入後，用受影響角色驗證實際選單。

## 5. 設定角色成員

1. 開啟目標角色的人員設定，分辨「已選使用者」與「可加入使用者」。
2. 只勾選核准納入角色的使用者；若本次清單為空，代表清空此角色的使用者歸屬。
3. 儲存時系統會先比較既有與本次清單，再分別新增新勾選者、移除未勾選者。
4. 儲存後重新查詢角色成員，並讓受影響使用者重新載入選單以確認權限快取已更新。

## 6. API 與異常處理

| 操作 | API | 維運重點／例外 |
|---|---|---|
| 查詢角色樹 | `GET api/Role/QueryRoles` | 無資料時回空集合。 |
| 群組 CRUD | `POST api/Role/CreateRoleGroup`、`UpdateRoleGroup`、`DeleteRoleGroup` | 欄位驗證失敗會被拒絕；有角色的群組不可刪除，訊息為 `群組中還有角色存在，不可刪除!`。 |
| 角色 CRUD | `POST api/Role/CreateRole`、`UpdateRole`、`DeleteRole` | 新增指定的群組不存在時為 `角色群組不存在!`；其他驗證／資料庫錯誤保留回應。 |
| 查詢功能權限 | `GET api/Role/QueryRoleFunctions` | 查無既有設定仍回完整矩陣，未授權項目未勾選。 |
| 儲存功能權限 | `POST api/Role/CreateRoleFunction` | 以完整選擇重建；任一新增失敗不要假設部分設定已成功，重新查詢確認。 |
| 查詢成員 | `GET api/Role/QuerySelectedUserList`、`QueryUserList` | 無資料時回空集合；找不到使用者資料時姓名可能顯示 `未知`。 |
| 儲存成員 | `POST api/Role/UpdateRoleUserData` | 以既有／新清單差集增刪；空 `userIds` 代表清空角色歸屬。 |
