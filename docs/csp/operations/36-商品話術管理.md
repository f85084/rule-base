# 商品話術管理

## 敘述狀態與查核界線

- **現行事實**：`/SalesPitch` 入口、列表／明細／新增／更新／刪除的操作範圍，以及來源可直接核對的輸入驗證與資料異動邊界，依現有頁面與 API 來源整理。
- **歷史規則**：MI 手冊中的話術欄位示例、商品搜尋或話術快取的舊流程，只表示歷史文件曾如此描述；不把示例欄位、固定數量或舊入口當成目前保證。
- **推論**：由列表、模板、商品查詢與關聯資料整理出的部分成功／失敗判讀，是維運排錯用的推論；不能由前端列表變化反推所有關聯已同步。
- **runtime 未確認**：目前帳號角色、Vespa 匹配與排序、部分關聯失敗補救、快取 key／TTL／清除入口，以及各 API 的實際回應未在本次環境驗證；以當期 UI、回應、設定與 log 為準。

本頁對應 `/SalesPitch`，位於「內部工作管理」，用來維護商品話術主檔與銷售編號的綁定。[商品話術管理需求](../requirements/pages/36-商品話術管理.md) 目前為 0 筆需求單；下列操作先以畫面上的查詢、表單與結果為準，技術查核集中於文末。

## 入口與權限

- 網站路由：`/SalesPitch`；可由 [website-menus.json](../../../data/sources/csp/website-menus.json) 的 `id: 103` 核對，選單分類為「內部工作管理」。
- log-map 只確認登入後可查詢、檢查與操作；沒有提供管理職／一般職的細分矩陣。按鈕是否顯示以帳號實際授權為準，新增、更新、刪除前應確認目前登入者。
- 新增、更新與刪除會記錄目前登入者；不要把畫面送出的操作者欄位當成可信來源。

## 列表與商品名稱查詢

1. 在列表輸入銷售編號或商品名稱，依需求選一種查詢條件；兩種條件不要混用推導結果。
2. 商品名稱查詢會先找符合商品，再展開話術綁定；銷售編號查詢則直接找對應話術。
3. 列表為空時先確認條件、帳號、商品是否存在與目前資料範圍，不要直接判定話術已被刪除。
4. 點選銷售編號可開啟商品明細；商品明細是輔助判讀，不是新增話術的另一個操作入口。

## 話術模板與明細

新增或編輯時，先載入目前表單提供的話術模板，再依畫面勾選與填寫可用項目。MI 手冊列出的「商品亮點、開場白、產品重點、價格優惠、案例短篇、成交核對」只是常見示例；欄位與數量以當下畫面為準。

明細需要模板與話術內容都存在；任一邊為空時先記錄話術識別、回應與時間，交由維運查核，不要用其他話術代替。

## 新增話術

1. 開啟新增表單，確認模板載入完成。
2. 填寫話術內容與銷售編號清單，確認沒有空白或未完成項目。
3. 送出前逐筆確認銷售編號未重複綁定且商品存在。
4. 儲存成功後重新查詢主檔與銷售編號關聯；若只有部分項目失敗，保留失敗項目與回應，不要直接重送整批。

## 更新話術

1. 開啟既有話術，確認目前模板、內容與銷售編號關聯。
2. 修改模板或關聯清單後送出；若只改模板，不要把空清單誤當成要清除所有關聯。
3. 更新後重新查詢主檔、模板與關聯；若主檔成功但關聯失敗，依回應逐項確認，不要以列表變化推論全部完成。

## 刪除話術

刪除前確認話術識別、商品與銷售編號關聯；刪除後重新查詢。若話術不存在或刪除失敗，保留畫面訊息與時間，不要以列表暫時消失推論所有關聯與快取都已更新。

## 銷售編號檢查、快取與例外

輸入銷售編號後先確認格式、是否已有話術及商品是否存在。查詢、模板、明細與檢查本身不應被當成資料異動；新增、更新、刪除則要以重新查詢確認結果。若檢查結果為空或查詢例外，保留條件、回應與時間，不要用其他商品代替。

## 維運查核補充

以下集中 API、DomainData、資料庫程序、Repository／use case、Vespa 與快取證據；一般讀者先依前文的畫面步驟操作。部分關聯補救、快取 key／TTL／清除入口與實際回應未由 runtime 確認，不能寫成契約。

### 查詢、模板與明細

- `POST /api/SalesPitch/GetList` 接受 `SalesPitchListRq`。有 `ProductName` 時先以 Vespa 找商品銷售編號，再查話術綁定；沒有 `ProductName` 時以 `SaleNo` 查 `usp_salesPitch_getList_v1`。列表會補 `CreatedName`、`ModifiedName`、商品名稱，空列表的 `total` 為 0。
- `POST /api/SalesPitch/GetSalesPitchItem` 讀取 `MoneyInDomainData.SALES_PITCH` JSON，解析為 `SalesPitchItem` 清單；`POST /api/SalesPitch/GetSalesPitchById` 以 `pitchId` 組合 Domain 模板與話術內容。
- `Vespa` 的關鍵字匹配、排序與實際分頁細節沒有在 Controller 展開；`SalesPitchDetail` 無法解析時沒有已確認的 fallback。

### 寫入、關聯與快取

- `POST /api/SalesPitch/AddSalesPitch` 先寫主檔，再寫銷售編號關聯；`SendCheck`、`ValidateTemplates` 會檢查模板、商品與既有綁定。部分關聯失敗的補救未由 Controller 定義。
- `POST /api/SalesPitch/UpdateSalesPitch` 會依關聯增刪分類處理；新增／移除分別涉及 `usp_salesPitch_addSaleNo_v1`、`usp_salesPitch_deleteBySaleNo_v1`，`ValidateSaleNoList` 的 `null` 與空清單不可自行視為相同。
- `POST /api/SalesPitch/DeleteSalesPitch` 以整數 `id` 刪除，後端由登入者補 `ModifiedBy`，執行 `usp_salesPitch_delete`；快取清除由 use case／repository 下層處理，沒有來源證明目前存在人工清快取按鈕。
- `POST /api/SalesPitch/CheckSaleNo` 先查話術綁定，再查商品名稱；來源記載 Repository 例外可能回 `null` 後繼續，但不代表所有商品查詢例外都會被吞掉。快取 key、TTL 與實際失效狀態仍以當期設定與回應為準。
