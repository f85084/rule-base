# 帳號設定

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP `/User` 使用者列表與角色配置入口。此頁從人員維度查詢啟用使用者並調整其角色；它不是 AD 帳號開通／解鎖頁，也不是[系統角色](02-系統角色.md)的角色、功能與成員定義頁。

## 1. 權限與資料邊界

- 登入後可查詢可用使用者及其角色；儲存角色配置需要使用者／權限維護權限，實際可用按鈕以目前帳號為準。
- 使用者清單只提供啟用中的使用者，來源會先走使用者快取，必要時再查詢員工資料；不要在此頁自行加入停用或離職帳號。
- AD 帳號存在與鎖定是登入／驗證前置條件；本頁只處理使用者查詢與角色關聯，不會替 AD 或 FuGo 帳號開通、解鎖或修改密碼。
- 角色本身的群組、功能／區塊權限與角色成員，請分別依[系統角色](02-系統角色.md)的邊界處理；本頁只維護「使用者—角色」關聯。

## 2. 查詢使用者

1. 開啟 `/User`，載入使用者列表。
2. 使用頁面提供的關鍵字與分頁控制定位目標人員；確認顯示的 `EhsUserId`、姓名、帳號與 Email。
3. 只對目前清單中的啟用使用者開啟角色編輯；若找不到人員，先確認帳號是否已完成 AD／FuGo 前置條件，不要直接建立猜測資料。

頁面載入使用者列表；畫面會顯示 `EhsUserId`、姓名、帳號與 Email，查無資料時先視為目前條件沒有符合使用者。

## 3. 查詢與儲存角色

1. 選取人員後開啟角色編輯，查看該使用者目前的角色集合。
2. 角色視窗會列出完整角色清單，`Checked` 表示該使用者目前是否已套用；群組名稱由角色群組資料補上。
3. 先核對人員、角色名稱、群組與啟用狀態，再依核准內容勾選角色。
4. 儲存前確認本次勾選是完整的最終集合，不是只填寫想新增的一筆。
5. 儲存後重新開啟角色視窗或重新登入受影響帳號，確認角色與選單快取已更新。

儲存會依本次完整集合重建使用者角色關聯；空角色集合代表清除既有角色。完成後重新載入或登入驗證選單，不要只看送出按鈕狀態。

## 維運查核補充

以下欄位、API 與寫入規則只供維運查核；一般讀者先依前文確認使用者與完整角色集合，再操作畫面。

| 操作 | API／欄位 | 規則 |
|---|---|---|
| 使用者列表 | `GET api/User/QueryUsers` | 僅回傳啟用使用者與 `EhsUserId`、`DisplayName`、`Account`、`Email`。 |
| 角色查詢 | `GET api/User/QueryUserRoles?userId=...` | 回傳完整角色清單與目前 `Checked` 狀態。 |
| 角色儲存 | `POST api/User/UpdateUserRoleData` | `UserId` 與角色集合需可正常綁定；以全量重建方式更新。 |
| 空角色集合 | Update request 的角色資料為空 | 清除該使用者既有角色，仍會清理相關快取。 |

## 5. AD／登入問題的處理邊界

- 正式環境登入會依 `SYS_ADLogin` 使用 LDAP／AD 驗證，再由 FuGo 取得使用者資料；帳號不存在、關閉、鎖定或密碼錯誤的訊息應在登入流程確認。
- `/User` 查不到啟用使用者時，先記錄帳號、環境與登入／員工資料狀態，交由帳號管理或系統維運確認；不要把「查不到」直接當作 AD 已鎖定，也不要在此頁重複建立帳號。
- 使用者可登入但沒有電話功能時，另確認電話工具的 Agent／分機資料；這不屬於本頁角色儲存操作。

## 6. 異常處理

| 情況 | 處理方式 |
|---|---|
| 查無使用者 | 確認關鍵字、環境與啟用狀態；再依 AD／FuGo 前置條件交由帳號管理確認。 |
| 查無角色或全未勾選 | 確認目標 UserId 與角色資料；空清單可能代表尚未配置角色，不自行補授權。 |
| 儲存失敗 | 重新查詢確認是否已更新；保留 UserId、角色集合、時間與錯誤訊息，勿假設部分角色已成功。 |
| 儲存後仍看到舊選單 | 重新查詢、重新登入受影響帳號，確認角色是否更新；不要立即重複送出全量更新。 |
| 登入顯示帳號不存在／關閉／鎖定 | 依登入錯誤訊息記錄帳號與時間，交由 AD／FuGo 帳號管理處理；本頁不提供解鎖或密碼異動。 |
