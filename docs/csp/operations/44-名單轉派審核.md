# 名單轉派審核

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP／MI 的名單轉派審核入口，對應網站路由 `/OutBoundListTransferReview`。供指定審核人或代理審核人查看待審名單轉派申請、檢視明細，並執行核准、駁回或頁面提供的抽單操作。

## 權限與審核人

1. 進入頁面後先載入目前使用者與代理人清單；從審核人下拉選單選擇要處理的審核人／被代理人視角。
2. 尚未選擇審核人時，【搜尋】按鈕會保持不可用；不要直接以空白 reviewerId 查詢。
3. 申請人不能審核自己送出的申請。代理人處理時，確認目前選取的被代理人、案件關卡與代理範圍，不能只看登入者本人權限。
4. 審核清單會依權限分一般審核人與第三關管理員模式；可見範圍由後端權限判斷，前端清單不是跨部門全量資料。

## 查詢待審清單

1. 選定審核人後執行查詢；頁面會以分頁方式載入待審申請單。
2. 查詢 API 的 `reviewerId`、`page` 不可為 0 或負值，`pageSize` 不可大於 100；遇到參數錯誤先確認頁面分頁狀態，不要連續重送。
3. 清單查無資料時，保留審核人切換與重新查詢能力；空清單不等於申請單被刪除。
4. 開啟案件明細後，核對申請單 ID、客代、申請原因、申請／目標單位、目前關卡、審核人、附件與歷程。需要補充通話或客訴資料時，依明細中的 Connection ID／CSId 回查相關入口。

## 核准與駁回

### 送出前

- 【審核說明】是核准與駁回的必要欄位；未填時先補足具體判斷理由，不能只依按鈕結果推定已留下歷程。
- 再次確認案件仍屬目前審核人、沒有被其他視窗或人員先處理，且申請資料與附件已讀取完成。
- 若頁面回傳 `failReason` 或權限／流程提示，先依提示處理，不要重複點擊核准。

### 核准

1. 在明細確認申請內容與審核說明後執行核准。
2. 系統會先新增審核歷程，再依目前是否為最後關卡推進流程。
3. 非最後關卡會更新審核流程，最後關卡會同步更新 FUGO 的名單歸屬並發送通知；因此核准成功不只代表畫面狀態改變，也要回查[名單轉派查詢](45-名單轉派查詢.md)與通知中心。
4. 若是最後關卡，送給 FUGO 的資料範圍以客代、被指派專員、操作類型、審核人及申請原因標籤等必要資料為限；申請說明、附件與審核歷程留在 CSP，不要將它們當成已傳到 FUGO。

### 駁回

1. 填寫駁回原因／審核說明後執行駁回。
2. 系統會先新增駁回歷程，再將審核流程改為駁回；駁回不會刪除申請單，也不會繼續推進後續關卡。
3. 成功後通知申請人。申請人可到[名單轉派查詢](45-名單轉派查詢.md)查看駁回原因並依需要重送。

## 抽單與附件

- 明細可查看歷程與附件；附件不存在時，明細仍可開啟但附件區可能沒有圖檔。先確認案件 ID、附件識別資料與權限，不要把附件空白直接判定為整張申請單遺失。
- 共用明細元件提供【抽單】時，只在頁面允許的申請狀態執行；若目前不是可抽單狀態，交由原申請／審核流程處理，不要直接呼叫 API。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 搜尋按鈕不可用 | 是否選定審核人、代理人清單、登入權限 | 重新選擇審核人並確認可見範圍；不要用空白 reviewerId 查詢 |
| 查詢參數錯誤 | reviewerId、頁碼、每頁筆數 | 確認頁碼大於 0、每頁不超過 100，保存畫面與查詢條件 |
| 查不到應有案件 | 被代理人、目前關卡、組織範圍、案件是否已被處理 | 先切換審核人視角並重新查詢；必要時用名單轉派查詢回查案件狀態 |
| 核准或駁回顯示無權限 | 目前審核人、代理關係、案件關卡、是否為申請人本人 | 停止重送，記錄案件 ID、登入者與被代理人，交權限／維運確認 |
| 顯示找不到申請單或審核流程 | AppId、案件是否已被其他人處理、明細是否過期 | 回查名單轉派查詢與歷程；不要重建相同申請單 |
| 送出後流程或名單未更新 | 審核歷程、目前關卡、最後關卡結果、通知與 FUGO 回應 | 保存案件 ID、操作時間與錯誤訊息，交維運比對流程與名單歸屬 |
| 重複送出或寫入失敗 | 是否開啟多個明細視窗、歷程是否已寫入 | 停止重試；依 BadRequest／NotFound／SystemError 記錄相應資訊後回報 |

## 維運查核補充

本節集中審核關卡、代理、附件、抽單與重送的技術查核範圍；一般讀者先依前文待審案件與核准／駁回流程操作。代理與部分流程若未 runtime 驗證，不得把歷史描述當成現行權限保證。
