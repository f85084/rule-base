# 名單轉派查詢

本篇是 CSP／MI 的名單轉派查詢入口，對應網站路由 `/OutBoundListTransfer`。用於追蹤名單轉派申請、查看明細與歷程、處理駁回重送，以及匯出目前查詢結果。

## 使用前確認

1. 先確認使用者角色與可查詢的組織範圍；組長可查自己部處下的組別，處長與部長依既有部／處範圍查詢。若是代申請或跨組協助，先確認申請單是否已進入可見範圍。
2. 由右上角名單轉派通知進入後，仍要回到本頁確認案件明細與審核狀態；通知本身只代表有事件，不取代案件查詢。
3. 若案件附有 CS 編號，可由明細點選連至客訴處理頁面。

## 查詢與明細

### 查詢條件

- 依頁面提供的搜尋類型輸入條件後查詢；切換搜尋類型時保留已選擇的時間區間，避免重複輸入。
- 查詢範圍受角色與組織限制。組長請假由他組組長協助申請時，需確認協助組別的案件仍可被查到；處長、部長的範圍依既有權限維持。
- 查詢結果與匯出內容應先確認搜尋條件及時間範圍；匯出會依目前搜尋結果處理，而不是只依畫面上最後選取的搜尋類型。

### 明細檢查

開啟案件明細時，至少確認：

- 申請單 ID、申請時間、申請人、來源／目標單位與審核狀態。
- 申請原因、申請客代、會員／OB 等級、前一次維運專員，以及申請時附加的說明與圖片。
- 申請原因為緣故件時，若客戶沒有 OB 等級，仍應顯示 `OB 等級：` 欄位，不要把空白誤判成資料遺失。
- 圖片可正常載入與放大；列表查看與審核頁面的圖片權限不同，若無法查看，先確認目前頁面與使用者是否具備相應權限。

## 審核狀態與後續處理

- **審核中**：確認目前關卡與審核人員，等待對應主管／代理人處理；不要直接重複建立相同申請。
- **核可**：確認名單已完成轉派，並通知或回查被指定專員的新名單。若結果未出現，檢查通知中心與 TM 名單。
- **駁回**：查看駁回原因。申請人可使用【重送】複製原申請內容建立新單；已檢查且未修改的內容不需重複檢查，有修改的欄位必須重新檢查後再送審。
- **名單轉換／沉澱客戶**：涉及沉澱客戶的變更時，確認操作者屬於名單小組，勿只以頁面的一般管理／稽核權限判斷。
- A、B 級客戶的名單轉派申請，需確認是否已進入營運長簽核流程；未完成最終簽核前不可視為已完成轉派。

## 匯出

1. 先完成查詢並確認結果範圍，再執行匯出。
2. 匯出排序依申請時間新到舊，應與網頁呈現方向一致。
3. 依申請原因確認欄位：客戶進線、LINE 留言、客戶插撥等案件應檢查「前一次維運專員」；資料若與名單歷程不符，保留申請單 ID、時間與匯出條件供追查。
4. 若人員曾發生部門轉調，匯出仍應取得轉調前的部門資料；遇到部門欄位錯誤，不要直接以目前組織資料覆蓋案件歷史。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 查不到跨組協助申請 | 角色、部門範圍、搜尋時間 | 確認組長查詢範圍與案件目前所屬單位；必要時請管理職協助確認權限 |
| 駁回後沒有【重送】 | 案件是否確為申請人、狀態是否為駁回 | 先開啟明細確認狀態與申請人，再回報頁面權限或資料問題 |
| 圖片不存在或無法放大 | Lab／正式環境、圖片來源頁面、權限 | 記錄案件 ID 與圖片請求位置；列表與審核頁面分別確認權限，不要只以瀏覽器重整判斷 |
| 匯出排序或欄位不正確 | 查詢條件、申請時間、前一次專員、部門轉調 | 保存原查詢條件與匯出檔，交由維運／開發比對歷程資料 |
| 核可時出現未知錯誤 | 審核人／代理人、組織層級、目前關卡 | 確認操作者是指定審核人、代理人或名單小組，再記錄案件 ID 與錯誤時間 |
