# 訂單質檢

本頁給質檢人員、主管與維運人員查詢及處理訂單質檢案件使用。網站路由為 `/OrderQA`；需求單與來源請見文末連結。

## 1. 先確認角色與案件

訂單質檢涉及質檢人員、組長、處長及質檢小組主管等角色。開始處理前先確認：

1. 目前登入帳號的質檢權限與可處理範圍。
2. 案件所屬專員、目前質檢者與目前處理人員。
3. 質檢類型、質檢日期、案件狀態，以及是否已有上訴或複核紀錄。
4. 關聯訂單與音檔是否正確；若需要追查通話，先確認音檔與 Connection ID。

質檢歷程涉及權限控管；一般權限查詢範圍也可能受時間限制，需依目前帳號權限與頁面提示判斷。

## 2. 查詢與開啟質檢單

1. 進入【訂單質檢】頁面，依可用條件查詢案件。
2. 開啟案件後，先閱讀質檢單基本資料、關聯訂單、音檔與既有歷程。
3. 確認目前流程節點與處理人員，再開始填寫或判斷質檢內容。
4. 若需查核通話內容，使用音檔或 Connection ID 對照實際紀錄；不要只依訂單摘要判斷。

## 3. 判斷質檢結果

依質檢項目逐項判斷，並保留必要的處理方式、分數、說明與附件。分數不可填寫負數；批次匯入時也要確認欄位格式、CID、質檢類型、被懲處人及處理方式是否正確。

### 正常流程

判斷為正常時，依目前流程送出。若兩位組長均判斷正常，案件可正常結案；測試資料預期 `order_qa.resultType` 為 `2`。

### 缺失與懲處流程

判斷有缺失時，依案件流程選擇懲處與處理方式，再送出確認。系統會依流程保存缺失判斷與處理人員；不要只在備註描述缺失而未完成正式結果欄位。

若同一案件有不同組長的判斷，需確認系統依流程保存的缺失組長員編。自動判斷案例中，第一位組長判斷正常、第二位組長判斷懲處時，預期 `order_qa.mistake` 記錄第一位組長員編。

## 4. 上訴與複核

1. 確認案件是否符合上訴條件，以及目前是否仍在上訴時間內。
2. 上訴時保留上訴內容、原判斷、相關附件與處理歷程。
3. 若案件進入複核，依複核流程完成判斷後再結案；不要直接覆蓋原有判斷。
4. 處理完成後回看歷程，確認上訴、複核、處理人員與時間均已寫入。

質檢歷程與附件都有權限限制；若看不到資料，先確認帳號權限與案件歸屬，不要直接判定資料不存在。

## 5. 批次匯入與重新指派

### 批次匯入

批次匯入前先確認 Excel 欄位與資料格式，至少核對：

- CID／關聯訂單資料。
- 質檢類型。
- 被懲處人與員工編號。
- 處理方式、分數、說明及附件／截圖欄位。
- 員工是否已離職或留停。

匯入失敗時保留完整錯誤訊息，特別檢查 CID、欄位換行與員工狀態；不要只重複匯入同一份檔案。

### 重新指派

需要變更質檢人員或處理人員時，先確認質檢日期、部門與角色條件，再依權限重新指派。重新指派後應回看案件歷程與目前 `assignTo`，確認案件沒有留在原處理人員名下。

## 6. 結案前檢查

結案前逐項確認：

1. 質檢項目已完成判斷，分數與處理方式正確。
2. 缺失、懲處或正常結果已依流程送出。
3. 關聯訂單、音檔、Connection ID 與附件對應正確。
4. 上訴／複核案件已完成必要流程，歷程可追溯。
5. 案件狀態已更新，且沒有待處理人員或下一流程節點。

## 7. Lab 驗證流程

訂單質檢的 Lab 測試帳號、初始化欄位與預期結果請依[訂單質檢測試資料](../test-data/test-data-order-qa.md)執行。主要驗證：

| 測試案例 | 流程 | 預期結果 |
|---|---|---|
| 手動缺失判斷 | 懲處 → 確認 → 上訴 → 結案 | 缺失組長員編正確保存 |
| 手動缺失判斷含複核 | 懲處 → 確認 → 上訴 → 複核 → 結案 | 複核歷程與缺失資訊完整 |
| 自動缺失判斷 | 組長 1 正常 → 組長 2 懲處 → 確認 → 懲處 | `order_qa.mistake` 為組長 1 員編 |
| 正常結案 | 組長 1 正常 → 組長 2 正常 | `order_qa.resultType = 2` |
