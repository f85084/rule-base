# 小結清單

## 一般人員操作入口

**這頁做什麼**：在 `/ContactSummary` 依專員識別查詢近一小時電話小結，必要時補登完成時間。它不是通話後填寫結果的 [電話小結作業](13-電話小結作業.md)。

**開始前**：準備員工／專員數字識別與查詢時間，確認目前帳號有維運／管理權限；不要以姓名或猜測 ID 查詢。

**照著做**：

1. 開啟 `/ContactSummary`，輸入員工識別後按查詢。預期結果：列表顯示近一小時小結與分頁。
2. 核對列中的小結 `id`、客戶／時間與員工，確定是要補登的項目。預期結果：不會選錯小結。
3. 只對已處理且需要補登的項目執行【補登完成時間】，再重新查詢。預期結果：完成時間與清單狀態更新。

**完成確認與常見問題**：識別、分頁、目標列與完成時間可回查。`Count=0` 先確認 ID、時間與分頁；電話顯示未顯示號碼不要猜原號碼；更新失敗不要重複操作。

**影響與技術附錄**：補登會寫入小結完成時間並可能產生通知已讀事件；API、操作者覆寫與型別邊界留在後段。

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP `/ContactSummary` 維運／管理查詢入口，用來查詢指定專員近一小時的電話小結清單，並補登小結完成時間。它不同於[電話小結作業](13-電話小結作業.md)：電話小結作業是在通話後選擇成交、拒絕、回電等結果並完成小結；本頁只處理清單查詢與完成時間補登。

## 1. 權限與查詢範圍

- 本頁供維運／管理用途使用；實際可見頁面與操作按鈕依目前登入帳號權限為準。
- 查詢以指定員工／專員識別為條件，資料範圍是該員工近一小時內的電話小結。
- 前端員工識別欄位不可空白且需為數字；不要以姓名或猜測帳號代替識別值。

## 2. 查詢清單

1. 開啟 `/ContactSummary`。
2. 輸入目標員工識別，確認不是空值且格式為數字。
3. 執行查詢，依頁面分頁查看清單；若沒有資料，接受 `Count=0`，不要自行補造小結。
4. 確認顯示的客戶識別與姓名。後端會補查缺少的 CustomerID／Name；電話空白或含字母時，畫面顯示 `未顯示號碼`。

查詢使用 `POST api/ContactSummary/QueryContactListByUserId`，請求包含 UserId、Page、Limit。`Page<1` 會按第一頁偏移處理；分頁時應以畫面回傳的筆數與頁碼為準。

## 3. 補登完成時間

1. 先確認目標列的 `id` 與員工／時間資訊，避免選錯小結。
2. 只對確定已處理、需要補登的項目執行完成操作。
3. 執行後重新查詢，確認完成時間與清單狀態已更新。

補登使用 `POST api/ContactSummary/UpdateContactDoneTime`，請求以小結 `id` 定位。後端從登入內容取得 UserId，不採信前端自行帶入的操作者；成功後會發布 `NoticeReadIntegrationEvent`。這個操作不是重新填寫通話結果，也不會取代電話小結作業中的狀態選擇。

## 4. 欄位與邊界

| 項目 | 規則／維運重點 |
|---|---|
| 員工識別 | 查詢必要條件；前端要求非空數字。 |
| Page／Limit | 查詢分頁欄位；Page 小於 1 時後端按第一頁偏移處理。 |
| 顯示時間範圍 | 近一小時內的電話小結；超出範圍不要當作查詢遺失而自行補資料。 |
| 客戶資料 | 缺 CustomerID／Name 時由後端補查；補不到或電話不適合顯示時依畫面提示處理。 |
| 小結 id | 更新完成時間時必須是可解析的整數識別；不可手動改寫或猜測 id。 |

## 5. 寫入與副作用

- 查詢清單是唯讀；【補登完成時間】會寫入目標小結的完成時間，並可能發布通知已讀事件。
- 後端以登入內容取得實際操作者，不採信前端自行帶入的操作者；送出後要以小結 id 重新查詢確認結果。
- 補登完成時間不等於重新完成電話小結，也不會取代[電話小結作業](13-電話小結作業.md)的追蹤狀態寫入。

## 6. 異常處理

| 情況 | 處理方式 |
|---|---|
| 查詢欄位被阻擋 | 檢查員工識別是否填寫且為數字；保留頁面驗證訊息。 |
| 查無資料 | 確認員工識別、查詢時間與分頁；`Count=0` 是正常空結果，不補造資料。 |
| 電話顯示 `未顯示號碼` | 依畫面顯示處理，不以字串猜測原始電話；需要追查時記錄小結 id、時間與員工識別。 |
| 補登失敗或下游錯誤 | 保留回應與識別資料，重新查詢確認是否已更新；不要重複操作造成誤判。 |
| 小結彈窗未出現、歷史空白或 ContactID 溢位 | 記錄 ContactID、員工與通話時間，交由系統／資料庫維運檢查型別與下游錯誤；不要手動轉換識別值。 |
