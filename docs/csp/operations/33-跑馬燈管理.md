# 跑馬燈管理

本篇是 CSP／MI 的跑馬燈管理入口，對應網站路由 `/Marquee`。用於建立、發送、查詢歷史跑馬燈，以及依當期可見功能重新發送訊息。

## 敘述狀態與查核界線

- **現行事實**：目前前端 route 為 `/Marquee`；頁面提供範本、歷史查詢、接收部門選擇與新增／重新發送入口。建立成功後後端會寫入跑馬燈資料並發送即時刷新事件。
- **歷史規則**：既有手冊／需求描述過一般權限、管理權限、近 30 天歷史與每則最多 10 分鐘等規則；這些內容保留作為操作背景，不等同目前所有環境的保證。
- **runtime 未確認**：來源中的授權略過設定、顯示期限、組織可視範圍、歷史查詢實際可回看天數與各帳號按鈕狀態，仍應以當期 UI、設定、回應及授權矩陣確認；程式名稱集中於維運查核補充。

## 權限與使用前確認

- 既有手冊將權限分為一般權限（組長、處長、部長）與管理權限（講師）；管理權限沒有發送對象限制。實際可見功能仍以目前帳號權限與頁面顯示為準，不要僅因能看到歷史資料就推定可以發送給所有部門。
- 一般權限的發送對象受組織範圍限制，通常只能選擇自己所屬部門的同層級組別；發送人查詢權限已放寬到可查同組人員發送的內容。
- 跑馬燈會顯示在 MI 工具列／頁首區域，訊息可能覆蓋目前舊訊息；發送前要確認內容與收件組別。

## 建立與發送

1. 進入【跑馬燈管理】，選擇自訂內容或制式內容。預設為「自訂」；選擇制式內容後會帶入內容欄位，仍可依需要修改。
2. 輸入跑馬內容，內容上限為 50 字。避免把測試文字、內部不應公開的資料或未確認的時間直接送出。
3. 點【選擇】開啟組織圖，依可見範圍個別勾選或全選發送群組；下方會顯示已選擇的部門／人數。管理權限無發送對象限制的規則，仍以帳號實際權限為準。
4. 送出前再次核對內容、收件組別與字數，點【送出】後觀察接收端是否出現新訊息。

## 顯示與歷史規則

- 既有手冊／需求描述新發布的跑馬燈會閃爍提醒，且每則最多顯示 10 分鐘；目前實際顯示期限與到期行為屬 **runtime 未確認**，以當期設定與 UI 為準。
- 新訊息會覆蓋舊訊息；多個 MI 分頁也會在上方顯示跑馬燈。若要保留內容，先在歷史查詢確認，不要把畫面目前顯示當成完整歷程。
- 既有手冊記載歷史查詢範圍為近 30 天，並描述一般權限、同組與同處管理職的可查範圍；目前查詢日期與組織可視範圍仍以頁面條件與授權結果為準（**runtime 未確認**）。
- 查詢結果中，同一則訊息會合併顯示；接收部門過多時列表以 `...` 顯示，將游標移到項目上可由 Title 查看完整部門列表。
- 歷史資料可直接【發送】，或開啟後修改再發送；重新發送前仍須重新確認收件範圍，因為它會覆蓋當前舊訊息。

## 資料來源與寫入副作用

- 範本、歷史與接收端是不同資料邊界；任一區塊空白時，先保留畫面結果，不以空範本推論資料已被刪除。
- 空的歷史清單可能是條件未命中，不直接等同服務故障。
- 新增／重新發送會寫入資料並通知接收範圍；送出前核對收件部門。結果不明時保留訊息、部門、操作者、時間與回應，不重複盲送。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 看不到【送出】或不能選部門 | 帳號角色、管理權限、組織範圍 | 記錄帳號角色與頁面狀態，請權限管理者確認；不要代用其他帳號發送 |
| 送出後收件人沒看到 | 收件群組、訊息內容、發送時間、是否被新訊息覆蓋 | 先查近 30 天歷史並確認接收端分頁；保留發送人、時間與收件群組 |
| 逾目前設定的顯示期限仍顯示 | 發送時間、目前是否有更新訊息、頁面版本 | 重新整理並確認其他分頁；若仍未消失，附上訊息內容與時間回報（對應 #49321） |
| 歷史查不到訊息 | 查詢日期、發送人範圍、同組／同處權限 | 依當期 UI 縮小日期並確認權限；不要只因歷史描述就推定資料不存在 |
| 發送對象列表顯示不完整 | 列表省略號與 Title 完整內容 | 以 Title 內容核對實際部門，再判斷是否為顯示問題；不要依省略文字發送 |
| 跑馬燈圖示或工具列跑版 | 瀏覽器寬度、目前 MI 分頁、是否有新訊息 | 記錄解析度、瀏覽器與截圖回報；對應 [#49581](https://redmine.etzone.net/issues/49581) |

## 維運查核補充

本節集中跑馬燈設定、發送、歷史查詢與外部影響的技術查核範圍；一般讀者先依前文表單與狀態操作。deadline、歷史範圍與發送結果若未 runtime 驗證，以當期公告與回應為準。

### 資料來源與寫入查核

- 範本查詢會合併 `MARQUEE_ONE`、`MARQUEE_TWO`、`MARQUEE_THREE` 三組 DomainData；任一組為空或格式錯誤時保留原始回應。
- 歷史清單查詢 MariaDB 跑馬燈資料，部門條件會展開可視部門並去重。
- 新增／重新發送逐部門建立主檔與歷史資料，建立者由目前登入者帶入，成功後透過 SignalR 廣播刷新事件；多部門部分失敗的交易／回復策略尚未 runtime 確認。
