# 外呼組別管理

本篇是 CSP／MI 的外呼組別管理入口，對應網站路由 `/OutBoundTeam`。用於查詢外呼組別、維護組別名稱／狀態，以及新增、修改、移除組別成員。

## 使用前確認

1. 進入頁面後系統會載入組別清單、年資、推薦類別、成員角色與狀態選項；若下拉資料未完成，不要先送出新增或修改。
2. 左側組別清單支援前端關鍵字篩選；點選組別後才載入右側成員清單。頁面初次載入會帶出第一筆組別及其成員，需先確認選取的組別 ID 與名稱。
3. 實際新增、編輯、刪除按鈕受登入帳號與環境權限控制；操作前記錄組別、員工編號與目前狀態。

## 組別查詢與維護

### 查詢

- 頁面初始化使用 `GET /api/OutBoundTeam/QueryOutBoundTeamData` 取得組別與選項資料。
- 組別名稱搜尋是前端對已載入清單的篩選，不會因輸入關鍵字而另外查詢後端。
- 點選組別後使用 `POST /api/OutBoundTeam/QueryMembers` 載入成員；沒有成員時回傳空清單，先確認組別 ID，不要把空清單當成系統錯誤。

### 新增組別

1. 點選新增組別，填寫名稱；名稱為必要欄位。
2. 儲存前確認名稱未與現有組別重複。
3. 系統會以目前登入者作為建立人，並透過 `CreateTeam` 寫入外呼組別。

### 編輯組別

1. 選定組別後修改名稱或狀態；`Id`、`Name`、`Status` 都必須可通過驗證。
2. 儲存後重新載入組別清單與成員，確認更新的是原本的組別，不是關鍵字篩選後的其他項目。
3. 暫時不使用時，先依業務確認是否調整狀態；不要以刪除組別取代停用，頁面未提供組別刪除流程。

## 成員維護

### 欄位與新增

新增成員至少確認下列資料：

- `TeamId`：目標外呼組別。
- `EmployeeNo`：員工編號。
- `RoleType`：組員角色。
- `Status`：成員狀態。
- `Seniority`：年資欄位。

推薦類別選項由頁面初始化資料提供；新增與更新成員時，後端 UseCase 會將 `RecommendCategory` 固定補為 `1001`，不要以畫面空白或舊值推定寫入值。

新增流程會先查該組現有成員；同一員工已在同一組別時會被擋下。確認員工編號、組別 ID、角色、狀態與年資後，再送出【新增】。

### 更新成員

1. 從指定組別的成員清單選取成員。
2. 修改頁面允許的成員欄位，確認組別與員工識別資料沒有被換成另一筆。
3. 儲存後重新查詢成員清單，確認資料與狀態已更新；後端會記錄目前登入者作為修改人。

### 移除成員

1. 先核對組別、成員 ID 與員工編號。
2. 執行移除後重新查詢清單，確認該成員不再列出。
3. 移除使用 `SPX_OB_UpdTeamMember` 的刪除操作模式；若結果不明，不要重複點擊，以免無法判斷第一次操作是否已完成。

## API 與異常處理

| 操作 | API | 來源可確認的例外／邊界 |
|---|---|---|
| 初始化組別與選項 | `GET /api/OutBoundTeam/QueryOutBoundTeamData` | 選項讀取失敗時先確認 domain／組別資料是否完整 |
| 新增組別 | `POST /api/OutBoundTeam/CreateTeam` | 名稱空白或重複為 `BadRequest`；Fugo 寫入非 OK 可能為 `SystemError` |
| 更新組別 | `POST /api/OutBoundTeam/UpdateTeam` | `Id`、`Name`、`Status` 驗證失敗或更新失敗時中止 |
| 查詢成員 | `POST /api/OutBoundTeam/QueryMembers` | 無成員回空結構；組別 ID 必須可解析 |
| 新增成員 | `POST /api/OutBoundTeam/CreateMember` | 欄位驗證失敗、同組重複員工為 `BadRequest`；寫入失敗可能為 `SystemError` |
| 更新成員 | `POST /api/OutBoundTeam/UpdateMember` | 成員編號、組別、角色、狀態等驗證失敗時中止 |
| 移除成員 | `POST /api/OutBoundTeam/RemoveMember` | 組別／成員識別資料不合法或 SP 失敗時回錯誤 |

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 新增組別顯示同名錯誤 | 組別清單、名稱前後空白、前端篩選結果 | 以完整組別清單確認名稱；不要連續重送 |
| 新增成員出現 `ORA-00001` | 組別 ID、員工編號、是否已在該組、是否重複點擊 | 先重新查詢成員清單；若已存在，停止新增並記錄組別／員工編號與時間 |
| 成員欄位驗證失敗 | TeamId、EmployeeNo、RoleType、Status、Seniority | 依頁面欄位重新選擇；保留錯誤訊息，不要用手動 API 繞過驗證 |
| 組別或成員寫入失敗 | Fugo 回應、目前資料、操作人 | 先查詢確認是否已寫入，再以錯誤時間、組別／成員識別資料回報 |
| 組別有資料但成員清單空白 | 選取組別 ID、QueryMembers 結果、資料同步 | 重新選取組別並查詢；不要直接新增同名成員 |
| 修改後畫面仍是舊資料 | 儲存結果、重新查詢、目前選取組別 | 重新載入清單後比對；保留修改人與時間供追查 |
