# 直播／見面會管理

## 一般人員操作入口

**這頁做什麼**：在 `/LiveStreamManage` 查詢活動、查看內容／報名統計；具 Admin／管理權限者才新增、編輯、匯出或修正管理名單。客戶報名回 [直播／見面會報名](18-直播-見面會報名.md)。

**開始前**：確認活動名稱、時間、目前帳號與資料用途；非 Admin 只處理可見範圍，不以空名單判定整場沒有資料。

**照著做**：

1. 開啟活動管理，設定目前畫面提供的搜尋條件／分頁後按查詢。預期結果：列表顯示活動名稱、時間、狀態與平台／類型。
2. 開啟活動明細，先查內容、報名名單與統計，核對 ActivityId／活動名稱。預期結果：統計與目標活動一致。
3. 有管理權限才新增／編輯欄位或匯出 Excel；儲存／匯出後重新查詢與抽查檔案。預期結果：主檔、內容與輸出可回查。

**完成確認與常見問題**：活動、可視範圍、統計／名單與檔案符合查詢條件。零筆先核對條件與部門權限；更新不一致記錄 ActivityId、時間與非敏感提示。

**影響與技術附錄**：活動新增／編輯、報名資料修正與匯出會寫入或產生受控檔案；API、roster 與驗證規則留在後段。

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP `/LiveStreamManage` 直播／見面會活動管理入口，負責活動清單、場次新增／編輯、活動內容與報名統計，以及管理端名單查詢／匯出。它與[直播／見面會報名](18-直播-見面會報名.md)不同：本篇管理活動主檔與管理名單，報名入口則由專員對客戶執行報名或取消報名。

## 1. 權限與範圍

- 新增、編輯活動及匯出報名名單標示為 Admin／管理權限；一般登入者可依頁面權限查詢活動與可視範圍資料。
- 活動管理與客戶報名是兩條不同流程；不要在管理頁替代專員的客戶報名操作，也不要把活動取消或編輯當成客戶取消報名。
- 報名名單查詢會依非 Admin 使用者可視的部門／處／組裁切；統計與匯出使用完整活動 roster，操作前確認資料授權與用途。

## 2. 查詢活動清單

1. 開啟 `/LiveStreamManage`，先設定頁面提供的活動搜尋條件與分頁。
2. 執行查詢後確認活動名稱、活動時間、狀態、活動類型／平台等顯示資料，再選擇檢視內容、明細或編輯。
3. 查無資料時保留空結果與查詢條件；不要自行判斷活動已被刪除。

查詢使用 `POST api/LiveStreamManage/Query`，後端依活動搜尋條件回傳清單與分頁資料；總筆數由查詢結果組裝。

## 3. 新增與編輯活動

### 新增

1. 以具活動維護權限的帳號選擇新增活動。
2. 填寫頁面要求的活動名稱、開始／結束時間、報名截止時間、人數上限、平台類型與狀態等欄位。
3. 依需求確認活動類型；本頁的直播／見面會活動類型與平台選項要以目前環境顯示為準，不能把活動類型當成報名方式。
4. 通過欄位驗證後儲存，取得新 `ActivityId`，再回查清單確認活動主檔與活動資訊。

使用 `POST api/LiveStreamManage/CreateActivity`。後端透過 `ActivityValidator` 驗證後，寫入活動主檔與活動資訊。

### 編輯

1. 從清單選取既有活動，確認 `ActivityId` 與要修改的場次。
2. 修改欄位後重新確認時間、截止時間、人數、平台／活動類型與狀態的相容性。
3. 儲存後重新查詢；更新成功需包含主檔與活動資訊兩段資料更新。

使用 `POST api/LiveStreamManage/UpdateActivity`。更新前會檢查活動存在，並再次通過 `ActivityValidator`。

## 4. 內容、統計與管理名單

1. 內容彈窗只檢視清單已查得的主推商品與活動內容，不把它當成另一個編輯入口。
2. 以活動明細查看報名名單時，使用 `POST api/LiveStreamManage/GetActivityRoster`；非 Admin 只能取得可視部門範圍。
3. 需要查看整場報名統計時，使用 `GET api/LiveStreamManage/GetStatistics`；結果依活動報名資料彙整部門／處資訊。
4. 具備管理權限且有明確匯出需求時，使用 `POST api/LiveStreamManage/ExportExcel`；匯出前確認活動與資料範圍。
5. 若要修正單筆報名者客戶資訊，使用 `POST api/LiveStreamManage/UpdateActivityCustomerInfo`，需帶有效 `ApplyId`；這是管理端資料修正，不是替客戶送出報名。

## 維運查核補充

以下欄位、狀態與 API 對照只供維運查核；一般讀者先依前文活動清單與表單操作。

| 操作 | API | 規則／邊界 |
|---|---|---|
| 活動查詢 | `POST api/LiveStreamManage/Query` | 查無資料回空結果；支援清單分頁。 |
| 新增活動 | `POST api/LiveStreamManage/CreateActivity` | 需 Admin；名稱、時間區間、報名截止、人數上限、平台類型與狀態需通過驗證。 |
| 更新活動 | `POST api/LiveStreamManage/UpdateActivity` | 需 Admin；活動須存在，主檔與資訊表更新都成功才算完成。 |
| 報名名單 | `POST api/LiveStreamManage/GetActivityRoster` | 依登入者可視部門裁切；組織設定無法解析時拒絕。 |
| 活動統計 | `GET api/LiveStreamManage/GetStatistics` | 以指定活動的完整 roster 組裝統計。 |
| Excel 匯出 | `POST api/LiveStreamManage/ExportExcel` | 需 Admin；以指定活動 roster 產生檔案。 |
| 修正報名者資訊 | `POST api/LiveStreamManage/UpdateActivityCustomerInfo` | `ApplyId` 不可為 0；只修正報名資料中的客戶資訊。 |

活動驗證包含開始／結束時間同日且結束時間晚於開始時間等規則；日期與狀態不符合時先修正欄位，不要重複送出。

## 6. 異常處理

| 情況 | 處理方式 |
|---|---|
| 新增／編輯被驗證拒絕 | 逐項核對名稱、時間、截止時間、人數、平台／狀態；保留頁面錯誤訊息。 |
| 更新回報失敗 | 重新查詢活動，確認主檔與活動資訊是否一致；若不一致，記錄 ActivityId、時間與回應交由維運處理。 |
| 報名名單不完整 | 先確認登入者的部門可視範圍與活動 ActivityId；非 Admin 不應以缺少其他部門資料判定資料遺失。 |
| `組織設定有誤，請確認組織別。` | 檢查目前帳號的組織資料與可視部門設定，記錄 ActivityId、帳號與時間後交由維運處理。 |
| `UpdateActivityCustomerInfo` 回 `需有報名序號` | 確認 `ApplyId`，不要用活動 ID 或客戶 ID 代替；此操作不會建立報名。 |
| 統計／匯出與清單不同 | 先確認統計或匯出使用的活動、查詢時間與權限範圍；保存 ActivityId 與輸出結果供比對。 |

## 7. 與報名入口的區分

| 需求 | 使用入口 |
|---|---|
| 建立或修改直播／見面會活動、時間、平台與狀態 | 本篇 `/LiveStreamManage`。 |
| 查詢客戶可報名場次、送出或取消客戶報名 | [直播／見面會報名](18-直播-見面會報名.md) 的 `/LiveStreamSignUp`。 |
| 管理端查看活動名單、統計或匯出 | 本篇的活動明細與管理功能。 |
