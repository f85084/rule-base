# 系統功能

本篇是 CSP／MI `/Function` 系統功能維護入口，供具備功能與權限維護責任的管理職使用。此頁異動會影響功能樹、可見選單與部分區塊權限；若只是查詢目前選單，不要直接修改功能設定。

## 1. 先確認操作範圍與權限

- 本頁管理三類資料：功能群組、群組底下的子功能，以及子功能的區塊設定。
- 新增、修改、刪除與區塊設定維護屬管理操作；實際可見按鈕以目前帳號權限與環境為準。
- 修改功能項目後，系統會清除相關功能 cache；若功能已被角色使用，也會清除受影響使用者的 menu cache。完成後應重新載入選單驗證。
- 不要把 `/Function` 的設定當成單一畫面偏好；功能 URL、啟用狀態與區塊設定可能直接影響角色可用功能。

## 2. 查詢功能樹

1. 開啟 `/Function`。
2. 先查看左側功能群組，再點選群組檢視其子功能。
3. 右側編輯區會顯示目前選取項目的名稱、描述、排序、網址、ICON 與相關區塊設定。
4. 若目標是確認使用者實際可見選單，重新登入或重新載入後，以該使用者的角色範圍驗證，不只看功能維護樹。

頁面載入會取得功能群組、功能項目與區塊設定；使用者選單則另由 `QueryMenu` 依 Power User 或角色功能組裝。

## 3. 新增與編輯功能

### 3.1 新增功能群組

1. 選擇新增功能群組。
2. 填寫名稱、排序、ICON 與描述。
3. 送出前確認名稱與排序位置，避免與既有群組重複或造成選單順序錯亂。
4. 儲存後重新查詢功能樹與使用者選單。

### 3.2 新增子功能

1. 先選定要掛載的功能群組。
2. 選擇尚未使用的功能網址；頁面會透過 `QueryFunctionUrls` 取得可配置的網址。
3. 填寫子功能名稱、啟用狀態、排序與描述，確認 ICON 與所屬群組。
4. 儲存後確認子功能出現在正確群組，並以受影響角色驗證選單。

### 3.3 編輯功能群組或子功能

- 名稱為必填，最長 50 字元。
- 描述最長 200 字元。
- 群組與子功能共用維護入口，但以 `GroupId` 判斷寫入哪一層；操作前要確認目前選取的是群組還是子功能。
- 修改子功能的啟用狀態、網址、排序或區塊設定後，必須重新檢查選單與實際頁面路由。

## 4. 區塊設定

1. 在子功能下開啟區塊設定。
2. 新增區塊時填寫區塊名稱；更新時確認 `BlockId` 與目前功能項目一致。
3. 依需求調整區塊啟用與前端隱藏狀態。
4. 批次更新時逐筆確認結果；任一筆失敗後不要假設後續項目也已成功。
5. 若將區塊關閉，系統會同步移除該區塊的角色設定並清除角色區塊 cache；完成後需重新檢查角色實際可見狀態。

## 5. 刪除前檢查

- 刪除動作實際上會檢查功能樹節點，若目標底下仍有子功能，系統會拒絕刪除並回報「子層有其他功能，無法刪除！」。
- 先確認是否仍有角色、需求或文件引用該功能，再處理子功能與群組的依賴關係。
- 不要用刪除取代停用；若只是暫時不提供功能，優先確認是否應調整啟用狀態。

## 6. 異常處理與驗證

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 儲存失敗或提示驗證錯誤 | 名稱是否空白、長度、目前層級 | 修正欄位後重新送出；保留畫面訊息 |
| 子功能沒有出現在選單 | 功能啟用狀態、角色功能、menu cache | 重新載入或登入驗證；必要時交由維運確認 cache |
| 刪除被拒絕 | 目標是否仍有子功能 | 先處理子層或改用停用，不要重複送出刪除 |
| 區塊關閉後權限仍顯示 | 區塊啟用／隱藏狀態、角色設定、角色 cache | 重新登入或刷新後再驗證，記錄功能與區塊識別 |
