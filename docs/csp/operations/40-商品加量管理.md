# 商品加量管理

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本頁對應 MI 的 `/ProductIncrease`，位於「內部工作管理」。它處理已建立的商品加量案件：查詢一般／OB 清單、分批載入、標記完成、刪除與 Excel 匯出。[商品加量管理需求](../requirements/pages/40-商品加量管理.md) 目前是 0 筆需求單；以下只記錄來源可證實的 API 與邊界，不把其他頁面或歷史需求內容當成此頁現行功能。

## 入口與權限

- 網站路由：`/ProductIncrease`；可由 [website-menus.json](../../../data/sources/csp/website-menus.json) 的 `id: 127` 核對，選單分類為「內部工作管理」。
- 登入後可依目前帳號權限查詢一般／OB 清單、完成／刪除案件及匯出；不要自行推定只有管理職才能操作。
- 初始的無量通報發生在[接單作業](06-接單作業.md)的商品流程；本頁沒有「建立加量申請」或「重新送出申請」入口。不要把查詢頁當成申請入口。
- 完成與刪除都會改變資料並可能通知申請人，執行前先核對案件、商品與申請人。

## 查詢與分批載入

1. 進入頁面後先選擇一般或 OB 清單，再依畫面提供的銷售編號條件查詢。
2. 清單採分批載入；向下捲動時保留原本條件，不要把一般與 OB 清單混在一起判讀。
3. 每批資料可能另外補上申請人與組織顯示名稱；名稱缺少時，先核對案件識別與原始資料，不要直接判定案件不存在。
4. OB 清單載入失敗時，先重新查詢並記錄畫面回應；不要用一般清單結果代替 OB 清單。

## 欄位與狀態邊界

### 來源可確認的識別與操作欄位

- 查詢條件、案件識別、完成／刪除與匯出範圍，都以畫面欄位與目前回應為準。
- 清單中的申請人、部、處、組是顯示用資料，不是另一個可編輯表單。

### 清單／Excel 欄位

歷史需求快照可核對的清單欄位包括申請時間、銷售編號、商品、供應商、組織與專員等資訊；這些欄位可作為現行畫面與 Excel 的交叉核對線索，實際輸出仍以當前畫面與 Excel 範本為準。

### 狀態

- 【完成】會將指定案件標記完成；目前沒有可由本頁確認的「取消完成／恢復」操作。
- 【刪除】是刪除資料，不是把案件改成另一個可查詢的狀態。刪除後不要假設仍能由本頁復原。
- 完成與刪除的結果可能是失敗訊息／失敗回應；查無商品或查無申請人時不應只重複點擊按鈕。

## 完成：可用量、申請人與通知

1. 點【完成】前確認案件、商品、可接單量與申請人。
2. 完成後重新查詢案件與通知中心，確認狀態與通知是否一致。
3. 可用量為 0、查無商品／申請人或結果不明時，保留畫面訊息與時間，不要重複點擊。

## 刪除與通知副作用

刪除前確認案件、商品與申請人；刪除後回查清單與通知。完成與刪除都可能通知申請人，通知中心的實際文案與導頁行為以當期畫面為準；若未收到通知，連同案件、申請人、時間與回應一起交維運查核。

## Excel 匯出

1. 先確認列表條件與是否只匯出 OB，再按【匯出】。
2. 下載後檢查檔案可開啟、資料範圍與列表條件是否一致。
3. 沒有下載檔時，先保留條件與畫面回應，不要直接判定資料為空。

## 維運查核補充

本節集中商品加量清單、分批載入、完成／刪除、匯出與通知的技術查核範圍；一般讀者先依前文畫面操作。通知送達、部分刪除與分頁若未 runtime 驗證，以回應、案件與通知紀錄為準。

### API、資料組裝與寫入查核

- 一般清單使用 `GET /api/ProductIncrease/GetProductIncreaseList`，OB 清單使用 `GET /api/ProductIncrease/GetProductIncreaseObList`；兩者都傳入 `saleNo`、`skip`、`take`，空結果回空集合。
- OB 篩選依 `SUBCHANNEL` DomainData 解析 `MultiSaleNo` 前綴；前綴不足兩筆時來源記載可能發生例外，需保留原始回應。
- 每批結果會由 `DataTransform()` 補 applicant 及部、處、組資料；查不到 applicant 時回退原始 mapping 結果。
- 【完成】對應 `POST /api/ProductIncrease/Done`：依 `id` 查案件、以 Fugo Oracle `fugo21.spx_QueryProdAvailableqty` 查可接單量，確認 applicant 後寫入完成者；成功後發布 `NoticeUserIntegrationEvent`。可用量為 0 時來源記載會回失敗訊息。
- 【刪除】對應 `POST /api/ProductIncrease/DeleteIncrease`：先查商品與 applicant，再刪 MariaDB 加量資料，之後查商品明細並通知申請人；後續查詢失敗是否回復刪除未由來源保證。
- 匯出使用 `POST /api/ProductIncrease/DownloadProductIncreaseList` 與 `isSelectOb`；先取得案件、依 `SUBCHANNEL` 篩選、補組織資料並套用 Excel 範本。檔名含時間戳，範本或組裝失敗可能使下載失敗。
