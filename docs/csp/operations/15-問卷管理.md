# 問卷管理

## 用途與入口

問卷管理頁用來查看目前服務會員的待測問卷、回看歷史問卷，以及填寫並送出待測問卷。

- 網站路由：`/Survey`
- 進入方式：從網站的問卷管理功能進入；若網址帶有 `customerId`，頁面會先檢查目前服務會員，必要時要求確認切換後再載入問卷。
- 主要畫面：`待測問卷清單`、`歷史問卷清單`、歷史明細，以及「填寫問卷」側邊視窗。

### 角色視角與操作前提

**現行事實**：本頁以「目前登入員工」與「目前服務會員」作為查詢／送出的上下文。待測清單可使用網址的 `customerId` 查詢；未提供時使用目前服務會員。歷史清單固定使用目前服務會員。文件與目前程式未提供可供本手冊引用的角色權限矩陣，因此不自行推定哪些職稱或群組一定有權限。

**操作前提**：先確認頁面上的目前服務會員是要作答的會員，再開始回答。若尚未選擇會員，待測或歷史清單查詢會收到 `BadRequest`，訊息為「尚未選擇會員，請重新查詢客戶！」；這不是「目前沒有問卷」的空資料狀態。

本頁的敘述狀態如下：`現行事實` 為目前程式或 canonical 文件直接支持的行為；`推論` 為依來源整理出的排查判讀；`runtime 未確認` 為來源有線索但尚未在目前環境實際驗證的行為。

## 一般操作

### 1. 查看待測問卷

1. 進入 `/Survey` 後，預設開啟 `待測問卷清單`。
2. 清單顯示問卷標題與問卷編號；點擊該列的 `回答問卷`。
3. 頁面會載入問卷標題、題目、選項與拒答設定，並在側邊視窗開啟 `填寫問卷`。
4. 若網址帶有不同的 `customerId`，頁面會先查詢該會員並顯示切換確認；確認後重新載入待測清單。切換前先核對會員姓名，避免替錯誤會員作答。

待測清單與歷史清單是兩個獨立分頁，不會在畫面上合併；待測清單為可回答資料，查無列時先視為目前條件下沒有待測資料，不要僅因畫面顯示 `無` 就判定服務故障。

**推論**：若會員上下文正確、請求沒有錯誤回應而清單仍顯示 `無`，較符合「目前條件未命中資料」；仍應以網路回應與資料查詢結果交叉確認。

### 2. 查看歷史問卷

1. 切換到 `歷史問卷清單`；頁面會依目前服務會員重新查詢。
2. 歷史列顯示問卷類型、問卷標題、問卷日期與發問人。
3. 點擊列上的查看按鈕，進入歷史明細。
4. 明細顯示問卷標題、題目、回答結果，以及有值時的題目備註；點擊 `返回` 回到清單。

**現行事實**：歷史明細查不到資料時，後端仍會回傳空標題與空題目清單。這是可顯示的空明細結果，不等同於已確認的服務錯誤；應一併核對目前服務會員與問卷編號。

### 3. 填寫與送出

1. 在 `填寫問卷` 視窗依題目順序作答。題目若有說明文字，先閱讀題目下方的提示。
2. 單選／複選題直接選取選項；問答、日期、時間區間或日期＋時間區間題依欄位輸入。
3. 題目有 `本題拒答` 時，可勾選拒答；也可依問卷設定勾選 `拒絕回答此份問卷`。
4. 需要補充時，在題目下方的 `請輸入備註` 欄位填寫備註。
5. 確認所有目前啟用且未拒答的題目都已有答案或備註後，點擊 `提交問卷`。
6. 成功時會顯示「送出問卷成功」、關閉填答視窗並重新整理待測清單；送出期間按鈕會停用，避免重複點擊。

## 題型代碼與畫面判讀

題型由問卷資料帶入，代碼固定如下；一般操作只需依畫面控制項作答。

| 代碼 | 題型 | 畫面控制與填答方式 |
|---:|---|---|
| `1001` | 單選 | 只能選取一個選項（radio）。 |
| `1002` | 多選／複選 | 可選取多個選項（checkbox）；送出答案時以逗號分隔選項編號。 |
| `1003` | 簡答／問答 | 以文字欄位輸入回答。 |
| `1004` | 日期 | 以日期欄位選取日期。 |
| `1005` | 時間區間 | 分別輸入開始時間與結束時間。 |
| `1006` | 日期＋時間區間 | 依序輸入日期、開始時間與結束時間。 |

## 拒答與跳題

### 整份問卷拒答

若問卷回傳的拒答設定為可顯示，填答視窗標題旁會出現 `拒絕回答此份問卷`。勾選後，題目會視為拒答並停用填答欄位；取消後可重新依題目作答。若該問卷設定為隱藏整份拒答，畫面不顯示此勾選項。

### 單題拒答

題目的 `NoAnswer` 設定為顯示時，題目右側會出現 `本題拒答`。勾選後會清除該題答案，選項與題型輸入會停用；取消後可重新填寫。備註欄位是否同步停用，應以當期畫面實際狀態確認。`NoAnswer` 設定為隱藏時，不應以畫面沒有按鈕推論 API 或權限錯誤。

### 跳題

選項可帶有下一題的目標編號。選取帶跳題設定的選項後，系統會停用並隱藏中間被跳過的題目，直接啟用目標題目；沒有跳題設定時則依序啟用下一題。更換前一題答案時，後續題目的暫存答案會被重設，應重新檢查後續題目再送出。

**現行事實**：送出時跳過的題目會以空答案保存，備註標記為 `此為跳題！`；它們不被視為尚未完成的啟用題目。

## 必填與送出限制

- **現行畫面限制**：提交按鈕在送出中會停用。前端逐題檢查：已拒答的題目直接視為完成；被跳過／未啟用的題目不要求填答；其餘啟用題目必須有 `answerId` 或 `mark`，否則不能送出。這涵蓋「沒有填寫不可直接送出」的目前表單行為。
- **備註必填的來源狀態**：需求索引保留 [43950「問卷新增備註可設定為必填」](../requirements/pages/15-問卷管理.md)，後端 `QuestionOption.Remark` 欄位註解也寫明 `Y` 表示必填。可是目前前端將備註欄位以一般文字區塊呈現，送出檢查只判斷整題的 `answerId` 或 `mark`，沒有在目前可讀程式中看到依選項 `Remark=Y` 的獨立檢查或必填提示。因此「備註設定為必填時必定不能送出」屬於**runtime 未確認**事項；若遇到該設定，應以當期畫面與實際送出結果確認，不要把需求標題當成現行保證。
- **後端基本驗證**：送出資料的會員編號、問卷編號、建立者須大於 0，答案集合不可為空；目前登入員工會覆蓋 request 的建立者欄位。這是維運查核所需的資料條件，不代表畫面會逐項顯示相同驗證訊息。

## 資料來源、合併與寫入副作用

### 查詢資料如何組成

| 畫面資料 | 來源與條件 | 是否寫入 |
|---|---|---|
| 待測問卷 | 目前服務會員（或網址 `customerId`）與目前登入員工共同查詢。 | 否，讀取。 |
| 歷史清單 | 目前服務會員的歷史問卷。 | 否，讀取。 |
| 歷史明細 | 目前服務會員＋問卷編號；回傳題目與回答。問卷標題取查詢結果第一筆的問卷名稱。 | 否，讀取。 |
| 填答題目 | 先取得待測清單中的整份拒答旗標，再取得該問卷的標題、題目與選項，組成填答模型。 | 否，讀取。 |

待測清單與歷史清單使用不同查詢，不以其中一個分頁的空結果補入另一個分頁。填答題目則是「拒答旗標」與「題目／選項」的合併結果；若待測清單找不到指定問卷，目前程式會將整份拒答旗標留空，應回到待測清單與目前會員條件檢查。

### 送出後的寫入與副作用

送出一份問卷會：

1. 以問卷編號、受訪會員編號及每題結果建立暫存答案列。
2. 每題先寫入 `TBX_320` 暫存資料；拒答、跳題、問答題會依不同情況填入答案編號、備註標記與問答標記。
3. 再呼叫既有問卷流程將同一批暫存資料寫入正式問卷結果。

**現行事實**：這是本功能唯一的寫入流程；清單、明細與題目查詢本身不寫入問卷結果。**runtime 未確認**：目前來源沒有證明暫存列逐筆寫入失敗時是否會自動交易回滾；若送出錯誤，不能直接假定整批必然已回滾或必然完整成功，應依序號與後端回應查核。

## 空資料與錯誤排查

依下列順序區分「條件未命中」與「服務故障」：

1. **先確認目前服務會員**：核對會員姓名／客代與作答對象。未選會員時，先回客戶查詢選取會員，再重新進入問卷管理。
2. **再確認是哪個分頁或動作失敗**：待測、歷史、明細、題目與送出是不同請求；一個分頁空白或失敗，不代表整個問卷頁都故障。查看瀏覽器網路回應中的狀態碼、會員編號與問卷編號。
3. **待測或歷史顯示 `無`**：先視為該會員在該查詢條件下沒有資料；若同時有錯誤回應，再依錯誤內容檢查 API、資料來源與登入上下文。
4. **明細為空**：確認目前服務會員仍正確、問卷編號來自歷史列且未被替換；明細查無資料在目前 API 會回空標題／空清單。
5. **題目載入後拒答狀態不符**：確認該問卷仍在待測清單、目前會員未被切換，以及題目資料的拒答設定；查詢題目時拒答旗標先取自待測清單。
6. **送出按鈕不能按**：逐題檢查仍啟用且未拒答的題目；跳過題目不需填答，但可見題目必須有答案或備註。另確認沒有仍在送出中的請求。
7. **送出失敗**：保留前端錯誤提示與網路回應，交由維運依「維運查核補充」檢查暫存寫入是否每筆影響 1 列，以及正式問卷流程的回傳碼；不要只用前端清單是否消失判定資料是否已落地。

## 維運查核補充

以下技術名稱只供查核，不是一般操作步驟。

### API 與資料庫入口

| 動作 | API | 主要資料來源／結果 |
|---|---|---|
| 待測清單 | `GET /api/Survey/QuerySurveyList`；可帶 `customerId` | Oracle `FUGO21.SPX_OB_SURVEY_1`；以會員與員編查詢。 |
| 歷史清單 | `GET /api/Survey/QueryHistoryList` | Oracle `FUGO21.SPX_OB_SURVEY_LIST`；使用目前會員。 |
| 歷史明細 | `GET /api/Survey/QueryDetail?questionnaireId={id}` | Oracle `FUGO21.SPX_OB_SURVEY_RESULT`；以目前會員與問卷編號查詢。 |
| 題目與拒答設定 | `GET /api/Survey/QueryQuestions?questionnaireId={id}` | 先讀 `SPX_OB_SURVEY_1` 取拒答旗標，再讀 `FUGO21.SPX_OB_GET_SURVEYQUESTION` 取標題、題目與選項。 |
| 儲存結果 | `POST /api/Survey/SaveQuestionnaire` | 先取序號、逐題寫 `TBX_320`，再呼叫 `FUGO21.SPX_OB_INS_ITTBQ005` 寫入正式流程。 |

### 儲存映射與失敗邊界

- `Refused=true`：答案編號為空；備註會加上 `本題拒答！`；問答標記也會寫入 `本題拒答！`。
- `QuestionEnable=false`：答案編號為空；備註寫入 `此為跳題！`；問答標記為空。
- `OptionType=1003` 且非拒答／跳題：問答標記為 `這是問答題`；有答案編號時會確保以逗號結尾。
- `CreateTbx320` 每筆寫入若影響列數不是 1，會拋出 `InvalidOperationException`；正式寫入回傳碼不是 `OK` 時會拋出 `CustomerServiceException`。這兩類錯誤都需要保留序號、問卷編號、會員編號與後端回應供查核。
