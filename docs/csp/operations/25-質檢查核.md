# 質檢查核

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP／MI 的質檢查核入口，對應網站路由 `/OrderQACheck`。本頁供質檢流程中的組長、處長、質檢小組與質檢主管依目前指派與權限查核案件；案件建立、查詢報表與完整質檢處理請分別參考相關入口。

## 使用前確認

1. 確認目前登入角色、可查核的審核人／部門範圍，以及案件是否仍指派給自己或目前選定的審核人。
2. 先準備案件識別資料、被檢查專員、質檢類型與目前狀態；需要追查通話時，同時核對 Connection ID。
3. 進入頁面後依審核人篩選待查核案件，從清單開啟明細或 AI 查核視窗。不要只依清單摘要判斷案件結果。

## 查核流程

1. 設定審核人及頁面提供的篩選條件，執行查詢並確認清單與分頁結果。
2. 開啟案件明細，核對專員、質檢內容、目前處理節點、既有歷程與附件。
3. 依查核項目完成判斷；需要補充時，使用質檢內容的 Connection ID、備註或附件欄位。Connection ID 可供後續上訴或音檔追查。
4. 若被懲處對象需由原專員改為組長等其他人員，在質檢小組／質檢主管關卡確認並調整【最終懲處者】；此欄位預設帶入專員名稱，月報與匯出資料會優先使用最終懲處者，空白時才以專員資料判斷。
5. 有需要時上傳佐證圖片。來源需求記載最多 5 張、每張 1000KB 以內，格式為 JPG、JPEG、PNG、GIF 或 BMP；上傳後先確認縮圖與歷程可查看。
6. 送出前再次確認案件指派與目前狀態，完成後回看歷程、處理人與狀態是否更新。

## 備註、附件與重複送出

- 質檢主管關卡有備註欄位，結案後上訴也可輸入備註；上訴再次輸入備註時，來源需求記載會以新備註取代原備註，送出前先確認是否要保留原內容。
- 附件查看受案件與帳號權限限制。看不到附件時先核對角色、案件歸屬與附件是否確實上傳，不要直接判定附件遺失。
- 不要同時開啟同一質檢單的多個視窗進行送出。系統會檢查案件指派與是否已審核；若案件已被審核，應停止重送並保留提示「此質檢單已審過，請勿重複審核」。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 查不到待查核案件 | 審核人、部門範圍、案件狀態、分頁與權限 | 重新確認篩選條件與目前指派；保留查詢時間、帳號與案件識別資料 |
| 明細或附件無法查看 | 案件歸屬、角色、附件格式與上傳結果 | 先確認權限與歷程；若仍異常，附案件 ID、附件欄位與畫面回報 |
| 送出顯示權限不足 | 登入角色、案件指派、質檢類型與處理方式 | 近期案例包含「雙向面談表」；記錄處理方式與錯誤時間，請權限管理者／開發核對 |
| 送出提示已審核 | 是否開啟重複視窗、其他人是否已先送出 | 停止重送，回查案件歷程與目前狀態 |
| 最終懲處者或備註未出現 | 目前關卡、欄位值、是否已儲存、匯出版本 | 先回開明細與歷程確認；不要用專員欄位手動取代正式最終懲處者 |
| 圖片無法上傳或預覽 | 副檔名、檔案大小、張數與格式 | 依限制縮減檔案並重新選取；保存原檔資訊與錯誤提示 |

## 維運查核補充

本節集中查核關卡、附件、備註、送出與權限錯誤的技術查核範圍；一般讀者先依前文畫面完成查核。未 runtime 驗證的 API、寫入與重送行為，不得由按鈕狀態推定成功。
