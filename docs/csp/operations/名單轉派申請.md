# 名單轉派申請

本篇是 CSP／MI 的名單轉派申請入口，對應網站路由 `/OutBoundListTransferApply`。用於建立名單轉派申請、檢查客代資料與附件，並將案件送入既有審核流程。

## 使用前確認

1. 先確認申請人所屬單位、申請原因與目前可用的申請原因。2026-07-01 的需求單記載目前下拉選單暫時只保留「小鳥件」與「緣故件」；若畫面版本不同，以實際顯示為準並記錄版本。
2. 一般由組長協助組內專員申請；組長請假時，他組組長或處長也可代申請，但案件仍依專員所屬處／部進入審核，不要把代申請人當成案件歸屬人。
3. A、B 級會員不得直接提交名單轉派申請。頁面若顯示需發信上呈事業部主管的提示，先依組織流程完成核准，不要以重新整理或改選原因繞過停用的提交按鈕。

## 建立申請

### 欄位與檢查

頁面「轉派申請」分頁可能包含下列欄位；以目前頁面顯示與必填標記為準：

- **申請原因**：依下拉選單選擇原因。
- **申請專員**、**申請客代**：確認申請對象與客代；申請客代應為數字，送出前先執行頁面提供的檢查。
- **介紹客代**：申請原因為「緣故件」時顯示，非必填；執行檢查後確認客代存在及顯示的客戶姓名。
- **專員維運客代**：重疊轉派等情境用來比對目前維運關係，確認客代與客戶姓名沒有對錯。
- **內容說明**：可由參考片語帶入後再修改；內容過長時先縮短，避免資料欄位錯誤。
- **ConnectionId／CSId**：有對應通話或客訴時填入，送出前核對編號；CS 編號後續可連到客訴處理。
- **附加檔案**：依申請原因與頁面提示判斷是否必填。重疊轉派涉及不同維運專員時，應附上二處處長協調同意的截圖或頁面要求的佐證。

### 送出前的規則

1. 申請客代已在其他案件申請中時，提示會帶出申請中的部門／單位；先確認是否為重複操作，不要連續送出相同客代。
2. 重疊轉派會檢查申請客代與原維運客代的客戶 ID。兩者身分證不同或任一客代缺少身分證時，依提示確認客代是否輸入正確並補齊資料；近期需求也修正了「ID 不同卻未提示」的情況。
3. 名單轉派申請與審核會排除虛擬帳號的既有專員判斷；不要把 `obvip` 類虛擬帳號誤當成一般專員而直接判定不可申請。
4. 緣故件的新客／審核判斷以會員等級為準：新會員流程到部長即可完成；新會員以外需到經營規劃處處長。A、B 級另依事業部主管上呈規則處理。
5. 所有欄位、客代檢查與附件確認完成後才按【提交申請】；提交後保留申請單 ID、申請人、客代與時間，後續到[名單轉派查詢](名單轉派查詢.md)確認狀態。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 沒有可選的申請原因或提交按鈕不可用 | 目前部署版本、會員等級、申請原因、必要欄位 | 記錄畫面提示與案件資料；A、B 級依上呈流程處理，不要嘗試繞過前端限制 |
| 顯示客代已申請中 | 提示中的申請單位、客代與申請人 | 先到名單轉派查詢確認既有案件；若確為重複，停止新增 |
| 重疊轉派要求補 ID 或附件 | 兩個客代的身分證、原維運專員、附件欄位 | 核對客代後補資料與協調佐證；仍不符時保留提示文字與申請單 ID |
| 介紹客代查不到姓名 | 客代格式、客戶是否存在、申請原因是否為緣故件 | 重新檢查客代；不要手動填入未被系統確認的姓名 |
| 送出後出現資料過長或驗證錯誤 | 內容說明長度、特殊內容、必填欄位 | 縮短說明並重新確認欄位；保存錯誤時間、畫面與案件資料交維運追查 |
| 代申請後查不到案件 | 申請專員所屬單位、代申請人權限、查詢條件 | 由案件所屬人員或具管理範圍者回查；不要以代申請人的組織範圍覆蓋案件歸屬 |
