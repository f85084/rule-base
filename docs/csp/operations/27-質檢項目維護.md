# 質檢項目維護

本頁對應網站的「質檢項目維護」，用途是維護可供訂單質檢、質檢查核與質檢查詢共用的質檢標準。需求來源只有已結束的 [需求單 27173](../requirements/pages/27-質檢項目維護.md)：描述為「包含維護列表、修改及新增頁面」。

## 入口與權限

- 網站路由：`/OrderQAStandard`；選單位置可核對 [website-menus.json](../../../data/sources/csp/website-menus.json) 的 `id: 96`。
- 進入頁面或按重新整理會呼叫 `POST api/OrderQAStandard/QueryAll?isRefresh={true|false}`。清單頁以此結果顯示質檢項目。
- 頁面提供新增、編輯與快取更新；未在來源中看到刪除、排序、批次匯入或啟停功能，勿以其他質檢頁面的功能推定本頁具備這些操作。
- `QueryAll` 受指定功能權限的 `CustomAuthorize` 保護；log-map 對查詢／新增／更新的摘要均記為登入後可用，但實際能否看到或修改仍以帳號角色的功能權限為準。

## 查詢與維護流程

1. 進入 `/OrderQAStandard`，先以 `QueryAll` 讀取清單；`isRefresh=true` 會先清除 `RedisConfig.CacheKey.OrderQa.Standards`，再以 MariaDB 的 `usp_orderqaStandard_getall` 重建快取。一般查詢優先讀快取。
2. 新增時在編輯視窗填寫質檢項目，呼叫 `POST api/OrderQAStandard/Create`。後端先處理 `Title`、`Describe` 的 HTML Encode，再通過 validator，最後執行 `usp_orderqaStandard_create`；成功回傳新建立的 `Id`。
3. 編輯既有列時先依項目 ID 取得資料（`POST api/OrderQAStandard/QueryById`），再呼叫 `POST api/OrderQAStandard/Update`。更新同樣會 HTML Encode，並以 `usp_orderqaStandard_update` 的實際影響筆數判斷成功；儲存後重新 `QueryAll` 取得最新清單。

## 欄位、驗證與狀態

| 欄位／資料 | 可確認規則 |
|---|---|
| `Id`／`standardId` | 查詢與更新的質檢項目識別值；`QueryById` 查不到時回 `NotFound`，訊息為 `質檢項目編號:[{standardId}] 不存在`。 |
| `Title` | 新增、更新前會 HTML Encode；其餘長度或格式限制以後端 validator／畫面實際回應為準，來源未提供固定數值。 |
| `Describe` | 新增、更新前會 HTML Encode；其餘長度或格式限制以後端 validator／畫面實際回應為準。 |
| 建立／修改操作者 | API 摘要記為操作者資訊的一部分；不要以前端可傳值取代登入授權上下文。 |

這頁沒有獨立的啟用／停用狀態 API。可觀察的狀態是「清單存在／查無資料」與新增、更新的成功／失敗結果；不可把 `OrderQA` 案件狀態套用到質檢標準主檔。

## 資料邊界與例外排錯

- MariaDB 預存程序是質檢標準的持久化來源；Redis `RedisConfig.CacheKey.OrderQa.Standards` 是查詢快取。新增或更新後若清單仍是舊資料，先用 `QueryAll` 的 `isRefresh=true` 驗證快取，再查資料庫寫入結果。
- 新增 validator 失敗會直接中止；寫入回傳 `Id=0` 代表新增失敗。更新影響筆數不是 1 時視為失敗。
- `QueryById` 查無資料是明確 `NotFound`，不要當成空白編輯表單繼續送出。
- 本組 endpoint 的 log-map 沒有 NormalLogger 呼叫。追查請保留時間、路由、`standardId`、回應訊息與 trace/tid；依 [MI完整手冊](MI完整手冊.md) 的維運原則記錄異動前後狀態，再到對應 API、MariaDB／Redis 服務查證。
- 需求單的原始快照可由 [issues_all.json](../../../data/sources/csp/redmine/issues_all.json) 的 `id: 27173` 核對；本頁不延伸解讀需求描述未提到的流程。
