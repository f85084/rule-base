# 行事曆

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP／MI 的行事曆瀏覽入口，對應網站路由 `/Calendar`。本頁供使用者查看自己可見的課程、名單、直播、活動、商品與維運等事項；不包含新增、刪除或標籤維護。

## 權限與進入方式

1. 登入 MI 後點右上角行事曆 icon；若畫面寬度較窄，右側工具列可能收合為下拉選單。
2. 一般專員只能看到自己單位的行事曆項目。若需要確認其他單位的活動，請使用具相應管理範圍的帳號或請管理職協助，不要把空白結果當成全站沒有活動。
3. 行事曆管理是另一個頁面 `/Meeting`，只有管理權限可進行活動維護；本頁只負責瀏覽。

## 查看行事曆

- 依目前頁面提供的模式切換月／列表；既有手冊另記載週檢視，若目前版本顯示週模式可用，依畫面切換即可。模式差異以實際部署版本為準。
- 登入時若隔日有課程、活動或直播等事項，行事曆 icon 會顯示紅點。點開行事曆後紅點會消失；重新登入時可能再次出現。
- 週六、週日及人事行政局公告的國定假日以灰底顯示，假日文字為紅色；其他活動通常以藍色文字、黑色 icon 顯示。
- 同一天多筆事項通常先依時間，再依類別排序：課程、名單、直播、活動、商品、維運、其他。
- 活動名稱太長時，格內會顯示 `...`；將游標移到活動上可查看完整標題與活動時間。
- 活動若有設定網址，點選活動名稱會另開頁籤。另開前先確認網址與活動內容相符，避免把外部連結誤當成 MI 功能頁。
- 在可查看全 OB 行事曆的情境，同日期同時間但不同部門的課程可能合併為一筆，並合併顯示相關部門。

## 補班、日期與資料判讀

- 既有手冊記載補班日目前可能需要另外建立活動補上；需求單另有依工作日管理判斷的調整。若補班日沒有出現在畫面，先確認工作日設定、管理行事曆是否已有對應活動及目前版本，不要直接修改行事曆瀏覽資料。
- 管理行事曆與個人行事曆曾有結束時間落在當日 00:00／23:59 的差異案例。遇到跨日或整日活動少一天、少一筆，記錄活動名稱、起迄時間、顯示模式與時區，再交維運比對。
- 列表沒有資料時，先確認月份／日期、帳號可見單位、事件是否已過期及是否有篩選條件；不要只依畫面上的 `No events to display` 判定資料遺失。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 看不到其他單位活動 | 登入帳號、所屬單位、目前是否為個人行事曆 | 請具管理範圍者使用全 OB 行事曆確認；不要要求一般專員自行修改權限 |
| 紅點沒有出現或點開後又出現 | 是否有隔日活動、是否已點開、登入時間 | 先重新開啟行事曆並記錄登入／點擊時間；紅點不是活動清單本身 |
| 活動顯示日期或時間不一致 | 起迄時間、整日活動、月／列表模式、時區 | 保存兩個頁面的畫面與活動資訊，交維運比對管理行事曆資料 |
| 補班日沒有特殊顯示 | 工作日管理設定、是否建立補班活動、版本 | 先依現行流程確認或請管理職補建活動；不要把需求單中的預期功能當成目前一定已啟用 |
| 活動標題被截斷或網址無法開啟 | 游標提示、活動明細、網址是否存在 | 以提示或明細確認完整標題；若網址錯誤，記錄活動與實際網址交管理者修正 |

## 維運查核補充

本節集中個人／全 OB 合併、日期、補班與查詢異常的技術查核範圍；一般讀者先依前文行事曆畫面操作。權限、同步與日期計算若未 runtime 驗證，以當期 UI 與回應為準。
