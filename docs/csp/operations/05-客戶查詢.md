# 客戶查詢

## 1. 用途、入口與權限視角

本頁用來依客戶識別資料找到會員，核對目前服務客戶，並進入訂單、聯繫歷史、問卷及客戶儀表板等後續作業。現行前端 route 為 `/CustomerService`；從 TM 名單點選客代也會帶入查詢條件。

一般專員可依帳號可見範圍查詢並選取客戶；管理職或具備額外功能權限者，才會看到相應的管理、調聽或資料異動入口。需求單有「調整專員〈客戶查詢〉權限」紀錄，但沒有在本文件可引用的完整權限矩陣，因此各按鈕仍以當期 UI 與登入權限為準（**runtime 未確認**）。

## 2. 正常查詢流程

1. 開啟 `/CustomerService`，或從 TM 名單、通知連結帶入客代。
2. 輸入一個或多個查詢條件：客代、姓名、手機、生日、會員等級、OB 會員等級或郵遞區號；也可依目前畫面提供的身分證字號／E-mail 查詢。
3. 點選【查詢】，先確認結果的客代、姓名、電話、地址、會員等級與維運專員，再點選目標客戶。
4. 若選取的客戶不是目前服務客戶，依畫面確認是否切換；切換完成後再進行接單、聯繫、客訴或資料異動。
5. 進入客戶相關功能前，確認頁面上的目前客代沒有被另一個分頁或通話流程改變。

## 3. 條件與結果判讀

- 不要把同一支電話對應的多筆會員資料視為同一客戶；以客代作為主要識別鍵，再核對姓名與其他資料。
- 搜尋條件中的空白應先移除；需求單 48161 明確要求客戶查詢搜尋條件濾掉空白。欄位格式與輸入驗證以當期表單提示為準。
- 客戶清單可提供進入問卷管理、活動管理或其他後續功能的按鈕；按鈕不顯示時，先確認帳號權限與是否已選取目前服務客戶。
- 搜尋結果為空只表示本次條件未命中或資料不在目前帳號範圍，不能直接推論會員不存在。

## 4. 客戶資訊與資料合併

選取客戶後，畫面可能載入下列資料；所有分頁與卡片都以客代作為合併鍵，不應以姓名或電話合併：

| 區塊 | 判讀方式 |
|---|---|
| 訂單清單 | 查看消費與訂單紀錄，另依訂單頁的狀態判讀銷退或配送。 |
| 外撥交談註記／聯繫歷史 | 查看聯絡內容與時間；需要完整歷史時改走[聯繫歷史](12-聯繫歷史.md)。 |
| 消費者輪廓 SCV | 查看累計及期間消費、通常進線時間等摘要；摘要與訂單明細不是同一資料集。 |
| 客戶備註 | 查看方便聯繫時間、特殊飲食等常態資訊；不要把工作備註寫成病史、政治或個人負面評語。 |
| 360 畫像／人物誌 | 查看消費、偏好、標籤與摘要；若單一卡片失敗，先視為該區塊資料失敗。 |
| 問卷 | 查看尚未完成的問卷，問卷作業請改看[問卷管理](15-問卷管理.md)。 |

**現行事實**：目前前端先以 `GetCustomers` 查詢清單，再以選取客代建立目前服務客戶，儀表板另由 `QueryCustomerDashboardInfo` 取得。這些請求不是單一資料集的原子交易，清單成功而儀表板空白時，應分開排查。

## 5. 寫入與副作用

- 查詢本身是唯讀操作。
- 點選客戶會更新「目前服務客戶」上下文，這不是會員資料異動；切換時可能觸發提醒或要求確認。
- 後續從本頁進入接單、客訴、問卷或會員明細後，才依各頁按鈕執行寫入。不要因為查詢結果已顯示就假設後續資料已儲存。

## 6. 空資料、部分失敗與錯誤排查

| 現象 | 先檢查 | 判讀與處理 |
|---|---|---|
| 完全無法開頁或所有功能都失敗 | 登入狀態、主頁載入與網路回應 | 視為頁面或共用服務問題，保留時間與畫面訊息。 |
| 查詢結果為空 | 客代格式、空白、條件組合、帳號資料範圍 | 先用單一明確條件重查；仍無資料再回報條件與客代。 |
| 清單有資料但儀表板／某一卡片空白 | 該區塊的載入狀態與錯誤訊息 | 視為單一資料請求或尚未同步，不要清除或重建會員資料。 |
| 選客戶時提示目前客戶已變更 | 目前服務客代、其他分頁／通話是否剛切換 | 重新核對客代後再確認切換；避免在錯誤客代上接單或寫備註。 |
| 按鈕不見或無法操作 | 登入者角色、功能權限、是否已有目前服務客戶 | 以當期授權矩陣與 UI 為準，不能以其他帳號畫面推論權限。 |
