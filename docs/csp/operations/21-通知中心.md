# 通知中心

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本頁給專員、管理職與維運人員查看 MI 系統通知，並回到原功能處理待辦使用。網站路由為 `/Notifications`；右上角小鈴鐺是快速入口，完整通知列表由本頁說明。

## 1. 查看通知

1. 從右上角小鈴鐺開啟通知，或進入【通知中心】。
2. 先確認通知時間、通知來源與對應功能。
3. 點選通知後，確認是否已讀，以及是否需要回到原功能完成處理。
4. 若通知只清除小鈴鐺顯示但沒有自動跳轉，從功能選單自行開啟對應頁面。

小鈴鐺的顯示是提醒入口，不代表對應案件已完成；清除通知後仍要確認原案件的狀態、待辦與歷程。

## 2. 常見通知來源

| 通知來源 | 收到通知後要做什麼 |
|---|---|
| 電話小結 | 開啟[電話小結作業](13-電話小結作業.md)，確認通話結果並完成小結。 |
| 指定回電 | 核對客代、期限與聯繫內容，完成外撥或待辦結案。 |
| 客訴未結 | 開啟[客訴處理](09-客訴處理.md)，確認客訴主因、指定對象與目前處理狀態。 |
| 新名單／名單轉派 | 開啟[TM 名單推薦](04-TM名單推薦.md)或名單轉派功能，確認新分派資料。 |
| 簡訊審核 | 管理職或代理人進入簡訊審核，依客代、申請人與內容完成審核。 |
| 訂單質檢／質檢查核 | 開啟[質檢查詢](26-質檢查詢.md)或[訂單質檢](24-訂單質檢.md)，確認案件與下一個流程節點。 |
| 行事曆 | 開啟行事曆查看隔日課程、活動、直播或維運項目。 |
| 軟體電話 | 先確認 CTI／軟體電話狀態，再依[軟體電話](軟體電話.md)排查。 |
| 訊息／即時推送 | 回到[訊息查詢](20-訊息查詢.md)確認訊息內容、狀態與是否需要重送。 |

不同帳號與角色看到的通知可能不同；收不到預期通知時，先確認案件是否屬於目前帳號的部門與權限範圍。

## 3. 待辦處理原則

1. 先記錄通知來源、時間、客代／案件編號與通知文字。
2. 點入原功能確認實際資料，不要只依通知摘要判斷。
3. 完成處理後，回查原功能的狀態、歷程或待辦是否已更新。
4. 若通知內容與原功能不一致，保留兩邊畫面與發生時間，提供後續排查。

通知可能因同類事件合併、已讀狀態或批次寫入而與實際案件數不同；需要確認完整案件時，以原功能查詢結果為準。

## 4. 常見異常

| 現象 | 先確認 |
|---|---|
| 小鈴鐺沒有通知 | 案件是否已讀、帳號權限、部門範圍與通知來源功能是否已產生事件。 |
| 點通知沒有跳轉 | 直接開啟對應功能頁，依通知來源查詢案件。 |
| 點擊後通知消失但待辦仍在 | 這是顯示狀態與案件狀態分開，回原功能完成待辦即可。 |
| 通知位置被遮住 | 確認頁面版面、Slider／視窗狀態與瀏覽器縮放，記錄畫面位置。 |
| 通知延遲或一次出現多筆 | 記錄事件時間、通知類型與帳號，確認是否為批次寫入或即時推送延遲。 |

## 維運查核補充

本節集中通知合併、已讀、原功能導頁與即時／批次推送的技術查核範圍；一般讀者先回到原功能確認案件。通知延遲、合併與同步若未 runtime 驗證，不得由小鈴鐺狀態推定案件已完成。
