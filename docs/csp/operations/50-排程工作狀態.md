# 排程工作狀態

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP `/JobStatus` 排程工作狀態查詢入口。頁面只讀取 `schedule_task` 的任務資料與分頁結果，不會啟動、停止、重跑或修改排程；實際 CSP JOB 名稱與環境部署另依 CSP 排程清單核對。

## 1. 權限與資料邊界

- 登入後可查詢排程工作狀態；實際資料可見範圍以目前帳號、環境與頁面權限為準。
- `JobStatus` 查的是資料表中的排程任務紀錄，不等於 Windows Task Scheduler、容器 process 或外部 JOB 主機的即時健康狀態。
- 此頁沒有維護 API；要處理排程啟停、部署或重跑，需依受控部署／JOB 維運流程，不要在頁面重複送出查詢當成控制操作。

## 2. 查詢流程

1. 開啟 `/JobStatus`，確認目前環境與要追查的時間區間。
2. 設定 `startTime`、`endTime`、`page`、`pageSize`，呼叫 `GET api/JobStatus/QueryScheduleTaskList`。
3. 依 `StartTime` 遞減查看任務，核對 TaskId、Name、Status、Description、ScheduleData、ScheduleType、StartTime、EndTime、CreatedDate、RunServer。
4. 若只輸入日期，後端會將 `endTime` 展開至當日最後一毫秒，避免漏掉當天任務。
5. 翻頁時保留同一時間條件；`page <= 1` 會從 offset 0 開始。

## 維運查核補充

以下欄位、DTO 與 API 對照只供維運查核；一般讀者先依前文完成唯讀查詢，勿把查核資訊當成排程控制入口。

| 欄位／操作 | 規則／維運重點 |
|---|---|
| `startTime` | 篩選任務 `StartTime` 的下界；為 null 時不限制。 |
| `endTime` | 篩選任務 `StartTime` 的上界；repository 會展開到當日最後一毫秒，為 null 時不限制。 |
| `page`／`pageSize` | 查詢分頁；`page <= 1` 時 offset 為 0。 |
| `TaskId`、`Name` | 辨識排程任務；與 CSP 排程清單名稱對照時保留原始值。 |
| `Status`／`StatusDesc` | 任務狀態及 DTO 衍生顯示欄位；頁面不會替任務變更狀態。 |
| `ScheduleData`、`ScheduleType` | 顯示排程設定資料；不要由欄位自行推測實際觸發器是否仍在執行。 |
| `RunServer` | 辨識任務執行主機／服務欄位，供排錯交叉比對。 |
| API | `GET api/JobStatus/QueryScheduleTaskList`；只讀 `schedule_task`，回傳清單與總筆數。 |

## 4. CSP 排程清單對照

依 CSP 排程清單，已列出的排程與環境／備註如下；這是部署與功能對照資料，不是 `/JobStatus` API 的即時控制清單。

| 排程名稱 | 功能／資料邊界 | LAB | TEST | STG | PROD／備註 |
|---|---|---|---|---|---|
| `RefreshOutBoundStatus` | 更新 OB 人員狀態；保留最新時戳於快取並透過 SignalR 發送 | ✅ | ❌ | ❌ | ✅ |
| `PushMessage` | 訊息通知同步 | ✅ | ❌ | ❌ | ✅ |
| `SyncTmList` | 同步 TM 推薦名單，可能新增指定回電／客訴未結通知 | ✅ | ❌ | ❌ | 預計 2026-02-04 03:00 部署，持續執行 |
| `SendBookingMessage` | 發送預約訊息；每小時觸發，新舊不可同時運作 | ✅ | ❌ | ❌ | 預計 2026-02-04 03:00 部署 |
| `ReCallAttention` | 預約外撥通知，使用 SignalR；新舊不可同時運作 | ✅ | ❌ | ❌ | 預計 2026-02-04 03:00 部署，持續執行 |

對照時先以 `Name`、`RunServer`、時間與環境確認，再查排程清單；不要僅因頁面出現一筆 `Status` 就宣稱對應 JOB 已部署或正在執行。

## 5. 異常處理與排錯

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 查無任務 | 環境、時間區間、StartTime 邊界、分頁 | 重新查詢並保留條件；空集合不代表 JOB 從未存在。 |
| 狀態長時間未更新 | `StartTime`、`EndTime`、`Status`、`RunServer` 與實際部署／JOB log | 交叉查 CSP 排程清單、JOB log、主機或容器狀態；本頁不能重跑任務。 |
| 查詢失敗 | endpoint、帳號、時間與 MariaDB 錯誤 | Controller 沒有額外 try/catch，保留底層錯誤交系統／資料庫維運。 |
| Oracle 錯誤大量出現 | FATAL 時間、排程名稱、Oracle 錯誤碼 | `ORA-12526`／`ORA-01033`／`ORA-12528` 組合表示 Oracle 初始化／關機狀態；聯絡 DBA／Fugo，不能只依錯誤數量判定 JOB 永久失敗。 |
| SignalR 推播異常 | JOB 執行結果、HTTP／SignalR 路徑、Web 端推播與前端連線 | 依目前架構先分辨 JOB 計算／快取更新與 Web 推播責任，不把頁面查詢結果當成推播成功證據。 |
