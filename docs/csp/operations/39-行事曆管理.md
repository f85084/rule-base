# 行事曆管理

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本篇是 CSP／MI 的行事曆管理入口，對應網站路由 `/Meeting`。本頁供具管理權限的人員查詢、新增、修改、刪除行事曆活動及維護標籤；一般使用者只能查看行事曆。

## 權限與頁面分頁

1. 從【內部工作管理】進入【行事曆管理】。若帳號只有一般權限，通常只能看到行事曆瀏覽功能，不會看到管理分頁。
2. 【全 OB 行事曆】可查看全部活動及處別；【行事曆管理】用於活動清單與新增／修改／刪除。
3. 開始異動前先確認目前環境、帳號管理權限、活動對象與日期範圍。不要以一般使用者看不到活動，推定活動不存在。

## 查詢與列表

行事曆管理列表可核對：

- 序號。
- 類別：課程、名單、直播、活動、商品、維運、其他。
- 活動名稱。
- 時間：依類別顯示；若有起迄時間則顯示起迄。相同活動若有多筆不同處／組別時間，列表可顯示最早至最晚的範圍。
- 操作：編輯、刪除。

活動列表依建立時間新至舊排序。開啟明細時一併確認建立人與建立時間，並檢查活動對象是否為預期部門。

## 新增或修改活動

點選【新增活動】或列表的編輯功能，依頁面欄位處理：

1. **類別**：必填，從課程、名單、直播、活動、商品、維運、其他選擇。
2. **活動名稱**：必填。確認名稱能讓專員在月曆與列表辨識，過長時瀏覽頁可能以 `...` 顯示。
3. **對象**：必填。點【選擇部門】開啟組織圖，勾選部、處、組並設定時間；開始時間必填，結束時間非必填，可設定多筆部門／組別與不同時間。
4. **網址**：非必填。填寫後，使用者點活動名稱會另開頁籤前往該網址，儲存前先核對網址內容與活動用途。
5. **標籤**：可複選，最多選 3 個，每個標籤最多 5 字。標籤是辨識用途，不取代原有活動類別。
6. 儲存後回到列表與全 OB 行事曆，確認活動名稱、日期、對象、標籤及網址顯示正確；開啟明細時也要確認建立人、建立時間與排序沒有造成誤判。

## 標籤管理

標籤管理僅限管理權限：

1. 在【行事曆管理】點【標籤管理】。
2. 點【新增標籤】，輸入不超過 5 字的名稱；點【儲存】建立，點【取消】放棄。
3. 現有標籤可點【修改】調整名稱，或點【停用】使其不再出現在新增活動的選項中。
4. 已停用但曾被活動使用的標籤，仍會顯示在既有活動中；不要為了移除歷史顯示而刪除活動資料。

## 日期、顯示與補班判讀

- 同一天多筆活動先依時間，再依類別排序：課程、名單、直播、活動、商品、維運、其他。
- 相同日期時間但不同部門的課程，在全 OB 行事曆可能合併成一筆並合併顯示部門。
- 假日與補班顯示受行事曆／工作日資料與版本影響。既有手冊記載補班日可能需要另外建立活動；若需求預期的工作日顯示與現場不一致，先核對工作日設定及是否已建活動，不要直接改瀏覽頁資料。
- 個人行事曆與管理行事曆曾有整日活動結束時間為當日 00:00／23:59 的差異。遇到少一天、少一筆或跨日顯示異常，記錄活動起迄時間、模式與時區供比對。

## 刪除與異常處理

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 看不到行事曆管理 | 帳號角色、管理權限、目前入口 | 請權限管理者確認；一般權限只應瀏覽，不要以其他帳號代改資料 |
| 月份切換超出範圍或出現負數 | 目前月份、上下月按鈕、頁面版本 | 記錄月份與操作後畫面，回報行事曆管理調整問題 |
| 當月沒有活動顯示英文提示 | 日期範圍、對象部門、是否真的沒有活動 | 先確認全 OB 行事曆與管理列表，再記錄 `No events to display` 畫面 |
| 活動沒有出現在使用者行事曆 | 對象部門、起迄時間、活動狀態與工作日 | 以管理頁明細核對，不要直接重複新增；必要時請管理者修正 |
| 標籤停用後仍在舊活動 | 該標籤是否曾被使用 | 這是既有規則；只確認新活動選單不再出現即可 |
| 刪除前後資料不一致 | 活動對象、建立人、建立時間、列表排序 | 保留活動名稱、時間、畫面與帳號，交維運追查，不要連續重複刪除 |

## 維運查核補充

本節集中活動、標籤、日期、補班與寫入副作用的技術查核範圍；一般讀者先依前文表單操作。交易、刪除與同步若未 runtime 驗證，不得由畫面更新推定已完整完成。
