# 小m文件管理

本篇是 CSP `/DocumentQA` 小m文件與 FAQ 維護入口。文件主檔與段落在 MySQL，實體檔案落在檔案系統，段落向量同步至 Qdrant；操作成功必須分別確認各資料邊界，不能只看到主檔就視為向量與檔案都完成。

## 1. 權限與資料邊界

- 查詢、文件維護與 FAQ／標籤操作依目前帳號的文件維護權限；全量 Qdrant 匯入明確限制 Admin，實際按鈕以目前環境為準。
- 文件資料包含 MySQL 文件主檔、`ai_doc_paragraph` 段落、檔案系統附件與 Qdrant 向量四段流程。
- 文件更新會先刪除舊匯入段落，再新增新段落並同步 Qdrant；任何一步失敗都可能使整體操作失敗。
- 文件刪除先清 Qdrant 再刪 MySQL 主檔；Qdrant 清理失敗時不要自行刪主檔或附件。

## 2. 查詢與上傳限制

1. 開啟 `/DocumentQA`，先呼叫 `GET api/DocumentQa/QueryInitData` 取得目前 token、允許副檔名與檔案大小限制；限制來自設定，缺設定時會回預設值。
2. 使用 `POST api/DocumentQa/QueryDocuments` 依文件名稱查詢清單；查無資料時回空集合。
3. 使用 `GET api/DocumentQa/QueryDocTags` 載入標籤，確認目標標籤未被其他文件使用。
4. 下載既有附件時使用 `POST api/DocumentQa/DownloadFile`，先確認 DB 文件存在，再確認檔案系統檔案存在。

## 3. 新增／更新文件

1. 準備文件描述、標籤、使用者識別與附件；`Description` 不可超過 1000 字，`TagId`、`UserId` 必須大於 0，檔案不可為空。
2. 先依 `QueryInitData` 的設定確認副檔名、檔案大小與 embedding token 限制，不要自行猜測上限。
3. 使用 `POST api/DocumentQa/CreateOrUpdateDocument` 儲存。後端會驗證檔案、檢查標籤唯一性，建立／更新 MySQL 主檔、重建段落、同步 Qdrant 並寫入檔案系統。
4. 更新文件時確認舊文件 ID；後端會先刪除舊 `Import` 段落，再批次新增新段落。
5. 成功後重新查詢文件、下載附件，並在具權限條件下確認 Qdrant 同步結果；不要只依 API 成功訊息判斷四段資料皆可用。

## 4. 刪除與 Qdrant 全量匯入

### 文件刪除

1. 確認文件 ID、名稱、標籤與受影響問答範圍。
2. 使用 `POST api/DocumentQa/DeleteDocument`；流程先清除該文件的 Qdrant `Import` points，再刪除 MySQL 文件主檔。
3. 若 Qdrant 清除失敗，保留文件 ID、錯誤與時間，不要直接重複刪除主檔。

### 全量匯入 Qdrant

1. 只由 Admin 執行 `POST api/DocumentQa/BatchImportDocumentParagraphToQdrant`。
2. 此 API 先讀取全部文件，再逐份讀取段落，最後全量重建 Qdrant 集合；不是單份文件的增量修復。
3. 執行前確認目前文件與段落資料已完整，並記錄開始時間；大量資料會累積到記憶體，執行中不要同時進行不必要的文件批次異動。
4. 完成後以小m問答或受控查詢驗證向量索引，但不要把 Qdrant 有資料推論成文件附件一定存在。

## 5. 標籤與 FAQ 維護

- 標籤新增 `POST api/DocumentQa/CreateDocTag`：`TagName` 必填、最長 50 字，需 Admin；排序由服務端依現有最大排序計算。
- 標籤修改 `POST api/DocumentQa/UpdateDocTag`：`Id > 0`、名稱必填且最長 50 字；只改名稱，不改排序。
- 標籤排序 `POST api/DocumentQa/UpdateDocTagSort`：`Items` 不可空，每項 `Id > 0`、`Sort >= 0`，是批次更新。
- 刪除標籤 `POST api/DocumentQa/DeleteDocTag`：`Id > 0`；仍有文件綁定時會拒絕，成功時同一交易也刪除該標籤 FAQ。
- FAQ 新增 `POST api/DocumentQa/CreateFaq`：`TagId > 0`、`Question` 必填且最長 300 字；標籤不存在或同標籤 FAQ／啟用數量達設定上限時拒絕。
- FAQ 修改 `POST api/DocumentQa/UpdateFaq`：`Id > 0`、問題必填且最長 300 字，只改問題內容。
- FAQ 啟停 `POST api/DocumentQa/UpdateFaqStatus`：`Id > 0`；啟用時會檢查同標籤啟用上限。
- FAQ 查詢 `GET api/DocumentQa/QueryFaqList?tagId=...`：`tagId <= 0` 直接回參數驗證失敗，結果依 `Sort` 排序。
- FAQ 刪除／排序分別使用 `POST api/DocumentQa/DeleteFaq`、`POST api/DocumentQa/UpdateFaqSort`；排序項目不可空且每項 `Id > 0`、`Sort >= 0`。

## 6. 異常處理與排錯

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 上傳被拒絕 | 檔案是否存在、設定中的副檔名／大小／token 限制、描述、TagId、UserId | 依 `QueryInitData` 與驗證訊息修正；不要猜測或繞過限制。 |
| `TagHaveBeenUsed` | 目標標籤是否已綁其他文件 | 改用未使用標籤或先依文件關聯處理，不要硬覆蓋。 |
| 文件可查但下載失敗 | 文件主檔、文件名稱副檔名、檔案系統路徑 | `NotFound` 時分辨「查無文件」與「文件檔案不存在」，分別記錄 ID。 |
| 文件更新後問答結果舊 | 段落刪除／新增、Qdrant 同步狀態與文件 ID | 先確認 MySQL 段落與 Qdrant；不要直接重建全部集合，除非具 Admin 且已評估全量影響。 |
| Qdrant 全量匯入失敗 | 文件／段落總量、執行者是否 Admin、記憶體與 Qdrant 回應 | 記錄批次開始／結束時間、文件數與錯誤；此 API 是全量重建，不以單份結果推論全部成功。 |
| FAQ／標籤刪除被拒 | Id、文件綁定、FAQ 啟用上限或標籤存在性 | 依錯誤分辨關聯限制與欄位驗證，保留原始訊息。 |
