# 小m文件管理

本篇是 CSP `/DocumentQA` 小m文件與 FAQ 維護入口。文件主檔與段落在 MySQL，實體檔案落在檔案系統，段落向量同步至 Qdrant；操作成功必須分別確認各資料邊界，不能只看到主檔就視為向量與檔案都完成。

## 敘述狀態與查核界線

- **現行事實**：`/DocumentQA` 的文件／FAQ 維護範圍，以及 MySQL 主檔、段落、檔案系統附件與 Qdrant 向量的資料邊界，依現有頁面與來源整理。
- **歷史規則**：需求或手冊中的檔案限制、Admin 條件與向量匯入描述，只代表來源文件曾如此記載；設定值或部署版本不同時不能當成現行保證。
- **推論**：由主檔、附件、段落與向量分段查核所作的部分成功／失敗判讀，是排錯推論；不能由單一 API 成功訊息推定四段資料全部完成。
- **runtime 未確認**：目前帳號權限、設定預設值、檔案與 Qdrant 實際同步、部分失敗補救及 FAQ／標籤限制未在本次環境驗證；以當期 UI、回應、設定與 log 為準。

## 1. 權限與資料邊界

- 查詢、文件維護與 FAQ／標籤操作依目前帳號的文件維護權限；全量 Qdrant 匯入明確限制 Admin，實際按鈕以目前環境為準。
- 文件資料包含文件主檔、段落、檔案附件與向量索引四段流程。
- 文件更新會先處理舊段落，再新增新段落並同步向量索引；任何一步失敗都可能使整體操作失敗。
- 文件刪除會先清理向量索引，再刪除文件主檔；清理失敗時不要自行刪主檔或附件。

## 2. 查詢與上傳限制

1. 開啟 `/DocumentQA`，先查看畫面提供的 token、允許副檔名與檔案大小限制；限制來自設定，缺設定時的預設值仍以當期畫面為準。
2. 依文件名稱查詢清單；查無資料時先視為目前條件沒有符合文件。
3. 載入標籤，確認目標標籤未被其他文件使用。
4. 下載既有附件前，先確認文件主檔與附件都存在；查不到任一邊時分開記錄。

## 3. 新增／更新文件

1. 準備文件描述、標籤、使用者識別與附件；依畫面提示確認描述長度、識別值與檔案不可為空。
2. 依查詢初始化時顯示的設定確認副檔名、檔案大小與文字／向量限制，不要自行猜測上限。
3. 在表單按【儲存】；系統會驗證檔案與標籤，建立／更新文件、段落、附件與向量索引。
4. 更新文件時確認選到舊文件；完成後重新查詢、下載附件，並在具權限條件下確認向量索引，不要只看成功提示。

## 4. 刪除與向量索引匯入

### 文件刪除

1. 確認文件 ID、名稱、標籤與受影響問答範圍。
2. 按【刪除】；系統會先清理該文件的向量索引，再刪除文件主檔。
3. 若向量索引清理失敗，保留文件 ID、錯誤與時間，不要直接重複刪除主檔。

### 全量匯入 Qdrant

1. 只由 Admin 執行畫面提供的【全量匯入】。
2. 此操作會先讀取全部文件，再逐份讀取段落，最後全量重建向量集合；不是單份文件的增量修復。
3. 執行前確認目前文件與段落資料已完整，並記錄開始時間；大量資料會累積到記憶體，執行中不要同時進行不必要的文件批次異動。
4. 完成後以小m問答或受控查詢驗證向量索引，但不要把向量索引有資料推論成文件附件一定存在。

## 5. 標籤與 FAQ 維護

- 新增、修改、排序與刪除標籤都要依畫面提示確認名稱、識別值、排序與文件關聯；仍有文件使用的標籤不可直接刪除。
- FAQ 新增、修改、啟停、查詢、刪除與排序都要依畫面提示確認標籤、問題內容、識別值與啟用數量上限。
- 標籤與 FAQ 的排序是批次異動；送出前確認清單完整，失敗後先回查，不要重複送出。

## 6. 異常處理與排錯

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 上傳被拒絕 | 檔案、畫面顯示的副檔名／大小／文字限制、描述與標籤 | 依畫面驗證訊息修正；不要猜測或繞過限制。 |
| 標籤正在使用 | 目標標籤是否已綁其他文件 | 改用未使用標籤或先依文件關聯處理，不要硬覆蓋。 |
| 文件可查但下載失敗 | 文件主檔、文件名稱／副檔名與附件 | 分辨「查無文件」與「附件不存在」，分別記錄文件 ID。 |
| 文件更新後問答結果舊 | 段落、向量索引與文件 ID | 先分段確認文件與索引；不要直接重建全部集合，除非具 Admin 且已評估全量影響。 |
| 全量匯入失敗 | 文件／段落總量、執行者、記憶體與畫面回應 | 記錄批次開始／結束時間、文件數與錯誤；不要以單份結果推論全部成功。 |
| FAQ／標籤刪除被拒 | 識別值、文件關聯、啟用上限或標籤存在性 | 依錯誤分辨關聯限制與欄位驗證，保留原始訊息。 |

## 維運查核補充

本節集中 API、資料庫、檔案系統、Qdrant 與批次匯入的查核資訊；一般操作先依前文畫面步驟。尚未由 runtime 確認的設定、權限、向量同步與部分成功行為，不得寫成保證。

### 文件與附件查核

- 初始化入口為 `GET api/DocumentQa/QueryInitData`，提供 token、允許副檔名與檔案大小限制；缺設定時會回預設值。
- 文件清單、標籤與附件查核入口分別為 `POST api/DocumentQa/QueryDocuments`、`GET api/DocumentQa/QueryDocTags`、`POST api/DocumentQa/DownloadFile`。
- `POST api/DocumentQa/CreateOrUpdateDocument` 會驗證檔案與標籤，建立／更新 MySQL 主檔、重建 `ai_doc_paragraph` 段落、同步 Qdrant 並寫入檔案系統；更新先刪舊 `Import` 段落。
- `POST api/DocumentQa/DeleteDocument` 先清該文件的 Qdrant `Import` points，再刪 MySQL 主檔；Qdrant 清理失敗時保留文件 ID、錯誤與時間。
- `POST api/DocumentQa/BatchImportDocumentParagraphToQdrant` 讀取全部文件與段落後全量重建 Qdrant 集合，不是單份增量修復。

### 標籤、FAQ 與限制查核

- 標籤入口為 `CreateDocTag`、`UpdateDocTag`、`UpdateDocTagSort`、`DeleteDocTag`；FAQ 入口為 `CreateFaq`、`UpdateFaq`、`UpdateFaqStatus`、`QueryFaqList`、`DeleteFaq`、`UpdateFaqSort`。
- 來源可確認的驗證包括 `TagName` 最長 50 字、FAQ `Question` 最長 300 字、識別值大於 0、排序項目不可空且 `Sort >= 0`，以及標籤關聯／啟用數量上限；實際設定與授權仍以 runtime 為準。
