# 名單小組管理

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本頁對應 `/OutBoundListManagement`，目前不是通用的外呼名單管理，而是單一「沉澱客戶」流程：先用客代檢查資格，再提交回收。需求盤點為 0 筆需求單，因此以下只記錄既有頁面與來源可證實的行為。

## 入口與權限

- 網站路由：`/OutBoundListManagement`；可由 [website-menus.json](../../../data/sources/csp/website-menus.json) 的 `id: 102` 核對，位於「內部工作管理」。
- 頁面只有「沉澱客戶」分頁，沒有列表、分頁、一般名單編輯或名單小組成員維護功能。不要把「名單小組管理」名稱解讀成 [外呼組別管理](41-外呼組別管理.md) 的同一套功能。
- 登入後可查詢／操作；實際可見性仍由帳號角色與功能權限決定。提交時操作者以目前登入者為準，不接受畫面自行填入的操作者資訊。

## 查詢與回收流程

1. 在「申請客代」輸入客代；空值先依畫面提示修正。
2. 執行資格檢查。系統會先確認客戶存在，再確認目前有「沉澱名單」狀態，並檢查近期歷程的最新狀態；通過後顯示客戶名稱。
3. 只有查到客戶名稱時「提交申請」才可用。送出前再次核對客代與客戶名稱，避免誤回收其他客戶。
4. 成功後頁面會清空客代與客戶名稱，供下一次檢查；若畫面結果不明，先重新檢查，不要重複提交。

## 欄位、驗證與狀態

| 欄位／狀態 | 規則 |
|---|---|
| 客代 | 唯一查詢／提交對象；不可空白。檢查成功後才可提交，且提交仍應使用同一客代。 |
| 客戶名稱 | 由資格檢查結果帶回，僅作畫面確認，不是可由使用者編輯的識別資料。 |
| 沉澱狀態 | 需同時符合系統狀態設定與客戶近期歷程的最新狀態；不是只看客戶是否存在。 |
| 回收結果 | 成功後客戶離開沉澱狀態，進入可再指派狀態；實際下游更新結果以回應與重新檢查為準。 |

此頁沒有本地申請單、審核狀態、名單列表或額外轉派對象欄位；回收是直接的 Fugo 狀態更新，不要臆測有另一個待審流程。

## 資料邊界、例外與排錯

- 查無客代、找不到「沉澱名單」狀態，或最新歷程不是沉澱狀態時，提交會維持不可用；先修正客代或回到資格檢查。
- 回收失敗時沿用服務回應訊息。客戶已不在可回收狀態時，應先回到檢查流程，不要重複提交。
- 排錯保留客代、登入者、時間、畫面回應與追蹤識別資料；先確認狀態設定與最新歷程，再回報維運查核。
- 本頁沒有需求單；若要處理一般外呼組別與成員，請改看 [外呼組別管理](41-外呼組別管理.md)，不要在本頁新增未被來源證實的操作。

## 維運查核補充

本節集中客代資格檢查、回收寫入、操作者覆寫與例外排錯的技術查核範圍；一般讀者先依前文單一客代流程操作。回收結果與下游同步若未 runtime 驗證，以回應與歷程為準。

### API、資料來源與寫入查核

- 資格檢查使用 `GET api/OutBoundListManagement/CheckPrecipitationCustomer?customerId={customerId}`：先查 `fugo21.spx_ob_getcustomerbysearch`，再以 `SPX_GETDOMAININFO` 取得客戶類型與 `ObCallingStatus`，並由 `fugo21.SPX_OB_GETCALLINGLIST_1` 檢查最近 30 筆、頁 1 的歷程；通過後回傳 `customerName`。
- 回收使用 `POST api/OutBoundListManagement/ApplyPrecipitationCustomerForm`，body 至少承載 `customerId`；controller 以登入上下文覆蓋 `CurrentUserId`，並以固定 `ActionType.Recycle` 呼叫 Fugo 的 `fugo21.SPX_OB_AGENT_ASS`。
- 回收 Fugo 回傳碼等於 `1` 才算成功；非 `1` 轉成 `SystemError` 並沿用 Fugo 訊息。查無客代、找不到狀態或最新歷程不符時，來源記載為 `NotFound`／`BadRequest` 類錯誤。
- log-map 沒有 NormalLogger 特徵。排錯保留 `customerId`、兩支 API、登入者、時間、Fugo 回傳碼／訊息與 trace/tid；這些技術名稱保留作為來源證據，未以本次 runtime 實測取代。
