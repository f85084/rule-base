# 訊息查詢

本頁給維運人員查詢歷史訊息、確認訊息狀態與處理訊息重送使用。網站路由為 `/Message`；右上角通知用途請看[訊息查詢與通知中心](訊息查詢與通知中心.md)。

## 1. 查詢訊息

1. 進入【訊息查詢】或「訊息管理 > 歷史訊息查詢」。
2. 先依需求選擇【全部】、【已發送】或【已收件】頁籤。
3. 預設先載入近期 20 筆；捲動至頁面底部會再載入 20 筆。
4. 需要查找較早訊息時，使用【發送時間】欄位選擇日期，再按【查詢】。
5. 發送時間查詢預設為空白；輸入日期後，會由該日期往前，以新到舊顯示訊息。

同一筆訊息若發送給多位收件人，列表會合併顯示；點開後再確認完整收件人清單。訊息內容支援斷行，查看時不要只依列表摘要判斷。

## 2. 確認訊息內容

查詢結果至少確認：

- 發送時間與訊息狀態。
- 發送人、收件人或收件人清單。
- 訊息文字是否完整、斷行是否正確。
- 是否有附圖或附件提示。
- 若為預約訊息，是否仍在預約清單，或已進入已發送／全部清單。

有附圖的訊息不一定直接顯示圖檔；若畫面顯示附圖提示，點選圖示開啟大圖確認。

## 3. 發送、預約與重送

### 立即或預約發送

1. 發送訊息時確認發送對象、內容與發送時間。
2. 發送時間預設為立即發送；需要延後時選擇預約發送並設定日期與整點時間。
3. 預約訊息會先保留在預約清單；排程完成後才會出現在全部、已發送或已收件頁籤。
4. 預約清單僅管理權限可見；預約者可刪除尚未發送的訊息。
5. 排程發送失敗時，系統會在後續重新發送，最多重試三次。

預約日期可設定至 D+3 天；遇到假日或需要延後發送時，先確認目前環境的行事曆與權限設定。

### 重新發送

需要重送時，先確認原訊息的收件人、內容與失敗狀態，再依權限使用重新發送。重送後回到歷史訊息確認是否產生新的發送紀錄，不要只看畫面提示。

自訂簡訊涉及審核時，先確認審核狀態；一般使用者沒有發送權限時，不應以重新整理或重複點擊方式繞過權限限制。

## 4. 圖片與文字限制

- 圖片格式：jpg、jpeg、png、gif、bmp。
- 目前完整手冊記載單檔上限為 1000KB、每次 1 張；但需求單 [#48233](https://redmine.etzone.net/issues/48233) 的標題記載上限調高至 2000KB，實際環境需依部署版本驗證，不能只依單一文件判斷。
- 圖片可透過檔案選擇或剪貼簿截圖上傳；每次只上傳一張。
- 圖片通知會保留附圖提示，圖檔依來源記載保留 7 日後自動刪除。
- 完整手冊記載訊息文字上限曾調整為 1200 字；不同訊息類型的字數限制仍應依目前畫面與需求單確認。

## 5. 異常處理

| 現象 | 先確認 |
|---|---|
| 查不到歷史訊息 | 日期是否從發送時間查詢、頁籤是否選錯、是否還需要向下捲動載入 |
| 收件人看起來不完整 | 開啟該筆訊息查看合併收件人清單 |
| 圖片無法查看 | 圖片是否仍在保留期限、格式／大小是否符合目前環境限制 |
| 預約訊息未發送 | 預約清單、預約時間、排程狀態與重試次數 |
| 即時訊息斷線或推送造成錯誤 | 先記錄發生時間、帳號與畫面狀態；需求單 #50152 目前為待測試，需依正式處理結果更新文件 |

不要因查詢列表暫時沒有資料就直接判定訊息遺失；先確認日期條件、頁籤、載入狀態與權限。
