# 客服即時狀態

本篇是 CSP／MI 的客服即時狀態操作入口，對應網站路由 `/OutBoundStatus`。用於管理職、主管與代理組長查看各單位客服員目前的電話狀態、工作描述與狀態持續時間。

## 開啟與基本查看

1. 開啟【客服即時狀態】後，頁面依登入者的上層部門帶出預設資料；先確認目前所在部門與子部門範圍。
2. 需要快速跳到客服員列表時，點選頁面錨點，畫面會帶到狀態列表，不影響左側狀態圓餅圖。
3. 狀態列表欄位依序查看客服員、工作描述與狀態；狀態顏色原則為：待機綠色、未待機藍色、通話中紅色。
4. 狀態持續時間切換時若出現負數，應視為資料更新或時間戳異常，正常顯示應從 `00:00:00` 重新計算。

## 圓餅圖篩選

- 狀態圓餅圖是篩選器，不只是提示色彩。點選狀態（例如【通話中】）會只顯示該狀態，再點選相同狀態可恢復顯示全部。
- 左側部門切換後，右側既有的狀態篩選應維持；若客服員狀態發生異動，篩選結果會隨資料更新。
- 若初始圓餅圖沒有資料、部門切換後消失，先確認目前部門、子部門篩選字串與資料更新時間，不要直接判斷為該單位沒有客服員。

## 單位隱藏與排序

### 隱藏單位

1. 點選下方的【單位】按鈕可隱藏該單位，讓職代或主管先排除不需查看的組別。
2. 再點選一次同一單位即可恢復查看；隱藏單位只影響目前畫面，不代表停用該單位或修改人員資料。
3. 代理組長查看代理組別時，若看不到預期狀態，先確認是否誤將該單位隱藏，再確認代理與組織權限。

### 多條件排序

- 在狀態列表上使用 `Shift + 滑鼠左鍵` 可進行多欄位排序，適合先依單位再依狀態或其他欄位檢視。
- 排序只改變目前列表的查看順序；狀態圓餅圖篩選、單位隱藏與即時資料更新仍分別生效。

## 即時更新原則

- 軟體電話狀態變更時，系統會同步更新客服即時狀態；狀態資料不應只依固定輪詢時間判斷。
- 背景排程負責取得差異資料並推播到頁面；頁面以本地時間戳與後端資料比對，時間戳邊界會保留前一秒／含等於的差異，避免漏掉同一秒的更新。
- 若資料沒有差異，不應以空資料誤更新頁面；若排程時間戳異常或過期，需記錄當下時間戳並確認排程是否能繼續執行。
- 2026 年排程已改由內部 Web API 推播，背景 Job 與前端連線可分開發版與重啟；若只有部分使用者未更新，分別檢查 Job、Web API 與瀏覽器連線。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 狀態長時間不變 | 軟體電話狀態、頁面連線、資料更新時間 | 先重新確認電話狀態，再檢查頁面是否收到推播；記錄使用者、單位與發生時間 |
| 圓餅圖與列表筆數不一致 | 部門範圍、狀態篩選、單位隱藏 | 清除或重新套用篩選，確認是否隱藏單位；仍不一致時保留畫面與時間戳 |
| 狀態持續時間顯示負數 | 前後端時間戳、切換狀態時間 | 以 `00:00:00` 為起點確認；回報時附上客服員、狀態切換時間與畫面時間 |
| 代理組長看不到代理組別 | 代理設定、角色、單位是否被隱藏 | 確認代理權限與目前部門，再恢復單位顯示；不要用一般使用者範圍推測代理範圍 |
| 重整後資料消失 | 預設部門、上層組織、後端快取 | 確認登入者上層部門是否正確，並比對排程／快取更新狀態 |
| 只有部分瀏覽器或使用者未更新 | Web API 推播、前端連線、Job | 區分單一瀏覽器連線問題與全體排程問題，記錄發生時間後交由維運追查 |
