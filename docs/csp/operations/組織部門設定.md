# 組織部門設定

本篇是 CSP／MI 的組織部門設定操作入口，對應網站路由 `/Department`。此頁面提供富購 SSG 組織架構、部門層級與主管資料的查看，並作為名單轉派、代理人、質檢與其他部門選擇功能的共同資料來源。

## 組織樹查看

1. 開啟【組織部門設定】後，載入部門組織樹；若頁面採用延遲載入，先等待根節點完成，再展開下層。
2. 部門層級通常為「部 → 處 → 組」，部分組織可能只有「部 → 處」；不可假設每個處一定有組，也不要因缺少組節點判定資料異常。
3. 點選部門可查看該節點的部門類別、部門等級、主管與成員資訊。其他功能使用組織樹時，通常只需要節點 ID、名稱、類型、子節點與狀態等基本資料。
4. 部門清單由後端查詢取得；若第一次進入沒有資料，先確認請求是否完成，再檢查組織資料同步，不要直接重複建立部門。

## 部門資料與權限邊界

- 部門組織設定頁可能顯示部門類別（IB／OB）、部門等級與主管；實際異動權限依目前帳號與頁面按鈕為準。
- 本頁的組織資料不是系統角色或帳號資料。角色權限請回到[系統角色]，帳號／在職狀態請回到[帳號設定]，代理關係請回到[使用者設定]。
- 組織異動會影響名單轉派查詢範圍、審核關卡、代理人選擇、客服即時狀態與質檢報表；異動前應確認是否需要保留案件當下的部處組與主管資訊。
- 已刪除或歷史部門可能仍需出現在質檢月報、案件歷程或舊資料中；報表需要歷史資料時，不要只用目前有效部門過濾。

## 名單轉派與審核驗證

1. 名單轉派申請與審核依申請當下的部門組織判斷，申請人後續轉調不應改寫原申請單位或原審核流程。
2. 正常組織為部 → 處 → 組時，確認審核關卡能依主管關係建立；若組織只有部 → 處，也應能完成核可，不應因缺少組層級卡在流程中。
3. 若組長協助其他組別或代理處長審核，需同時確認代理權限與組織範圍；不可只看目前登入者的直屬部門。
4. 匯出或查詢案件時，若人員曾轉調，優先採用案件建立／申請當下的部門資料，並保留目前部門供追查。

## 其他功能的使用方式

- 代理人設定：選擇代理人時使用組織樹，確認人員在職與所屬部門；詳細流程見[使用者設定](使用者設定.md)。
- 客服即時狀態：依登入者上層部門帶出預設範圍，切換部門時確認子部門與隱藏單位狀態。
- 質檢查詢與報表：部門搜尋可能需要包含已刪除部門，並依案件當下部處組統計；遇到歷史案件消失先檢查資料邊界。
- 公告、行事曆與訊息：使用組織圖選擇發送／顯示對象時，確認勾選的是部、處或組，以及起迄時間與可見範圍。

## 常見異常

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 組織樹空白或只顯示根節點 | 後端請求、登入權限、組織同步時間 | 先確認請求是否完成並重新展開節點；保留帳號、時間與請求結果供追查 |
| 部門沒有組層級導致審核失敗 | 實際組織層級、審核關卡判斷 | 確認是否為合法的部→處結構；若是，應回報審核流程未處理該層級 |
| 代理人或公告選不到人／部門 | 組織樹節點、在職狀態、可選範圍 | 重新查詢組織資料，確認目前帳號可見範圍，不要改用手動輸入繞過權限 |
| 轉調後案件部門錯誤 | 案件建立時間、申請時部門、目前部門 | 以歷史案件資料比對申請當下部門；不要直接以目前組織覆蓋歷史欄位 |
| 質檢歷史報表少了已刪除部門 | 報表資料來源與部門有效狀態 | 確認報表是否要求包含已刪除部門，再依案件當下部門重新查詢 |
| 同一部門在不同功能顯示名稱不一致 | 組織資料版本、節點 ID、快取 | 記錄節點 ID、名稱與功能頁面，交由維運比對共同組織資料來源 |
