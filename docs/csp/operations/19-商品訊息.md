# 商品訊息

## 敘述狀態與查核界線

- **現行事實**：本頁正文依目前列出的頁面用途、操作流程與來源整理。
- **runtime 未確認**：未在目前環境實際驗證的角色按鈕、API 回應、資料同步、保存期限與版本差異，不視為目前保證；以當期 UI、API 與授權設定為準。

本頁對應 `/SaleMessage`，用途限定為依「多重碼」查詢商品訊息歷程的唯讀頁面。[商品訊息需求](../requirements/pages/19-商品訊息.md) 目前為 0 筆需求單；本文件不延伸成商品訊息維護、發送、匯出或通知設定功能。

## 入口與權限

- 網站路由：`/SaleMessage`；可由 [website-menus.json](../../../data/sources/csp/website-menus.json) 的 `id: 137` 核對，選單分類為「訂單客服管理」。
- 頁面只供登入後查詢；實際能否開啟頁面以帳號角色及當前授權為準。
- 本頁是歷程查詢，不提供文件已確認的新增、修改、刪除、狀態切換、匯出或通知操作；不要把結果表格當成可編輯表單。

## 維運查核補充

以下查詢、欄位補值與例外資訊只供維運查核；一般讀者先依入口與頁面條件操作。尚未 runtime 驗證的 API、資料庫、排序與保存期間，不得自行擴寫。

| 操作 | API | 行為 |
|---|---|---|
| 輸入多重碼查詢 | `GET /api/SaleMessage/QuerySaleMessage?multiSaleNo={multiSaleNo}` | 以 `multiSaleNo` 呼叫 Oracle `SPX_OB_GETSALEMESSAGE`，取得該多重碼的商品訊息清單。 |
| 由 route query 自動帶入 | 同上 | 頁面可由 route query 帶入多重碼後自動查詢。 |
| 查詢結果搜尋／翻頁 | 無後端 API | 回應先放在前端，再由 DataTable 做關鍵字過濾與頁次切換；翻頁不會再次呼叫查詢 API。 |

前端會對多重碼輸入做格式檢查，但允許的長度／正規式沒有在目前可用的操作來源中固定記載。後端 action 的唯一查詢條件是 `multiSaleNo`；不要自行加入銷售編號、日期、分類或狀態等後端篩選條件。

### 回傳欄位與顯示名稱補齊

Oracle 商品訊息資料的來源快照記錄 `multisaleno`、`saleno`、`msgcategorytype`、`messagedesc`、`initdate`、`terminateddate`、`status`、`createdby` 等原始欄位。Controller 查詢後還會補齊顯示用名稱：

| 顯示欄位 | 補齊方式 | 查無對照資料時 |
|---|---|---|
| 分類 `MsgCategoryTypeName` | 以 `MsgCategoryType` 查 `DomainId.MsgCategoryType` 的 Domain 資料，再取分類名稱。 | 回空字串。 |
| 建立者 `CreatedName` | 以 `CreatedBy`（員編字串）對應啟用中的使用者清單。 | 顯示 `未知`。 |
| 狀態 `StatusName` | `1001` 對應「有效」、`1002` 對應「無效」。 | 其他狀態碼回空字串；未知狀態的業務意義未由此 Controller 定義。 |

因此畫面上的分類／建立者／狀態名稱不一定是 Oracle 原始欄位直接提供，而是後端組裝後回傳。分類、建立者對照資料查不到時，這是顯示欄位降級，不等於商品訊息歷程不存在。歷史欄位描述可在 [issues_all.json](../../../data/sources/csp/redmine/issues_all.json) 查閱；它不能把本頁擴充成其他寫入功能。

### 查無資料與例外邊界

- 指定多重碼查無訊息時，回傳空集合；頁面應顯示無資料，不應當成查詢成功建立了一筆訊息。
- `CreatedBy` 找不到啟用使用者時，建立者名稱是 `未知`；分類 Domain 對不到時是空字串；狀態不是 `1001`／`1002` 時狀態名稱是空字串。
- Repository、Oracle helper 或其他查詢錯誤會往上拋；目前 log-map 沒有明確的業務錯誤碼或 NormalLogger 特徵。排查時保留多重碼、查詢時間、帳號與原始回應。
- 查詢結果的後端排序規則、歷程保留期間與日期格式化細節未在 Controller／L2 文件中固定說明，不要自行承諾排序或保存年限。
