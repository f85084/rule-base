# 名單歷程查詢

本篇是 CSP／MI `/OutBoundCustomer` 名單歷程查詢入口，供需要回查客戶名單指派與追蹤狀態的維運、管理職與授權使用者使用。此頁是查詢功能，不負責新增、轉派、核准或修改名單狀態。

## 1. 查詢前確認

- 先確認客戶編號（客代）與要查詢的指派日期區間。
- 管理職若要集中查看客戶經營名單，可勾選【客戶經營】條件；此條件會以 `tagValue` 傳入查詢。
- 查詢結果受目前帳號權限、資料範圍與查詢條件影響；查不到資料不代表名單一定不存在。
- 若要處理轉派申請或審核，請改從[名單轉派查詢](45-名單轉派查詢.md)、[名單轉派申請](43-名單轉派申請.md)或對應審核入口開始。

## 2. 執行查詢

1. 開啟 `/OutBoundCustomer`。
2. 輸入有效客戶編號；必要時填寫指派日期起訖。
3. 需要篩選客戶經營名單時，勾選【客戶經營】。
4. 點選查詢，等待結果列表與總筆數回傳。
5. 由表格閱讀名單歷程、目前追蹤狀態與相關時間。
6. 使用分頁切換後續結果；切換頁碼會依原查詢條件重新查詢。

客戶編號會先轉成整數；無法解析或為 0 時，系統會回報「客戶編號不正確」。查詢成功後，系統會將 `ObCallingStatus` 狀態碼轉為可讀的中文狀態名稱。

## 3. 結果判讀

- 查詢結果是名單歷程與追蹤狀態的唯讀資料，不會在本頁更新名單、審核或轉派狀態。
- 先確認客代、日期區間、客戶經營條件與頁碼，再判讀結果是否完整。
- 若同一客代有多筆歷程，依時間與狀態變化回看，不要只用目前一筆資料推論完整處理過程。
- 需要進一步處理時，保留客代、查詢條件、結果頁碼、畫面時間與相關狀態，交由對應的名單作業入口處理。

## 4. 分頁與篩選注意事項

- 日期區間、`客戶經營`條件、頁碼與每頁筆數會一起送至查詢 API；切換頁碼前不要任意清除條件。
- 若結果為空，先確認客代格式與日期區間，再確認是否誤勾或漏勾客戶經營條件。
- 查詢只讀取名單歷程，不會因為重複按查詢而建立或修改名單資料。

## 5. 異常處理

| 情況 | 先檢查 | 處理方式 |
|---|---|---|
| 顯示客戶編號不正確 | 是否輸入非數字、空值或 0 | 修正為有效客代後重新查詢 |
| 查詢結果為空 | 客代、日期區間、客戶經營條件、帳號範圍 | 以最小條件重新查詢，再記錄差異 |
| 狀態只有代碼或顯示異常 | `ObCallingStatus` 狀態字典與時間 | 保留客代、狀態值與查詢時間，交維運確認 |
| 分頁結果不一致 | 查詢條件是否被清除、頁碼與資料總數 | 回到第一頁重新執行同一條件，再比對總筆數 |
| 需要修改名單 | 目前所在頁面是否為查詢入口 | 不在本頁直接處理，改走申請／審核／管理流程 |
