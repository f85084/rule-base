# 會員明細

## 1. 用途、入口與路由差異

會員明細用來查看與維護會員基本資料、聯絡方式、地址、家人關係及客戶備註。需求頁標示網站路由 `/Customer`；目前前端 `routes.ts` 的實際字串為小寫 `/customer`。這是來源大小寫差異，應以當期選單與 runtime 導向結果為準（**runtime 未確認**）。

## 2. 角色與權限

- 一般專員主要查看會員資料；客戶備註可新增，但不可編輯／刪除。
- 管理職可依權限修改會員基本資料、家人資訊、客戶備註及協助註冊新會員。
- 新增會員僅開放管理權限，目的是避免重複客代；不要以一般查詢結果直接建立新會員。
- 個別欄位的顯示或編輯按鈕可能再受功能權限控制，若畫面與上述文件不同，先保留帳號與欄位狀態供維運確認。

## 3. 正常操作流程

1. 先在[客戶查詢](05-客戶查詢.md)選取並核對目前客代，再從客戶資料或功能選單進入會員明細。
2. 查看姓名、客代、生日、手機／電話、E-mail、個人化資訊、地址、家人與備註。
3. 需要異動時，先確認目前客代與登入權限，再只修改本次作業需要的欄位。
4. 依欄位驗證提示送出；儲存後重新載入會員明細，核對實際結果與其他頁面是否同步。
5. 新增家人、地址或備註後，記錄客代、關聯客代與異動時間；不要用畫面暫存值作為已寫入證據。

## 4. 欄位與資料判讀

| 區塊 | 操作與限制 |
|---|---|
| 會員基本資料 | 基本資料由管理職修改，一般專員查看；生日是否必填依當期驗證。 |
| 手機／電話 | 住家區碼 2～4 碼、電話 5～8 碼、手機 10 碼；目前亦有手機一／二更換功能，實際欄位以 UI 為準。 |
| E-mail／空值 | 空值代表目前沒有資料；依手冊可確認客戶無資料後填「無」，避免重複詢問，但仍須遵守現行欄位驗證。 |
| 聯絡地址 | 寄送型錄、中獎通知、扣繳憑單與退款支票。 |
| 發票地址 | 發票或代收轉付收據寄送地。 |
| 配送地址 | 接單時商品配送地；地址最多 60 字，格式依表單提示。 |
| 家人資訊 | 新增／修改／刪除需管理權限；建立關聯後另一方客代會同步顯示。 |
| 客戶備註 | 專員新增、管理職維護；只記錄工作需要的聯繫資訊，不記錄病史、政治或個人負面觀感。 |

## 5. 資料來源、合併與寫入副作用

- 會員明細以目前客代為主鍵；基本資料、地址、家人與備註是不同區塊，載入或儲存不必然是同一個原子請求。
- 客戶查詢清單、會員明細與儀表板可能來自不同查詢入口；選取客戶後要重新核對客代，不要以同名或同電話合併。
- 修改會員基本資料、地址、家人或備註會產生對應的資料異動；家人關聯可能使另一客代的顯示資料同步改變。
- 手機載具、語音 E 幣抵用等個人化設定可能被接單流程讀取；異動後要回查會員明細與後續頁面，不以儲存 toast 推論所有下游已同步。

## 6. 空資料、部分失敗與錯誤排查

| 現象 | 先檢查 | 判讀與處理 |
|---|---|---|
| 開頁沒有會員資料 | route 導向、目前客代、客戶查詢是否成功 | 先回客戶查詢重新選客；不要以空白畫面建立新會員。 |
| 欄位不可編輯 | 登入角色、功能權限、目前客代 | 一般專員與管理職規則不同；無權限時交管理職，不要繞過 UI。 |
| 儲存驗證失敗 | 電話長度、地址 60 字、生日與必填欄位 | 依欄位錯誤修正後重送；保留原值以免覆蓋。 |
| 會員／家人／備註只有一區更新 | 重新載入各區塊、異動時間與客代 | 分開確認單一請求結果；不要把部分成功當成全部成功。 |
| 家人關聯未在另一客代出現 | 關聯客代、同步時間、目前查詢客戶 | 先重查兩邊客代；若仍沒有，回報關聯識別值與時間。 |
| 空值與「無」混淆 | 欄位目前值與客戶確認結果 | 只有在確認無資料且當期流程允許時填「無」，不要任意代填。 |
